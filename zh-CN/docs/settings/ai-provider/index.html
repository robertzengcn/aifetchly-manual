AI 提供商

AI 提供商页面允许您选择 AI 聊天从何处获取模型。您有两个选项：

  • 托管 aiFetchly — 由 aiFetchly 为您运行模型。这是默认选项，包含在 aiFetchly AI 订阅中。
  • 自定义/本地提供商 — 您可以将 aiFetchly 指向任何 OpenAI 兼容的端点，包括 Ollama 或 LM Studio 等本地服务器，或 OpenAI 和 OpenRouter 等第三方 API。
为什么这很重要

自定义提供商允许您使用自己的模型进行 AI 聊天——即使没有 aiFetchly AI 订阅。 其他托管的 aiFetchly AI 功能（关键词生成、邮件模板生成、AI 恢复、重排、嵌入）仍需要订阅；只有聊天界面可以通过您自己的提供商运行。

自定义提供商遵循标准的 OpenAI 聊天补全协议（/v1/chat/completions，并在支持时使用 /v1/models）。aiFetchly 不打包特定于提供商的 SDK——它直接从应用程序的后端与您的端点通信，因此您的 API 密钥永远不会离开您的机器。

语音设置也在此页面

此页面还包含 AI 聊天的语音设置——设备端语音转文字（按键说话）和语音播报（文字转语音）。语音在您的本机本地运行，与 AI 提供商相互独立。请参见下文的语音设置。

打开 AI 提供商页面​

  1. 点击左侧导航菜单中的 System Setting（系统设置）。
  2. 在 System Settings 页面点击 AI Provider 按钮。

您也可以从 AI 聊天中打开它——点击模型选择器旁边的提供商标签（例如 Hosted 或 Local: Ollama）。

提供商模式​

在页面顶部，使用单选按钮组选择一种模式：

模式适用场景所需条件
托管 aiFetchly您拥有 aiFetchly AI 订阅并希望走最简单的路径。有效的 aiFetchly AI 订阅。
自定义/本地提供商您运行自己的模型，希望获得更多控制权、隐私或更低成本，或者没有订阅。可访问的 OpenAI 兼容端点和已保存的提供商配置。

在托管模式下，页面会显示您的账户是否已启用托管 AI，或者提示需要订阅。

在自定义/本地提供商模式下，会出现提供商配置字段（见下文）。在此模式下保存会将 AI 聊天切换到您的提供商；在托管模式下保存则会切换回来。

仅 AI 聊天遵循此设置

切换到自定义提供商仅解锁AI 聊天。无论此设置如何，仅限托管的 AI 功能仍需要订阅。

提供商预设​

为节省输入，请选择一个提供商预设。选择预设会自动填写建议的名称和 Base URL——您之后仍可编辑每个字段。

预设默认 Base URLAPI 密钥
Ollamahttp://localhost:11434/v1通常不需要
LM Studiohttp://localhost:1234/v1通常不需要
OpenAIhttps://api.openai.com/v1必填
OpenRouterhttps://openrouter.ai/api/v1必填
vLLMhttp://localhost:8000/v1通常不需要
LocalAIhttp://localhost:8080/v1通常不需要
Custom（空）您自行决定

对于任何其他 OpenAI 兼容服务器（例如公司网关、兼容 Groq 的端点或另一个本地推理服务器），请选择 Custom。

配置字段​

当选择自定义/本地提供商时，会出现以下字段：

字段描述
提供商预设快速启动模板（见上文）。会填写默认值，但不会锁定字段。
提供商名称此提供商的标签。必填。
Base URL提供商的 API 根地址，例如 http://localhost:11434/v1。必填。参见 Base URL 规范化。
API 密钥（可选）作为 Bearer 令牌发送。已掩码。对于不需要密钥的本地提供商，请留空。
默认模型AI 聊天使用的模型。这是一个组合框——从刷新后的列表中选择，或手动输入名称。必填。
上下文大小（可选）覆盖模型的上下文窗口，单位为 token。
刷新模型从提供商的 /models 端点拉取模型列表。
测试连接验证端点并检测能力。参见 测试连接。
保存持久化配置。

Base URL 规范化​

您可以输入带有或不带 /v1 后缀、带有或不带尾部斜杠的 Base URL——aiFetchly 会在保存时将其规范化，使其以 /v1 结尾且不带尾部斜杠。

您输入的内容存储为
http://localhost:11434http://localhost:11434/v1
http://localhost:11434/http://localhost:11434/v1
http://localhost:11434/v1/http://localhost:11434/v1
https://api.openai.com/v1https://api.openai.com/v1

API 密钥处理​

  • API 密钥字段已掩码。点击眼睛图标可显示您正在输入的内容。
  • 密钥一旦保存，就永远不会再以明文形式显示。该字段会显示 "API 密钥已配置——留空则保持不变"，并出现一个绿色的 API 密钥已配置 标签。
  • 要保留现有密钥，请在保存时将该字段留空。
  • 要替换密钥，请输入新密钥并保存。
  • 要删除密钥，请点击 清除 API 密钥。
明文 HTTP

对于 localhost 和本地网络提供商，允许使用 http://。如果您使用 非本地的明文 http:// URL，aiFetchly 会警告该连接未加密——对于任何远程提供商，请优先使用 https://。

刷新模型​

点击 刷新模型 以查询提供商的 /models 端点并填充默认模型下拉列表。此操作是可选的——您始终可以手动输入模型名称。

  • 如果 /models 成功，返回的模型会被规范化并显示在下拉列表中。
  • 如果 /models 失败（某些本地服务器未实现该端点），您会收到警告，但只要输入了默认模型，配置仍然有效。aiFetchly 会回退到手动输入的模型。
  • 如果存在默认模型但无法加载列表，您仍然可以保存并聊天。

测试连接​

在依赖某个提供商之前，请点击 测试连接。测试会按顺序验证以下内容：

  1. Base URL 是有效的 http: 或 https: URL。
  2. 提供商可访问。
  3. /models 端点正常工作，或者已手动输入默认模型。
  4. 使用一个极小的提示词成功完成非流式聊天补全。
  5. 流式聊天补全成功（如果支持）。
  6. 尽可能检测工具调用支持。

测试会发送一个最简提示词（例如要求模型回复 pong）。任何有效的补全都算作成功——aiFetchly 不要求精确的文本匹配，因为本地模型常常会附加格式。

结果显示为状态消息和能力徽章（见下文）。连接测试永远不会记录或显示您的 API 密钥。

第三方 API 可能按 token 计费

OpenAI、OpenRouter 和其他付费端点按 token 收费，因此每次测试连接只会发送一个非常小的请求。该测试仍会发起真实的 API 调用。

能力徽章​

连接测试完成后，能力徽章会描述您的提供商和模型能做什么：

徽章含义
Models/models 端点可用。
Chat非流式聊天补全正常工作。
Streaming流式聊天补全正常工作。
Tools模型支持工具调用。
Vision模型接受图像输入。
Context检测到/已覆盖的上下文大小（以 token 为单位，在可用时显示）。

每个徽章具有以下状态之一：

状态颜色含义
支持🟢 绿色已验证可用。
不支持 / 失败🔴 红色已验证不可用，或测试失败。
未知🟡 黄色无法确定——请谨慎操作。
当 Tools 不支持或未知时

如果连接测试未确认工具支持，AI 聊天会显示警告*"此本地提供商尚未确认工具支持。此对话已禁用工具。"*，并禁用该对话的工具。依赖于工具的工作流（包括计划模式）在您切换到支持工具的模型或托管 aiFetchly 之前将无法运行。更改模型后，请重新运行 测试连接 以重新探测工具支持。

AI 聊天如何使用您的提供商​

一旦保存了有效的自定义提供商：

  • AI 聊天变为可用——即使没有 aiFetchly AI 订阅。
  • AI 聊天中的模型选择器旁边会出现一个提供商指示器（例如 Local: Ollama、Local: LM Studio 或 Hosted）。点击它会打开此设置页面。
  • 模型选择器会列出您提供商的模型（来自 /models，或者如果 /models 不可用，仅显示您配置的默认模型）。
  • 聊天请求直接从应用后端发送到您的端点——从不从浏览器/渲染器发送。

如果提供商不可访问，AI 聊天会显示明确的提供商错误，而不是静默失败。

相关内容：AI Chat V2

提供商模式在各聊天界面之间共享。有关聊天体验本身，包括计划模式和上下文使用徽章，请参见 AI Chat V2。

语音设置​

AI 提供商页面还包含一个语音面板，用于 AI 聊天中的设备端语音功能——语音转文字（语音输入）和文字转语音（语音播报）。语音使用 sherpa-onnx 引擎在您的本机本地运行，与 AI 提供商相互独立。

语音输入​

设置作用
启用语音输入在 AI 聊天输入框中显示麦克风按钮（按键说话）。默认关闭。
自动发送语音转录文本转录完成后立即发送转录文本，而不是将其放入输入框供您审阅。
STT 语言您将使用的口语语言：Auto、English、中文、Español、Français、Deutsch 或 日本語。
STT 模型语音转文字模型。仅已安装的模型可供选择。
最大录音时长单次录音的最长时长，单位为秒（1–600；默认 60）。

语音播报​

设置作用
启用语音播报朗读 AI 的文本回复。您也可以随时通过 AI 聊天头部的音量按钮切换此项。
仅在语音输入后播报开启后，AI 仅会朗读对您语音消息的回复（免提对话），而不是每条回复都朗读。
TTS 语言语音播报使用的语言：Auto、English、中文、Español、Français、Deutsch 或 日本語。
TTS 语音/模型用于语音播报的嗓音。仅已安装的嗓音可供选择。
语速播放速度，范围 0.5× 到 2.0×。

语音模型​

语音输入和语音播报各自需要一个语音模型。语音模型部分列出了可用的 STT 和 TTS 模型及其状态——下载、已安装或取消（下载过程中）——并显示实时下载进度。

模型会在您首次启用或使用某项功能时按需下载，因此第一次打开语音功能会触发一次性下载。您也可以在此处预先下载模型。

语音是本地且私密的

语音识别和合成完全在您的设备上进行。您的麦克风音频会在本地处理，不会被发送到服务器或存储。仅保留最终的转录文本——作为一条普通聊天消息。

语音不授予聊天权限

语音是本地且免费的，但它不授予聊天权限。要发送转录的消息并获取回复，您仍需要 aiFetchly AI 订阅（托管）或一个正常工作的自定义/本地提供商。有关语音在聊天中的使用方式，请参见 AI Chat V2 → 语音。

安全与隐私​

  • API 密钥在静态存储时加密，并与配置的其余部分分开存储。
  • 密钥保存后永远不会以明文形式返回到 UI——页面仅显示 apiKeyConfigured: true/false。
  • 密钥永远不会被记录。 调试和请求日志会脱敏处理 Authorization 头以及任何看起来像密钥的内容。
  • 请求由应用后端发起，而不是渲染器，因此凭据不会暴露给网页内容。
  • Base URL 仅被验证为 http: 或 https:。

快速开始：Ollama​

  1. 安装 Ollama 并拉取一个模型，例如 ollama pull llama3.1。
  2. 打开 设置 → AI 提供商。
  3. 选择 自定义/本地提供商。
  4. 将提供商预设设置为 Ollama（会自动填写 http://localhost:11434/v1）。
  5. 点击 刷新模型 并选择一个模型，或手动输入一个（例如 llama3.1）。
  6. 点击 测试连接 进行确认，然后点击 保存。
  7. 打开 AI 聊天——指示器显示为 Local: Ollama，您无需订阅即可聊天。

快速开始：OpenAI / OpenRouter​

  1. 打开 设置 → AI 提供商。
  2. 选择 自定义/本地提供商。
  3. 将提供商预设设置为 OpenAI 或 OpenRouter。
  4. 将您的 API 密钥 粘贴到 API 密钥字段中。
  5. 输入默认模型（例如 gpt-4o-mini，或一个 OpenRouter 模型 ID）。
  6. 点击 测试连接，然后点击 保存。

故障排除​

无法连接到提供商​

可能的原因：

  • 本地服务器未运行（检查 Ollama / LM Studio / vLLM 进程）。
  • Base URL 或端口错误。
  • 防火墙阻止了 localhost/局域网访问。

解决方案：

  1. 启动提供商并确认它在浏览器中能响应（例如 http://localhost:11434/v1/models）。
  2. 重新检查 Base URL 并运行 测试连接。
  3. 对于 Docker 或 WSL 环境，请确保该提供商可从 aiFetchly 的网络环境中访问。

认证失败（401 / 403）​

可能的原因：

  • API 密钥缺失、错误或已过期。
  • 该密钥无权访问所选模型。

解决方案：

  1. 重新输入 API 密钥并保存。
  2. 对于 OpenAI/OpenRouter，请确认密钥有效，并且对该模型有额度/权限。

所选模型不可用​

提供商返回了"model not found"（未找到模型）。请从 刷新模型 列表中选择其他模型，或者将默认模型更新为该提供商实际提供的模型。

无法加载模型列表​

某些本地服务器未实现 /models。这是预期情况——请在默认模型中手动输入模型名称并保存。聊天仍将正常工作。

聊天可用但工具/流式传输显示为不支持​

并非所有本地模型都支持工具调用或流式传输。如果您需要这些功能，请切换到支持工具或流式的模型，或使用 托管 aiFetchly。参见 能力徽章。

仅限托管的功能仍要求订阅​

这是设计使然。自定义提供商仅解锁 AI 聊天——关键词生成、邮件模板生成、AI 恢复、重排和嵌入仍需要 aiFetchly AI 订阅。
