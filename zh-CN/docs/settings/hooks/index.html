钩子

钩子（Hooks） 是在 AI 营销助手的操作前后运行您自定义逻辑的生命周期触发器。它们在明确的时机触发——最重要的是工具运行前后——可以观察、拦截、重写或注释操作。借助钩子，您可以执行策略（"绝不运行此类命令"）、添加 AI 可见的上下文（"抓取后提醒我合规事项"），并保留每个钩子决策的防篡改审计日志。

aiFetchly 内置了安全钩子，开箱即用即为您提供保护；同时允许您添加自己的命令钩子——即接收 JSON 事件并决定下一步操作的小型脚本。

钩子的作用位置

钩子位于 AI 与它所调用的工具（内置 AI 技能、MCP 工具 以及传统工具）之间。它们不会取代 AI，而是对 AI 请求的工具调用进行门控和塑形。一个允许调用的钩子永远不会绕过正常的权限系统；一个拦截调用的钩子则会在其运行之前就将其阻止。

钩子能做什么？​

每个钩子都会接收事件的详细信息，并可以返回一个决策：

  • 拦截（Block） 某项操作（例如拒绝危险命令）。
  • 重写（Rewrite） 工具即将被调用时所使用的输入（例如对某个值进行脱敏）。
  • 添加上下文 供 AI 在工具运行后读取（例如合规提醒）。
  • 记录活动 以便日后在审计日志中查看。

关键概念​

事件​

每个钩子都绑定到一个事件（event）——即 AI 生命周期中触发的时刻。最重要的事件是工具生命周期相关的事件：

事件触发时机能否拦截？
PreToolUse工具即将运行之前✅ 可以——工具不会执行
PostToolUse工具成功运行之后❌ 不可以（工具已运行），但可以添加上下文或重写其输出
PostToolUseFailure工具运行失败之后❌ 不可以（无法将失败变为成功），但可以添加消息

钩子模型中的其他事件——SessionStart、UserPromptSubmit、PermissionRequest、PermissionDenied 和 Stop——可在事件下拉菜单中选择，分别描述会话、提示、权限和回合结束等时刻。事件名称在所有语言中均保留为代码标识符（如 PreToolUse），以保持可搜索性和无歧义。

工具事件是实际的执行点

当前已完全接入执行点的是工具生命周期事件（PreToolUse、PostToolUse、PostToolUseFailure）。拦截、输入重写、输出重写以及上下文注入都在这里生效。会话、提示、权限和停止事件是钩子模型的一部分，可在界面中选择；但每个事件是否会触发，取决于应用程序中对应部分在哪里触发了它。

来源​

每个钩子都有一个来源（source），决定了它由谁拥有以及您可以对其做什么：

来源含义默认是否显示？
builtin随 aiFetchly 自带（安全与合规）✅ 是
user由您在此页面创建✅ 是
session为当前会话临时注册仅当 显示会话钩子 开启时

使用 来源 筛选器可将列表缩小到其中之一。

命令钩子​

您可以从界面创建的唯一钩子类型是命令钩子（command hook）。命令钩子运行一个本地命令（脚本或可执行文件），并通过 JSON 与 aiFetchly 通信：

  1. aiFetchly 将事件详情作为 JSON 对象通过标准输入 发送给您的命令。
  2. 您的命令完成其工作，并将 JSON 决策写入标准输出。
  3. aiFetchly 读取该决策并据此采取行动（拦截、重写输入、添加上下文等）。

内置钩子是用代码编写的（回调钩子），无法从界面编辑——您只能开启或关闭它们。

匹配器​

钩子的匹配器（Matcher）用于缩小其适用的工具调用范围。匹配器对工具名称进行测试，并支持简单的通配符模式：

匹配器匹配对象
*所有工具
shell_execute仅名称恰好为 shell_execute 的工具
scrape_*任何名称以 scrape_ 开头的工具（例如 scrape_search）
*_search任何名称以 _search 结尾的工具
*scrape*任何名称中包含 scrape 的工具

匹配器最多支持 128 个字符。

"If" 条件​

可选的 If 条件通过匹配工具的参数值（而非仅名称）来进一步收窄钩子范围。它使用与匹配器相同的通配符语法，对传递给工具的字符串参数进行测试。例如：

  • 在匹配器为 shell_execute 的 PreToolUse 上，If 条件 git * 使钩子仅对以 git 开头的命令触发。
  • If 条件 rm -rf * 仅对递归删除命令触发。

对于没有工具参数的事件，If 条件会被忽略。它最多支持 256 个字符。

失败模式​

钩子可能会失败——命令可能崩溃、超时或返回无效 JSON。失败模式（Failure mode） 决定当钩子本身出错时工具调用的命运（这与钩子有意返回"拦截"的情况不同）：

失败模式当钩子出错时……
warn错误会记录在审计日志中，工具调用正常进行。
block错误被视为拦截——工具调用不会运行。

对非关键钩子（日志、建议性上下文）使用 warn。仅当您宁可阻止工具运行、也不愿在没有钩子检查成功的情况下运行它时，才使用 block。

一句话理解 block 与 warn

钩子返回 { continue: false } 时总是会拦截工具，与失败模式无关。失败模式仅在钩子自身崩溃（超时、崩溃、错误 JSON）时才起作用。

全局启用​

页面顶部的 全局启用钩子 开关是总开关。当它关闭时，任何位置都不会触发钩子——无论是内置的还是用户创建的。页面其余部分保持可交互，因此您仍可在系统暂停时配置钩子。此设置在重启后仍然保留。

打开钩子页面​

  1. 点击左侧导航菜单中的 设置。
  2. 打开 钩子 页面（与技能和 MCP 并列）。

aiFetchly 自带以下内置钩子：

builtin-block-dangerous-shell-deletePreToolUseshell_execute启用拦截匹配危险递归删除模式的命令（例如 rm -rf / 或 rm -rf *）。

启用 builtin-scraping-compliance-context 会在每次抓取工具调用后向 AI 提示注入合规指引。这是有意为之，但请注意，它可能会影响 AI 后续回复的措辞。

内置钩子是只读的——它们的字段无法编辑，也无法删除。您只能开启或关闭它们；该覆盖设置在重启后仍然保留。

创建命令钩子​

第 1 步：新建钩子​

点击 + 添加命令钩子。编辑面板会切换为一个带有合理默认值的空白表单：

  • 事件：PreToolUse
  • 匹配器：*
  • 失败模式：warn
  • 超时：5000 毫秒
  • 启用：关闭（新钩子默认禁用）

第 2 步：填写字段​

字段描述
钩子 ID钩子的唯一名称（例如 block-home-delete）。用于列表和审计日志。
事件钩子的触发时机（参见 事件）。
匹配器钩子适用的工具名称；* 表示全部（参见 匹配器）。
If 条件可选——按工具参数值进一步限制（参见 "If" 条件）。
命令要运行的本地命令。它通过标准输入接收 JSON 格式的事件，并必须在标准输出打印 JSON 决策（参见 命令钩子契约）。
超时（毫秒）钩子被终止前的最大运行时间。默认 5000；上限 60000。
失败模式当钩子本身出错时的处理方式（参见 失败模式）。
状态消息可选——钩子运行时显示为进度指示器的简短标签。

第 3 步：保存并启用​

  1. 点击 保存。钩子会以 启用 关闭 的状态保存，此时还不会运行任何内容。
  2. 在列表中选中该钩子，并打开 启用 开关以激活它。
钩子仅在两个开关都允许时才会运行

命令钩子只有在全局启用钩子 并且 钩子本身已启用 时才会触发。新钩子默认处于禁用状态，是有意为之，以便您在任何运行之前先审查命令。

编辑、启用和删除钩子​

  • 启用 / 禁用 —— 选择任意钩子并切换 启用 开关。对内置钩子和用户钩子均有效；更改立即生效并持久化。
  • 编辑字段 —— 仅 user 钩子可编辑。选中钩子，修改字段，然后点击 保存。内置钩子和会话钩子的字段以只读形式显示。
  • 删除 —— 仅 user 钩子可删除。点击 删除，在对话框中确认钩子 ID 和命令预览，钩子将被永久移除。内置钩子无法删除（按钮隐藏；作为防护，后端也会拒绝删除）。

命令钩子契约​

当命令钩子触发时，aiFetchly 会以 shell: false 运行您的 命令——第一个标记是可执行文件，其余标记是它的参数。它通过 stdin 以 JSON 对象的形式发送事件，并从 stdout 读取 JSON 决策。

输入（stdin）​

对于 PreToolUse 钩子，输入大致如下：

{
  "eventName": "PreToolUse",
  "hookRunId": "run-1a2b3c",
  "tool": { "id": "...", "name": "shell_execute", "source": "legacy-tool" },
  "input": { "command": "rm -rf /tmp/old" },
  "permissionState": { "allowed": true, "needsPrompt": false },
  "timestamp": "2026-07-10T09:42:00.000Z"
}

具体字段取决于事件（例如，PostToolUse 还包含 output 和 executionTimeMs）。您的脚本应以防御性方式读取——使用可选链访问字段，并容忍缺失的键。

输出（stdout）​

您的命令打印一个描述其决策的 JSON 对象。所有字段均为可选：

字段效果
continuefalse 拦截工具调用（与 reason 配合使用）。省略或 true 表示允许。
reason人类可读的解释，显示在审计日志中，拦截时也会显示给 AI。最多 1000 字符。
additionalContext追加到 AI 上下文中的文本（通常用于 PostToolUse）。最多 4000 字符。
systemMessage系统级消息。最多 2000 字符。
updatedInput替换工具的输入（仅 PreToolUse）。最大 64 KB。
updatedToolOutput重写工具的输出（仅 PostToolUse）；无法将失败变为成功。最大 128 KB。
suppressOutput在对话中隐藏工具的输出。
permissionDecisionallow、ask 或 deny。allow 仅为建议性，永远不会覆盖权限系统。

最小的"允许"响应是一个空对象：{}。非有效 JSON 的输出会被视为钩子错误（按失败模式处理），因此请始终输出格式良好的 JSON。

执行规则​

  • 不支持 shell 特性。 由于 shell: false，管道（|）、重定向（>）、命令链（&&）和变量展开（$VAR）不会直接生效。若要使用它们，请显式调用一个 shell，例如 sh -c "..." 或 bash -c "..."。
  • 受限环境。 您的命令默认只接收一小部分允许的环境变量：PATH、HOME、USER、USERNAME、TEMP、TMP。aiFetchly 从不将其自身的凭据或令牌传递给您的钩子。
  • 引号。 命令解析器支持单引号和双引号，用于包含空格的参数（例如 -e "console.log(1)"），但不支持转义序列或变量展开。
  • 大小上限。 stdout 上限为 256 KB，stderr 为 64 KB。请保持响应精简。

示例​

示例 1 —— 拦截删除主目录的操作​

一个 PreToolUse 钩子，拒绝删除主目录下文件的命令。

钩子设置

字段值
事件PreToolUse
匹配器shell_execute
失败模式block
命令node /home/me/hooks/block-home-delete.js

block-home-delete.js

let raw = "";
process.stdin.on("data", (chunk) => (raw += chunk));
process.stdin.on("end", () => {
  let input = {};
  try { input = JSON.parse(raw); } catch { /* ignore malformed input */ }
  const command = String(input?.input?.command ?? "");
  if (/\brm\s+-rf\s+~(\/|$|\s)/.test(command)) {
    process.stdout.write(JSON.stringify({
      continue: false,
      reason: "Refusing to delete files inside the home directory.",
    }));
    return;
  }
  process.stdout.write(JSON.stringify({ continue: true }));
});

安全性​

钩子系统的设计使得行为异常或恶意的命令钩子无法危害应用程序：

  • 默认禁用。 新命令钩子在保存时启用状态为关闭；只有内置命令钩子是随产品启用的，且仅安全钩子默认开启。
  • 受限环境。 钩子仅接收允许的环境变量列表——永远不会收到 aiFetchly 的凭据、API 密钥或会话令牌。
  • 无 shell 注入。 命令以 shell: false 和一个最小化的 argv 解析器运行，因此 shell 操作符不会被解析，除非您显式调用一个 shell。
  • 有界执行。 每个钩子都有超时（默认 5 秒，上限 60 秒）；超时会被终止并记录为 timeout。
  • 有界输出。 stdout 和 stderr 都有上限；过大的输出会被截断。
  • 审计中脱敏。 看起来像 API 密钥、bearer 令牌、cookie 或 Authorization 头的模式，在写入审计日志之前会被脱敏。
  • 内置钩子防篡改。 它们的定义无法从界面编辑或删除——只能切换。
  • 钩子永不绕过权限。 钩子返回 allow 仅为建议性；标准权限系统仍然适用。只有钩子返回 block 才会短路（直接阻止）工具调用。
您对自己创建的命令钩子负责

命令钩子会以上述描述的环境在您的机器上运行一个程序。仅将钩子指向您信任的脚本，并放在您控制的目录下；启用前请审查命令内容。

故障排除​

我的命令钩子不触发​

可能的原因：

  • 钩子被全局禁用（顶部有黄色横幅）。
  • 钩子本身被禁用（启用开关关闭）。
  • 匹配器 不匹配工具名称，或 If 条件 不匹配参数值。
  • 事件 不是已激活的工具生命周期事件之一（PreToolUse / PostToolUse / PostToolUseFailure）。

解决方案：

  1. 打开 全局启用钩子。
  2. 选中该钩子并启用它。
  3. 暂时将匹配器设为 * 并清空 If 条件，以确认钩子能工作，然后再缩小范围。
  4. 检查审计日志——状态为 started 的行表示钩子被选中；没有行则表示它从未匹配。

钩子运行了，但工具仍然执行了​

可能的原因：

  • 钩子返回了 { continue: true }（或空对象），允许了调用。
  • 钩子出错（状态 failed 或 timeout）且失败模式为 warn，因此调用照常进行。

解决方案：

  1. 确保您的脚本在应当拦截时写入 { continue: false, reason: "..." }。
  2. 如果钩子持续出错，将失败模式设为 block（如果希望错误也阻止工具），或修复脚本使其不再失败。

钩子显示状态 failed 或 timeout​

可能的原因：

  • 脚本崩溃或输出了无效（非 JSON）的内容。
  • 脚本运行时间超过了配置的超时。
  • 命令使用了 shell 特性（管道、重定向）却没有调用 shell。

解决方案：

  1. 在终端中测试脚本：echo '{"eventName":"PreToolUse","input":{"command":"test"}}' | node my-hook.js。它必须输出有效 JSON。
  2. 增加超时（最高至 60000 毫秒），或让脚本更快。
  3. 将 shell 特性包裹在 sh -c "..." 或 bash -c "..." 中。

钩子 ID 无法更改​

钩子 ID 一旦创建即固定（编辑时该字段被禁用）。要重命名钩子，请新建一个使用所需 ID 的钩子，然后删除旧的。

我无法编辑或删除内置钩子​

这是有意为之。内置钩子由代码所有；您只能开启或关闭它们。
