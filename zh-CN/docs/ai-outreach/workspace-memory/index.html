工作区记忆

工作区记忆让 AI Chat 为已批准的工作区记住项目专属上下文。它与全局用户记忆和会话记忆分离，因此一个项目的细节不会被复用到另一个项目。

适合保存当你在同一个项目文件夹、营销活动工作区或代码仓库中工作时应持续适用的信息。

记住什么​

类型用途
项目文件中不明显的产品、活动、里程碑或项目背景。
决策用户已确认的产品或技术决策。
流程此工作区的命令、审查步骤或操作流程。
约定代码、写作、命名或 UX 约定。
引用指向本地文件、文档、规格或外部资源的引用。
警告已知陷阱、受限操作、不稳定测试、合规规则或安全约束。

不要保存密钥、API key、cookie、私有抓取线索数据、完整对话、大型工具输出、原始文件内容或临时任务进度。

工作区范围​

只有当前 AI Chat 会话有已批准的工作区时，工作区记忆才可用。

aiFetchly 会把工作区解析为稳定身份。如果所选文件夹位于 Git 仓库内，记忆会绑定到仓库根目录。如果没有 Git 根目录，则绑定到所选真实路径。

这意味着：

  • 使用同一已批准工作区的会话可以共享工作区记忆。
  • 一个工作区的记忆不会注入到另一个工作区。
  • 没有已批准工作区时，无法打开或使用工作区记忆。

打开工作区记忆​

  1. 打开 AI Chat。
  2. 在输入框上方的工作区区域选择或批准一个工作区。
  3. 点击工作区徽章上的 记忆。

工作区记忆对话框会显示当前工作区的活动记忆。徽章也会显示活动记忆数量。

创建记忆​

  1. 打开工作区记忆对话框。
  2. 点击 Create memory。
  3. 选择 Type。
  4. 输入简短 Title。
  5. 输入 Content。
  6. 设置 Confidence。
  7. 点击 Save。

手动记忆只会保存到当前已批准的工作区。

字段​

字段说明
Type分类：project、decision、workflow、convention、reference 或 warning。
Title用于浏览和搜索的短标签。
Content实际记忆内容。保持简洁且长期有效。
Confidence0 到 100 的置信度。手动记忆默认较高，但可对不确定内容调低。
Status编辑时可用：active、archived 或 contradicted。

搜索和查看​

使用搜索框按标题或内容查找工作区记忆。

每条记忆会显示类型、标题、内容、非活动状态、来源、更新时间、最后使用时间和置信度。打开 Show archived 可包含已归档和已矛盾的记忆。

编辑、归档和删除​

  • Edit 更新类型、标题、内容、置信度或状态。
  • Archive 将记忆从活动列表隐藏，但不删除。
  • Delete 确认后永久删除记忆。

已归档记忆只有在启用 Show archived 后才会显示。

工作区自动摘要​

工作区自动摘要在应用内部也称为 workspace auto-dream，可以从会话和智能体任务中整合项目专属信息。

在对话框中：

  • 状态徽章显示活动记忆数量和自动摘要状态。
  • RUN AUTO SUMMARY 会为当前工作区启动一次手动整合。
  • 如果有记录，会显示上次运行时间。

自动摘要生成的记忆仍可检查、编辑、归档或删除。

设置​

设置作用
工作区记忆注入将相关工作区记忆注入到当前已批准工作区的 AI Chat 上下文中。
工作区自动摘要在后台从会话和智能体任务中整合工作区专属记忆。
手动工作区记忆允许手动创建、编辑和删除工作区记忆。关闭它不会删除已保存的记忆。

当前用户消息始终优先。如果工作区记忆与当前指令冲突，应以当前指令为准。

最佳实践​

  • 保存每次新聊天都不想重复说明的决策和约定。
  • 保存 package scripts 或文档中不明显的项目命令。
  • 保存合规、安全、环境问题或已知测试陷阱。
  • 保持记忆简短，便于注入上下文。
  • 优先引用文件路径或文档，而不是复制大段文件内容。
  • 对过时记忆进行归档，不要保留互相矛盾的活动指导。
