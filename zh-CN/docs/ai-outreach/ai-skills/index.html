AI 技能

AI 技能是模块化扩展，为 AI 提供在聊天过程中可调用的工具——例如网页抓取、自动化、文件访问或 shell 命令等专业能力。当某个技能被启用后，AI 可以自行决定是否使用它来回应您的请求。

什么是技能？​

技能是一个打包的工具，具有：

  • 唯一的名称和版本号。
  • 来源：内置（随 aiFetchly 一起发布）或用户安装（由您导入，或随插件一起打包）。
  • 权限类别——由技能声明的权限派生（参见权限类别）。
  • 启用/禁用状态。

访问 AI 技能​

  1. 点击左侧导航菜单中的系统设置。
  2. 点击管理技能（或AI 技能）。

该页面以表格形式列出所有已安装的技能。

技能表格​

列名说明
名称技能标识符。如果该技能来自某个插件，其旁边会显示一个_"via plugin: {name}"_标签。
来源内置或用户安装徽章。
类别技能的权限类别（pure、network、filesystem、automation或shell）。
版本技能版本号。
状态已启用或已禁用。
操作启用/禁用切换按钮和卸载按钮——仅对用户安装的技能显示。
内置技能始终开启

内置技能既不显示启用/禁用切换按钮，也不显示卸载按钮。它们无法在此页面被禁用或移除。

导入技能​

技能以.zip包的形式导入。

  1. 点击导入（右上角，上传图标）。
  2. 选择一个技能.zip文件。
  3. aiFetchly 会校验该包（清单、权限、入口文件）并完成安装。
导入提示
  • 导入按钮仅支持.zip文件。
  • 包内必须包含有效的manifest.json（参见技能包格式）。
  • 随插件打包的技能无需导入——当其所属插件安装时会自动出现。

技能也可以通过以下途径自动出现：

  • 插件——一个插件会打包一个或多个技能；它们会以_"via plugin"_标签的形式出现在此处。可通过**插件管理器**来安装或移除它们。
  • 本地技能目录（进阶）——放置在~/.aifetchly/skills/<name>/下的技能会被自动发现。

启用、禁用和卸载​

对于用户安装的技能：

  • 启用 / 禁用——使用操作列中的对勾（启用）/叉号（禁用）切换按钮。
  • 卸载——点击垃圾桶图标并确认。卸载是永久性的；要再次使用该技能，需重新导入对应的.zip。

内置技能没有操作控件——它们始终处于启用状态。

技能在聊天中的工作方式​

一旦某个技能被启用，AI 会在相关时自行选择调用它。您无需按名称调用技能（不过也可以显式请求，例如*"用网页抓取器处理这个 URL"*）。

技能类别​

每个技能都属于一个权限类别，该类别决定了 AI 调用该技能时如何被审批。类别取自技能清单中声明的第一个permission，如未声明则为pure：

类别技能可以做什么
pure通用工具——文本处理、计算、格式化。无特殊访问权限。
network出站网络/HTTP 访问（抓取网页、调用 API）。
filesystem本地文件读写。
automation浏览器自动化、抓取、社交发布以及类似的脚本化操作。
shell运行系统 shell 命令。（仅限内置shell_execute——永不可导入。）

类别在表格中以原始小写形式显示（例如network、automation）。

审批提示​

当 AI 调用某个技能时，aiFetchly 可能会在其运行前请求您审批。是否出现提示取决于技能的类别以及您当前的聊天工具审批模式：

类别审批行为
pure始终自动批准——无提示。
shell**每条命令都会提示。**永不自动批准（见下文）。
network / filesystem / automation在默认的_"请求审批"模式下会提示。在"代我批准"或"完全访问"_模式下会自动批准。

当出现提示时，您会看到一张审批卡片，包含三个操作：

  • 允许一次——仅运行本次调用。
  • 始终允许——记住此决定，今后调用该技能时不再提示。
  • 拒绝——阻止本次调用。

对于shell技能，卡片标题为**"Shell 命令执行"，会显示命令预览（命令、工作目录、shell、超时时间），且第三个按钮显示为"始终允许（本次会话）"**，而非"始终允许"。

Shell 审批实际上是一次性的

对于shell技能，"始终允许"对后续命令不生效。每条 shell 命令都会再次提示——这是有意为之的安全措施，因为 shell 命令可以在您的机器上执行任何操作。只有非 shell 类别才会真正永久记住"始终允许"。

技能包格式​

技能.zip必须包含一个manifest.json。最小可用的清单如下所示：

{
  "name": "my-custom-skill",
  "version": "1.0.0",
  "description": "What this skill does, shown to the AI.",
  "runtime": "javascript",
  "entry": "index.js",
  "parameters": {
    "type": "object",
    "properties": {
      "url": { "type": "string" }
    },
    "required": ["url"]
  },
  "permissions": ["network"]
}

必需的清单字段​

字段说明
name唯一的技能标识符。
version版本字符串，例如1.0.0。
description简短描述——AI 会读取此内容来判断何时使用该技能。
runtimejavascript或python。
entry包内的入口文件（例如index.js或main.py）。
parameters描述技能输入参数的 JSON Schema 对象。

可选的清单字段​

字段说明
permissions权限字符串数组。**有效值仅为network、filesystem、automation。**第一项决定技能的类别（参见技能类别）。未知值在导入时会被拒绝。
权限会被严格校验

仅接受network、filesystem和automation。诸如web-search、data-access或shell之类的值将被拒绝，技能也不会被导入。没有单独的category字段——类别由permissions的第一项派生（如未提供则为pure）。

打包​

  1. 在包的根目录放置一个有效的manifest.json。
  2. 添加entry引用的运行时/入口文件。
  3. 压缩内容，而非外层文件夹。
  4. 将文件命名为skill-name.zip。

故障排除​

导入失败​

**可能的原因：**zip 无效、manifest.json缺失或格式错误、permissions值无效，或缺少必需字段（runtime、entry、parameters）。

解决方案：

  1. 验证 zip 文件的完整性。
  2. 检查manifest.json是否包含所有必需字段且值有效。
  3. 确认permissions仅使用network、filesystem或automation。
  4. 确认runtime为javascript或python，且entry指向真实存在的文件。

技能未在聊天中出现​

**可能的原因：**技能已被禁用，或（对于插件技能）其所属插件已被禁用。

解决方案：

  1. 在表格中检查该技能的状态并启用它。
  2. 对于插件技能，请查看**插件管理器**——其所属插件必须处于启用状态。

AI 不断请求审批​

  • 您正在使用shell技能。Shell 审批在设计上就是一次性的。
  • 对于其他类别，可将聊天工具审批模式切换为_"代我批准"_以减少提示（注意：这会自动批准非 shell 技能）。

内置技能没有切换按钮​

这是有意为之。内置技能始终处于启用状态，无法在此页面被禁用或卸载。
