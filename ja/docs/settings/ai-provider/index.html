AI プロバイダー

AI プロバイダーページでは、AI チャットがモデルを取得する場所を選択できます。2 つのオプションがあります。

  • ホステッド aiFetchly — aiFetchly がモデルを実行します。これがデフォルトであり、aiFetchly AI サブスクリプションに含まれています。
  • カスタム / ローカルプロバイダー — Ollama や LM Studio のようなローカルサーバー、OpenAI や OpenRouter のようなサードパーティ API など、任意の OpenAI 互換エンドポイントを aiFetchly に指定します。
これが重要な理由

カスタムプロバイダーを使用すると、aiFetchly AI サブスクリプションがなくても、独自のモデルで AI チャットを利用できます。 その他のホステッド aiFetchly AI 機能（キーワード生成、メールテンプレート生成、AI リカバリ、リランク、埋め込み）は引き続きサブスクリプションが必要です。チャット画面のみが独自のプロバイダーで実行できます。

カスタムプロバイダーは、標準的な OpenAI のチャット補完契約（/v1/chat/completions、およびサポートされている場合は /v1/models）に従います。aiFetchly はプロバイダー固有の SDK をバンドルせず、アプリのバックエンドから直接エンドポイントと通信するため、API キーがお使いのマシンから外部に送信されることはありません。

音声設定もここにあります

このページには、AI チャット用の音声設定（デバイス上の音声認識＝プッシュトーク、および読み上げ応答＝テキスト読み上げ）も含まれています。音声機能はお使いの端末でローカルに動作し、AI プロバイダーとは独立しています。以下の音声設定を参照してください。

AI プロバイダーページを開く​

  1. 左側のナビゲーションメニューで System Setting（システム設定）をクリックします。
  2. System Settings ページの AI Provider ボタンをクリックします。

AI チャットからも開けます。モデルセレクターの横にあるプロバイダーチップ（例: Hosted や Local: Ollama）をクリックしてください。

プロバイダーモード​

ページの上部で、ラジオグループからモードを選択します。

モード使用するタイミング必要なもの
ホステッド aiFetchlyaiFetchly AI サブスクリプションを持ち、最もシンプルな方法を選びたい場合。有効な aiFetchly AI サブスクリプション。
カスタム / ローカルプロバイダー独自のモデルを実行する、より高い制御、プライバシー、低コストを求める、またはサブスクリプションを持っていない場合。到達可能な OpenAI 互換エンドポイントと保存済みのプロバイダー構成。

ホステッドモードでは、ページにお使いのアカウントでホステッド AI が有効かどうか、またはサブスクリプションが必要かどうかが表示されます。

カスタム / ローカルプロバイダーモードでは、プロバイダー構成フィールドが（下記に）表示されます。このモードで保存すると AI チャットがお使いのプロバイダーに切り替わります。ホステッドモードで保存すると元に戻ります。

AI チャットのみがこの設定に従います

カスタムプロバイダーへの切り替えでロックが解除されるのは AI チャット のみです。ホステッド限定の AI 機能は、この設定に関係なく引き続きサブスクリプションが必要です。

プロバイダープリセット​

入力の手間を省くために、プロバイダープリセットを選択します。選択すると推奨される名前とベース URL が自動入力されますが、その後もすべてのフィールドを編集できます。

LM Studiohttp://localhost:1234/v1通常は不要
OpenAIhttps://api.openai.com/v1必須
OpenRouterhttps://openrouter.ai/api/v1必須
vLLMhttp://localhost:8000/v1通常は不要
LocalAIhttp://localhost:8080/v1通常は不要
Custom（空）任意

その他の OpenAI 互換サーバー（企業ゲートウェイ、Groq 互換エンドポイント、別のローカル推論サーバーなど）には Custom を選択してください。

カスタム / ローカルプロバイダーが選択されている場合、以下のフィールドが表示されます。

ベース URL の正規化​

ベース URL は、/v1 サフィックスの有無、末尾のスラッシュの有無にかかわらず入力できます。aiFetchly は保存時に /v1 で終わり、末尾のスラッシュがない形に正規化します。

入力値保存される値
http://localhost:11434http://localhost:11434/v1
http://localhost:11434/http://localhost:11434/v1
http://localhost:11434/v1/http://localhost:11434/v1
https://api.openai.com/v1https://api.openai.com/v1

API キーの取り扱い​

  • API キーフィールドはマスク表示されます。目のアイコンをクリックすると、入力内容が表示されます。
  • キーを一度保存すると、プレーンテキストで再表示されることはありません。フィールドには "API key configured — leave blank to keep" と表示され、緑色の API key configured チップが表示されます。
  • 既存のキーを保持するには、保存時にフィールドを空欄のままにします。
  • 置き換えるには、新しいキーを入力して保存します。
  • 削除するには、Clear API key をクリックします。
プレーン HTTP

http:// は localhost およびローカルネットワークプロバイダーで許可されています。ローカル でない プレーン http:// URL を使用すると、aiFetchly は接続が暗号化されていないことを警告します。リモートプロバイダーには https:// を使用してください。

モデルを更新​

モデルを更新をクリックすると、プロバイダーの /models エンドポイントにクエリを送信し、デフォルトモデルのドロップダウンに入力されます。これはオプションであり、代わりにモデル名を手動で入力することも常に可能です。

  • /models が成功すると、返されたモデルが正規化されてドロップダウンに表示されます。
  • /models が失敗した場合（一部のローカルサーバーは実装していません）、警告が表示されますが、デフォルトモデルが入力されていれば構成は有効です。aiFetchly は手動で入力されたモデルにフォールバックします。
  • デフォルトモデルは存在するがリストを読み込めない場合でも、保存してチャットできます。

接続テスト​

プロバイダーを本格的に利用する前に 接続テスト をクリックします。テストは以下の順序で検証します。

  1. ベース URL が有効な http: または https: URL であること。
  2. プロバイダーに到達できること。
  3. /models エンドポイントが機能する、または デフォルトモデルが手動で入力されていること。
  4. ごく小さなプロンプトで非ストリーミングのチャット補完が成功すること。
  5. ストリーミングチャット補完が成功すること（サポートされている場合）。
  6. 可能な場合、ツール呼び出しのサポートが検出されること。

テストは最小限のプロンプトを送信します（例：モデルに pong と返答するよう依頼）。有効な補完はすべて成功とみなされます。ローカルモデルは多くの場合フォーマットを追加するため、aiFetchly は厳密なテキスト一致を要求しません。

結果はステータスメッセージと 機能バッジ（下記）として表示されます。接続テストでお使いの API キーがログに記録されたり表示されたりすることはありません。

サードパーティ API はトークンごとに課金する場合があります

OpenAI、OpenRouter、その他の有料エンドポイントはトークンごとに課金されるため、各接続テストでは非常に小さなリクエストのみを送信します。それでもテストは実際の API 呼び出しを行います。

機能バッジ​

接続テストの後、機能バッジはプロバイダーとモデルが何をできるかを示します。

バッジ意味
Models/models エンドポイントが利用可能です。
Chat非ストリーミングチャット補完が機能します。
Streamingストリーミングチャット補完が機能します。
Toolsモデルがツール呼び出しをサポートしています。
Visionモデルが画像入力を受け付けます。
Context検出/上書きされたコンテキストサイズ（トークン単位）（利用可能な場合に表示）。

各バッジは以下のいずれかの状態になります。

状態色意味
Supported🟢 緑動作が確認済みです。
Unsupported / Failed🔴 赤動作しないことが確認された、またはテストが失敗しました。
Unknown🟡 黄判定できません。注意して進めてください。
Tools が unsupported または unknown の場合

接続テストでツール対応が確認できない場合、AI チャットは 「このローカルプロバイダーはツール対応を確認していません。この会話ではツールを無効化します。」 という警告を表示し、その会話ではツールを無効化します。ツール依存のワークフロー（プランモードを含む）は、ツール対応モデルまたはホスト型 aiFetchly に切り替えるまで実行されません。モデルを変更した後は Test Connection を再実行して、ツール対応を再確認してください。

AI チャットがプロバイダーを使用する仕組み​

有効なカスタムプロバイダーが保存されると、以下のようになります。

  • AI チャットが利用可能になります — aiFetchly AI サブスクリプションがなくても。
  • AI チャットのモデルセレクターの近くに プロバイダーインジケーター が表示されます（例：Local: Ollama、Local: LM Studio、Hosted）。クリックするとこの設定ページが開きます。
  • モデルセレクター には、プロバイダーのモデルが一覧表示されます（/models から、または /models が利用できない場合は構成済みのデフォルトモデルのみ）。
  • チャットリクエストはアプリバックエンドから直接エンドポイントに送信され、ブラウザ/レンダラーから送信されることはありません。

プロバイダーに到達できない場合、AI チャットはサイレントに失敗するのではなく、明確なプロバイダーエラーを表示します。

関連：AI Chat V2

プロバイダーモードはチャット画面全体で共有されます。プランモードやコンテキスト使用量バッジなど、チャット体験自体については AI Chat V2 を参照してください。

音声設定​

AI プロバイダーページには、AI チャットでのデバイス上の音声（音声認識＝音声入力、およびテキスト読み上げ＝読み上げ応答）のための 音声 パネルも含まれています。音声機能は sherpa-onnx エンジンを使用してお使いのマシンでローカルに動作し、AI プロバイダーとは独立しています。

音声入力​

設定機能
音声入力を有効化AI チャットのコンポーザーにマイクボタンを表示します（プッシュトーク）。デフォルトはオフです。
音声トランスクリプトを自動送信文字起こし完了後にコンポーザーに配置して確認するのではなく、トランスクリプトが完了した直後に送信します。
STT 言語話す言語：Auto、English、中文、Español、Français、Deutsch、または 日本語。
STT モデル音声認識モデル。インストール済みのモデルのみ選択できます。
最大録音時間1 回の録音の最大時間（秒単位、1–600、デフォルト 60）。

読み上げ応答​

設定機能
読み上げ応答を有効化AI のテキスト返答を読み上げます。AI チャットヘッダーの音量ボタンからもいつでも切り替えられます。
音声入力後にのみ読み上げオンの場合、AI はすべての返信ではなく、音声メッセージに対する返信のみを読み上げます（ハンズフリー会話）。
TTS 言語読み上げ返答の言語：Auto、English、中文、Español、Français、Deutsch、または 日本語。
TTS ボイス / モデル読み上げ返答に使用するボイス。インストール済みのボイスのみ選択できます。
読み上げ速度再生速度（0.5× から 2.0×）。

音声モデル​

音声入力と読み上げ応答には、それぞれ音声モデルが必要です。音声モデルセクションには、利用可能な STT および TTS モデルとそのステータス（ダウンロード、インストール済み、またはダウンロード中の キャンセル）が一覧表示され、ダウンロードの進行状況がリアルタイムで表示されます。

モデルは、機能を初めて有効化または使用したときにオンデマンドでダウンロードされるため、初めて音声をオンにすると 1 回限りのダウンロードが発生します。ここから事前にダウンロードすることもできます。

音声機能はローカルでプライベートです

音声認識と合成はすべてお使いのデバイス上で行われます。マイク音声はローカルで処理され、サーバーに送信されたり保存されたりすることは ありません。結果のトランスクリプトのみが、通常のチャットメッセージとして保持されます。

音声機能はチャットへのアクセスを付与しません

音声機能はローカルで無料ですが、チャットへのアクセスは付与されません。文字起こししたメッセージを送信して返信を得るには、aiFetchly AI サブスクリプション（ホステッド）または機能するカスタム/ローカルプロバイダーが引き続き必要です。チャットで音声がどのように使用されるかについては、AI Chat V2 → 音声を参照してください。

セキュリティとプライバシー​

  • API キーは保存時に暗号化され、構成の他の部分とは別に保存されます。
  • キーは保存後、UI にプレーンテキストで返されることはありません。ページには apiKeyConfigured: true/false のみが表示されます。
  • キーはログに記録されません。 デバッグログとリクエストログでは、Authorization ヘッダーやシークレットらしきものが編集されます。
  • リクエストはアプリバックエンドから行われ、レンダラーからではないため、認証情報は Web コンテンツにさらされません。
  • ベース URL は http: または https: のみとして検証されます。

クイックスタート：Ollama​

  1. Ollama をインストールし、モデルをプルします（例：ollama pull llama3.1）。
  2. 設定 → AI プロバイダーを開きます。
  3. カスタム / ローカルプロバイダーを選択します。
  4. プロバイダープリセットを Ollama に設定します（http://localhost:11434/v1 が入力されます）。
  5. モデルを更新をクリックしてモデルを選択するか、手動で入力します（例：llama3.1）。
  6. 接続テストをクリックして確認し、保存します。
  7. AI チャットを開きます。インジケーターは Local: Ollama と表示され、サブスクリプションなしでチャットできます。

クイックスタート：OpenAI / OpenRouter​

  1. 設定 → AI プロバイダーを開きます。
  2. カスタム / ローカルプロバイダーを選択します。
  3. プロバイダープリセットを OpenAI または OpenRouter に設定します。
  4. API キーを API キーフィールドに貼り付けます。
  5. デフォルトモデルを入力します（例：gpt-4o-mini、または OpenRouter のモデル ID）。
  6. 接続テストをクリックし、保存します。

トラブルシューティング​

プロバイダーに接続できない​

考えられる原因：

  • ローカルサーバーが実行されていない（Ollama / LM Studio / vLLM のプロセスを確認）。
  • ベース URL またはポートが間違っている。
  • ファイアウォールが localhost/lan アクセスをブロックしている。

解決策：

  1. プロバイダーを起動し、ブラウザで応答することを確認します（例：http://localhost:11434/v1/models）。
  2. ベース URL を再確認し、接続テストを実行します。
  3. Docker や WSL のセットアップでは、aiFetchly のネットワークコンテキストからプロバイダーに到達できることを確認します。

認証失敗（401 / 403）​

考えられる原因：

  • API キーが欠落している、間違っている、または期限切れである。
  • 選択したモデルへのアクセス権がキーにない。

解決策：

  1. API キーを再入力して保存します。
  2. OpenAI/OpenRouter の場合、キーが有効であり、モデルに対するクレジット/権限があることを確認します。

選択したモデルが利用できない​

プロバイダーから "model not found" が返されました。モデルを更新リストから別のモデルを選択するか、プロバイダーが実際に提供している デフォルトモデル に更新してください。

モデルリストを読み込めない​

一部のローカルサーバーは /models を実装していません。これは想定内の動作です。デフォルトモデルにモデル名を手動で入力して保存してください。チャットは引き続き機能します。

チャットは機能するが Tools / Streaming が unsupported と表示される​

すべてのローカルモデルがツール呼び出しやストリーミングをサポートしているわけではありません。これらが必要な場合は、ツールまたはストリーム対応のモデルに切り替えるか、ホステッド aiFetchly を使用してください。機能バッジを参照してください。

ホステッド限定機能が引き続きサブスクリプションを求める​

これは仕様です。カスタムプロバイダーでロックが解除されるのは AI チャットのみです。キーワード生成、メールテンプレート生成、AI リカバリ、リランク、埋め込みは、引き続き aiFetchly AI サブスクリプションが必要です。
