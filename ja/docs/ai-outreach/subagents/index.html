サブエージェント

サブエージェントは、再利用可能な専門 AI エージェントの定義です。焦点を絞った役割、システムプロンプト、許可ツール、モデル設定、実行時の制限を記述し、aiFetchly が特定の AI 作業に利用できます。

プラグインは AI Skills や MCP サーバーと一緒にサブエージェントをインストールできます。また、ご自身の繰り返し発生するワークフロー向けに、手動のサブエージェントを作成することもできます。

AI がサブエージェントを利用するしくみ​

サブエージェントを直接呼び出すことはありません。チャットの開始時に、aiFetchly は Available AiFetchly agents リストを AI のコンテキストに挿入します。各エントリには、エージェントの実行時 ID、説明、ソースが表示されます。タスクが適合する場合、AI はその ID を指定して run_subagent ツールを呼び出します。サブエージェントは自身のシステムプロンプト、許可されたツール、実行時の制限のもとで実行され、結果をメインの AI に返します。

組み込みエージェント​

aiFetchly は 1 つの組み込みサブエージェントを同梱しています。

  • Lead Researcher (agent-lead-researcher) — search-scraper と Knowledge Library のツールを使って、リードに関する公開ビジネスコンテキスト（業種、概要、製品、シグナル）を収集する specialist です。ソース URL と信頼度スコアを含む構造化 JSON オブジェクトを返します。読み取り専用です。

サブエージェントを開く​

  1. 左側のナビゲーションメニューで システム設定 をクリックします。
  2. サブエージェントを管理 をクリックします。

サブエージェントページには、コンパクトな表、検索とフィルターのコントロール、詳細ダイアログ、サブエージェントを追加 アクションがあります。

サブエージェントのソース​

ソース説明
組み込みaiFetchly に同梱されているエージェント。読み取り専用です。
プラグインプラグインによってインストールされたエージェント。サブエージェントページでは読み取り専用ですが、有効化または無効化できます。
ワークスペースワークスペースの .aifetchly/agents/ ファイルから読み込まれるエージェント。ここで有効化または無効化できます。定義を変更するにはワークスペースファイルを編集します。ワークスペースが信頼済みになるまで、ワークスペースエージェントは読み込まれません。
手動aiFetchly 内で作成したエージェント、または ~/.aifetchly/agents/ 配下の Markdown ファイルとして定義されたエージェント。編集、有効化、無効化、削除が可能です。

ソースフィルターを使うと、すべてのサブエージェントを表示することも、特定のソースだけを表示することもできます。

サブエージェントの検索とフィルター​

サブエージェントの表には次のものがあります。

列説明
Agent表示名と実行時 ID。
Descriptionエージェントが何をするかの短い要約。
Source組み込み、プラグイン、ワークスペース、手動のいずれか。
Plugin該当する場合、所有するプラグイン。
Modeエージェントの役割。specialist、verifier、coordinator、formatter など。
Toolsエージェントに許可されたツールの数。
Model設定されている場合、エージェントのデフォルトモデル。
Status有効または無効。異常なエージェントには警告インジケーターが表示されます。
Actions利用可能な場合に有効化/無効化のスイッチ。

エージェント ID、名前、説明、プラグイン名で検索できます。ステータスフィルターでは、すべて、有効、無効、警告あり のエージェントを表示できます。

詳細の表示​

サブエージェントの行をクリックすると、詳細パネルが開きます。パネルには次のものが表示されます。

  • エージェント名と実行時 ID
  • 該当する場合のソースと所有プラグイン
  • ステータスとヘルス
  • 説明
  • ソースファイルまたはプラグインコンポーネントのパス
  • モードとデフォルトモデル
  • 最大ツール呼び出し数
  • 最大実行時間
  • 最大継続呼び出し数
  • 許可されたツール
  • システムプロンプト

読み取り専用エージェントには、どこで編集すべきかを説明する注記が表示されます。手動エージェントには サブエージェントを編集 と このサブエージェントを削除 のアクションが表示されます。

手動サブエージェントの作成​

  1. サブエージェントを追加 をクリックします。
  2. Name を入力します。
  3. 生成された ID slug を確認または編集します。
  4. Description を追加します。
  5. Mode を選択します。
  6. System prompt を記述します。
  7. カンマ区切りで Allowed tools を追加します。
  8. 必要に応じて Default model を設定します。
  9. 実行時の制限を設定します。
  10. 必要に応じて Output schema の JSON オブジェクトを追加します。
  11. サブエージェントを Enabled で開始するかどうかを選びます。
  12. Save をクリックします。

ID slug は作成後にロックされるため、安定した識別子を選んでください。

手動サブエージェントの項目​

項目説明
Name表と詳細パネルに表示される、人間が読める名前。
ID slug安定した実行時識別子。最初の保存前に名前から自動生成され、後から変更することはできません。
Descriptionこのサブエージェントをいつ使うかの短い説明。
Mode機能上の役割: coordinator、specialist、verifier、formatter。
System promptサブエージェントへの指示。自己完結し、具体的にしてください。
Allowed toolsサブエージェントに許可される、カンマ区切りのツール名。実行時ポリシーは引き続き適用されます。
Default modelこのサブエージェントの任意のモデル設定。
Max tool calls1 回の実行中に許可されるツール呼び出しの最大数。
Max runtime (seconds)1 回のサブエージェント実行の最大時間。
Max continue calls継続ターンの最大数。
Output schema期待する構造化出力を記述する、任意の JSON オブジェクト。
Enabledこのサブエージェントを実行時に利用可能にするかどうかを制御します。

手動サブエージェントの編集と削除​

手動サブエージェントを開き、サブエージェントを編集 をクリックすると、名前、説明、システムプロンプト、許可ツール、モデル、実行時の制限、出力スキーマ、有効状態を更新できます。

手動サブエージェントを削除するには、詳細パネルを開いて このサブエージェントを削除 をクリックします。削除は元に戻せません。

プラグインがインストールするサブエージェント​

プラグインは、agents/ ディレクトリ内の Markdown ファイル、またはプラグインマニフェストの宣言を通じてサブエージェントを含めることができます。インストールされると、それらのファイルは aiFetchly 内のプラグイン所有のサブエージェント定義になります。

プラグインサブエージェントには次を含められます。

  • name
  • description
  • tools （および/または skills。これらは許可ツールにマージされます）
  • model
  • mode
  • 実行時の制限（maxToolCalls、maxRuntimeMs、maxTurns）
  • 任意の outputSchema
  • システムプロンプトになる Markdown 指示

プラグイン所有のサブエージェントは、lead-pack:researcher のようにプラグインによって名前空間化されます。ネストしたフォルダーでは、lead-pack:review:verifier のような深い ID を作成できます。

プラグインサブエージェントの管理​

プラグインサブエージェントは 2 か所に表示されます。

  • 完全なカタログとしては システム設定 → サブエージェント。
  • 1 つのプラグインが所有するエージェントとしては Plugin Manager → プラグインの詳細 → Subagents。

プラグイン詳細の Subagents タブでは、各エージェントの名前、ID、モード、ツール数、ヘルス、有効状態を確認できます。1 つのプラグインサブエージェントを無効化しても、そのプラグインの他のスキル、MCP サーバー、サブエージェントは無効化されません。

プラグイン全体が無効化されている場合、個別の有効スイッチがオンであっても、そのサブエージェントは利用できません。プラグインを再度有効化すると、以前に保存されたコンポーネントレベルの設定が復元されます。

ヘルスと警告​

サブエージェントは、healthy、disabled、partial_load、invalid、missing_files などのヘルス状態を報告できます。

警告は通常、aiFetchly が制限付きでエージェントを読み込んだか、ソース定義に問題を見つけたことを意味します。原因を調査するには、詳細パネルまたはプラグインの診断を開いてください。

セキュリティ上の注意​

  • プラグインサブエージェントは定義であり、独立したプログラムではありません。
  • permission mode、hooks、直接的な MCP サーバー登録、特権実行設定など、プラグインが提供するセキュリティ上重要なフィールドは無視されるか、警告されます。
  • 許可ツールはサブエージェントの上限を定義します。aiFetchly はそのリストを有効なツールと実行時ポリシーでさらに絞り込みます。
  • 手動のシステムプロンプトは自己完結させるようにしてください。サブエージェントは親チャットの履歴全体を参照できると想定すべきではないためです。
