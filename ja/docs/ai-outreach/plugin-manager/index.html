プラグインマネージャー

プラグインは、1つ以上の拡張機能（AI Skills、Subagents、スラッシュコマンド、Hooks、MCPサーバー）を、1つのマニフェスト、1つのインストールパス、1つの所有権レコードの下にまとめた単一のパッケージです。プラグインマネージャーでは、プラグインのインストール、参照、検査、有効化、無効化、アンインストールを行います。

プラグインは、スタンドアロンの AI Skills、Subagents、スラッシュコマンド、Hooks、MCP Tools の各システムの上に成り立ちます。プラグインをインストールすると、バンドルされている機能が登録され、アンインストールするとそれらが（すべて1つの単位として）削除されます。

プラグインマネージャーを開く​

左のナビゲーションから： Plugins（パズルアイコン）をクリックします。

システム設定から： System Setting を開き、Plugins をクリックします。

ページは 4つのタブ で構成されています。

タブ目的
インストール済みマシンに既に存在するプラグイン — インストール、有効化/無効化、検査、アンインストール。
Discoverマーケットプレイスのカタログを閲覧し、そこからプラグインをインストール。
MarketplacesDiscoverのソースとなるマーケットプレイスの追加、更新、削除。
Errors読み込みに失敗したマーケットプレイスとそのエラー詳細。

インストール済みタブ​

インストール済み タブには、3つのアクションを持つツールバーと、インストール済みのすべてのプラグインのテーブルがあります。

ツールバー​

  • 再読み込み — インストール済みプラグインを再スキャンします。
  • プラグインをインポート — ローカルの .zip ファイルからインストールします。
  • ソースからインストール — 6種類のソースのいずれかからインストールします（ソースからインストール を参照）。

プラグインのテーブル​

列説明
Pluginプラグイン名。
Versionインストール済みのバージョン。
Source組み込み、マーケットプレイス、または ローカル。
Imported From取得元（フォルダーパス、git URL、npmパッケージなど）。
SubAgentプラグインにバンドルされているサブエージェントの数。
Skillsスキルの数。
Hooksフックの数。
MCP ServersMCPサーバーの数。
Status現在の健全性状態（プラグインの健全性状態 を参照）。
Actionsプラグインレベルの 有効化/無効化 スイッチと、ゴミ箱（アンインストール）ボタン。

Source 列には、組み込み、マーケットプレイス、ローカル の3つの大まかなバッジのいずれかが表示されます。より具体的なインストールソース（例：git、npm、local-folder）は、プラグインの Overview タブに インストールソース として表示されます。

プラグインのインストール​

インストール済みタブには2つのインストール経路があります。

  • プラグインをインポート — ローカルの .zip ファイルを選択。
  • ソースからインストール — 6種類のソースのいずれかからインストール（下記参照）。

プラグインは、Discover タブからマーケットプレイス経由でインストールすることもできます（Marketplaces を参照）。

ソースからインストール​

ソースからインストール をクリックし、ソースの種類を選択します。ダイアログの既定値は Local Folder です。各ソースには専用のフォームがあります。

ソース受け付けるもの認証モデル
ローカル Zipディスク上の .zip ファイル。なし。
ローカルフォルダープラグインを含むディスク上のディレクトリ。フォルダーはプラグインキャッシュにコピーされ、元のソースフォルダーは変更されません。なし。
Git任意の HTTPS または SSH の git URL（https://…、git@…、ssh://…）。プレーン HTTP は拒否されます。SSHエージェントとOSのgit認証ヘルパー。認証情報がコマンドラインに渡されることはありません。
GitHubGitHub リポジトリ URL、リリースアセット URL、または releases/latest URL。リポジトリ URL はクローンされ、リリースアセット URL は直接ダウンロードされます。公開リポジトリと公開リリースアセットのみ。プライベートリポジトリには、認証ヘルパー付きの Git ソースを使用してください。
npmパブリック npm レジストリ上の任意のパッケージ。認証トークン付きの GitHub Packages およびスコープ付きレジストリも対象。レジストリ URL と認証トークンは任意指定。トークンはインストール作業ディレクトリ内の 0600 権限 .npmrc に書き込まれ、インストール後には 一切保存されません。
URL任意の URL を貼り付け — .zip、git URL、GitHub URL のいずれかをマネージャーが自動検出し、対応するルートで処理します。プレーン HTTP は拒否されます。一致したソースの設定を引き継ぎます。
セキュリティ保証

ソースに関わらず、すべてのインストールで次のことが適用されます。

  • 同一のサイズおよびファイル数上限（圧縮時 50 MB / 展開後 250 MB / 5,000 ファイル）を適用。
  • インストール中にプラグインのコードを実行しない — npm install、pip install、ライフサイクルスクリプトは一切実行しません。
  • npm pack は --ignore-scripts 付きで実行されるため、パッケージのライフサイクルスクリプトは実行されません。
  • 起動されたすべての git/npm/tar プロセスは、60秒のタイムアウトを超えると強制終了されます。
  • すべてのダウンロードは HTTPS を使用する必要があり（HTTP は拒否）、リダイレクトは最大5回までしか追跡しません。

Marketplaces​

マーケットプレイス は、閲覧やインストールが可能なプラグインのカタログです。プラグインマネージャーには、マーケットプレイス関連のタブが3つあります。

Marketplaces タブ​

マーケットプレイスのソースを管理します。

  • マーケットプレイスを追加 — 新しいマーケットプレイスを登録します。ソースには、owner/repo ショートハンド、git URL、ローカルフォルダー、marketplace.json への直接 URL が指定できます。ブランチ/タグ/コミットを指定してリビジョンを固定することも可能です（任意）。
  • すべて更新 — すべてのマーケットプレイスのカタログを再取得します。
  • 各行 — 個別のマーケットプレイスを 更新 または 削除 します。マーケットプレイスを削除しても、そこからインストール済みのプラグインはアンインストール されません。

Discover タブ​

マーケットプレイスが提供するすべてを閲覧します。

  • プラグイン名や説明で 検索。
  • マーケットプレイス および ステータス（すべて / インストール済み / 未インストール）で絞り込み。
  • 各行にプラグイン、そのマーケットプレイス、バージョン、ステータスが表示されます。詳細 をクリックすると、完全な説明、作成者、解決済みのソース、リスクフラグが表示されます。

リスクフラグと確認​

マーケットプレイスからインストールする前に、aiFetchly は機密性の高い可能性のある挙動をフラグで示します。

  • MCPサーバーを起動
  • フックを宣言
  • モニターを宣言
  • npmからインストール
  • コミットに固定されていない

いずれかのフラグが存在する場合、インストールボタンを有効にする前に 「リスクを理解した上でインストールします。」 のチェックを入れる必要があります。

既に別のバージョンのプラグインが存在する場合、ボタンは「インストール」ではなく 再インストール になります。

Errors タブ​

健全性状態が 正常 でないマーケットプレイスを、健全性状態とエラーメッセージとともに一覧表示します。読み込めないマーケットプレイスの診断に使用します。

プラグインの健全性状態​

状態意味
正常すべてのコンポーネントが正常に読み込まれました。
無効プラグインがオフに設定されています。その機能はAIには公開されません。
要設定プラグインに Python スキルが含まれています。初回使用時にランタイムが仮想環境をセットアップします。
部分ロード一部のコンポーネントは読み込まれ、他は失敗しました。Diagnostics タブでどれが失敗したかを確認できます。
不正プラグインマニフェストまたはインストール状態が壊れています。
ファイル不在インストールパスが存在しません（例：ディスクから削除された）。

詳細パネル​

任意のプラグイン行をクリックすると、9つのタブ を持つ詳細ダイアログが開きます。

Overview​

バージョン、ソース、imported-from URI、インストールパス、現在の健全性状態、commands と hooks の数、作成者、インストールソース（種類と ref）、マーケットプレイス（マーケットプレイスからインストールした場合）、説明。

Skills​

プラグインが所有する各スキル。健全性チップと個別の 有効化/無効化 スイッチが付いています。

Subagents​

プラグインが所有する各サブエージェント — 名前（ID付き）、モード、ツール数、健全性、個別の 有効化/無効化 スイッチ。プラグインにサブエージェントがない場合は空です。

Commands​

プラグインが提供するスラッシュコマンド — /name、説明、エイリアス、引数ヒント、有効/無効ステータス。読み取り専用（コマンドをここで個別に切り替えることはできません）。

Hooks​

プラグインが提供するフック — id、event、matcher、type、status。読み取り専用。

MCP Servers​

プラグインが所有する各 MCP サーバーと、そのトランスポート、およびサーバーごとの Enabled トグル。（MCP サーバーのツール探索と接続テストは、ここではなく、専用の MCP Tools ページで行われます。）

Permissions​

プラグインがマニフェストで宣言している権限。読み取り専用チップとして表示されます。

Diagnostics​

診断情報をエクスポート をクリックすると、プラグインの読み込み状態とコンポーネントごとのエラーの JSON バンドルが生成され、インラインで表示されます。トラブルシューティングや問題報告時に使用します。

Manifest​

プラグインマニフェストの、読み取り専用の整形済みビュー。

有効化と無効化​

  • プラグインレベルのスイッチ（テーブルの Actions 列）：プラグイン全体をオン/オフします。プラグインを無効化すると、その すべて の機能がAIから隠されます。
  • コンポーネントレベルのスイッチ（Skills、Subagents、MCP Servers の各タブ）：プラグイン内の個別のスキル、サブエージェント、MCP サーバーをオン/オフします。

コマンドとフックにはコンポーネントごとのトグルはありません — プラグインレベルのスイッチに従います。

任意の機能の有効状態は次のとおりです：プラグインが有効 AND（トグルが存在する場合はコンポーネントが有効）。

アンインストール​

  1. プラグインの Actions 列にある ゴミ箱 アイコンをクリックします。
  2. 確認ダイアログで 「このプラグインをアンインストールしますか？スキルおよびMCPサーバーが削除されます。」 と尋ねられます。
  3. 確認して削除します。

アンインストールを実行すると、プラグインにバンドルされた機能とキャッシュファイルが削除されます。プラグインのインストールルート外のファイルは削除されず、ユーザー自身が追加したスタンドアロンのスキル、コマンド、エージェント、フック、MCP サーバーには影響しません。

プラグインパッケージとマニフェスト​

プラグインは、次のようなレイアウトのディレクトリ（またはその zip）です。

my-plugin/
├── .aifetchly-plugin/
│   └── plugin.json          # manifest (root-level plugin.json also accepted)
├── skills/
│   └── my-skill/
│       ├── manifest.json
│       └── main.js
├── agents/                  # subagent markdown files (optional)
├── commands/                # slash command markdown files (optional)
├── hooks/                   # hook definitions (optional)
├── mcp/
│   └── servers.json         # MCP server declarations
└── docs/
    └── README.md

マニフェスト（plugin.json）は、プラグイン名、バージョン、説明、含まれる機能（skills、agents、commands、hooks、MCP サーバー設定への相対パス）、権限、依存関係（任意）を宣言します。

Claude形式のプラグイン

aiFetchly は Claude 形式のプラグインもサポートしています。Claude 形式で作成された、プラグインにバンドルされたサブエージェントとコマンドは、インストール時に自動的に適応変換されます。

トラブルシューティング​

インストールが「path escapes plugin directory」で失敗する​

プラグインマニフェストが自身のルート外のファイルを参照しています。このプラグインは拒否してください — 不正または悪意のあるものです。

インストールが「Package exceeds max size」で失敗する​

プラグインが圧縮状態で 50 MB、または展開後 250 MB を超えています。内容を削るか、より小さなプラグインを選んでください。

Git インストールがハングする​

クローンが60秒のタイムアウトを超えました。リポジトリのサイズとネットワークを確認してください。マネージャーはタイムアウト時に git プロセスを強制終了するため、ゾンビクローンは残りません。

npm インストールが 401 / 403 で失敗する​

プライベートパッケージには認証トークンを指定する必要があります。GitHub Packages の場合、レジストリ URL は https://npm.pkg.github.com で、トークンには read:packages スコープが必要です。

マーケットプレイスが読み込めない​

Errors タブを開き、マーケットプレイスの健全性状態とエラーメッセージを確認します。一般的な原因：到達不能な URL、不正な marketplace.json、存在しない git ref。マーケットプレイス行で 更新 をクリックして再試行するか、削除 して正しいソースで再追加してください。

プラグインが「要設定」と表示される​

プラグインに Python スキルがバンドルされています。Python 環境は、スキルを初回実行したときにセットアップされます。手動で一度スキルを実行してセットアップをトリガーすることもできます。

プラグインが「ファイル不在」と表示される​

インストールパスがディスクから削除されています。プラグインを再インストールして復元してください。

次のステップ​

  • AI Skills — プラグイン内でスキルがどのように機能するか。
  • Subagents — プラグインがバンドルできる、スコープ付きの専門エージェント。
  • スラッシュコマンド — 再利用可能なプロンプト/アクションコマンド。
  • Hooks — プラグインが宣言できるライフサイクルフック。
  • MCP Tools — プラグイン内で MCP サーバーがどのように機能するか。
  • AI Chat V2 — プラグインの機能がAIツールとして表示される場所。
