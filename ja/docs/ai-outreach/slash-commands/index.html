スラッシュコマンド

スラッシュコマンドは、AI Chat V2 の入力ボックスで入力する短いショートカットです。メッセージの先頭に / を入力すると、aiFetchly がすぐにアクションを実行する（チャットのクリア、ステータスの表示、プラグインのインストールなど）、あるいは再利用可能なプロンプトテンプレートを展開します。

すべてのスラッシュコマンドにはソースバッジが付いており、出所が常に分かります：

バッジソース意味
Built-inbuilt-inaiFetchly に組み込み済み。常に利用可能。
Useruserあなたが ~/.aifetchly/commands/ に作成したコマンド。
Workspaceworkspace現在のワークスペースの .aifetchly/ フォルダーに定義されたコマンド。ワークスペースが信頼されている必要があります。
Pluginpluginインストール済みプラグインが提供するコマンド。
スラッシュコマンドは AI Chat V2 で動作します

スラッシュコマンドは AI Chat V2 の入力ボックスで利用できます。V2 パネルが表示されない場合は、チャットアイコンまたは Ctrl/Cmd + K から開いてください。

スラッシュコマンドの利用​

コマンドをフルで入力することも、サジェストリストから選ぶこともできます。

キーボードの流れ​

  1. 入力ボックスをクリックし、最初の文字として / を入力します — サジェストのドロップダウンが開きます。
  2. そのまま入力を続けて絞り込みます。aiFetchly はコマンドの名前、エイリアス、または説明内の単語にマッチします。
  3. ↑ / ↓ でハイライトを移動するか、マウスでホバーします。
  4. Enter（またはクリック）でコマンドを選択します。これにより /name が入力ボックスに挿入され、ドロップダウンが閉じます — まだ送信されません。
  5. 挿入されたコマンドの後に引数を入力します（例えば翻訳対象のテキスト）。
  6. Enter を押して実行します（Shift + Enter は通常通り改行を挿入します）。
  7. いつでも Esc を押すと、何も選択せずにドロップダウンを閉じられます。
キー動作
/（先頭）サジェストのドロップダウンを開く
追加で入力名前 / エイリアス / 説明でリストを絞り込む
↑ / ↓ハイライトを移動する
Enterハイライトされたコマンドを選択（/name を入力）
Escドロップダウンを閉じる
Shift + Enter改行（通常の入力ボックスと同じ）
コマンドをフルで入力する

ドロップダウンは単なる補助です — 無視して自分でコマンド名を入力することもできます（例: /clear）。ただしドロップダウンが開いている間は、Enter を押すと入力した内容ではなくハイライトされた候補が選択される点に注意してください。先に Esc でドロップダウンを閉じてから Enter を押せば、入力した内容が実行されます。

コマンドは先頭でのみトリガーされます

メッセージは先頭が / で始まり、添付ファイルがない場合にのみスラッシュコマンドとして扱われます。/ で始まるリテラルテキストを送信したい場合は、最初にスペースや単語を追加してください（例: " /path/to/file"）。

組み込みコマンド​

これらは aiFetchly に組み込まれており、常に利用可能です。AI を呼び出さずに即座に実行されます（/plugin のみ例外で、インストールアクションを実行します）。

コマンド説明
/help利用可能なスラッシュコマンドとそのソースを一覧表示します。
/clear現在の会話をクリアします。
/statusaiFetchly の設定ステータス、カウント、診断情報を表示します。
/skillsこのシステムで現在利用可能な AI スキル/ツールを一覧表示します。
/agents利用可能な aiFetchly エージェント（組み込みおよび動的）を一覧表示します。
/reload-config~/.aifetchly を再スキャンし、設定を再読み込みします。
/goalAI Chat のアクティブな目標を作成または置換し、プランモードに入ります。
/loopアクティブな目標に向けて制限付きの自律イテレーションを実行します。
/pluginプラグインマーケットプレースを管理し、チャットからプラグインをインストールします。

/help​

現在のスコープ（built-in + user + workspace + plugin）で利用可能なすべてのコマンドのクイックインベントリを実行し、それぞれにソースバッジを付けて表示します。自分自身（またはプラグイン）が追加したコマンドを見つけるのに役立ちます。

/clear​

現在の会話を空にします。会話履歴ダイアログを開かずに新規開始できます。元に戻すことはできません。

/status​

aiFetchly の設定のスナップショットを出力します。読み込まれたコマンド、エージェント、フック、スキルの数、発生した診断の数、設定が最後に再読み込みされた時刻などが分かります。自作コマンドが読み込まれなかった場合のトラブルシューティングに便利です。

/skills と /agents​

/skills は現在このシステムで有効になっている AI スキル/ツールの一覧を表示します。/agents は利用可能な aiFetchly エージェント（組み込みおよび動的）を一覧表示します。背景については AI Skills と Subagents を参照してください。

/reload-config​

~/.aifetchly の再スキャンを強制し、設定を再読み込みします。アプリ外でコマンドファイルを手動で編集または追加した後に、それらをすぐに反映させたい場合に使います。ファイルウォッチャーが動いていれば新規コマンドは通常自動で表示されますが、これは手動のフォールバックです。

/plugin​

引数を取る唯一の組み込みコマンドです。チャットから離れることなく、プラグインマーケットプレースを管理してプラグインをインストールできます。

/plugin marketplace add <source> [--ref <ref>] [--overwrite]
/plugin install <plugin@marketplace|source> [--overwrite] [--ref <ref>] [--kind <kind>]

<source> にはローカルフォルダー、.zip ファイル、Git/GitHub/HTTPS URL、owner/repo GitHub 短縮表記、または npm:<package> を指定できます。省略可能な --kind は local-zip | local-folder | git | github | npm | url のいずれかです。

例:

/plugin marketplace add https://github.com/acme/aifetchly-plugins
/plugin install lead-tools@acme-plugins
/plugin install npm:@acme/awesome-plugin

プラグインのライフサイクル全体については Plugin Manager を参照してください。

/goal と /loop​

上記の他の組み込みコマンドとは異なり、この 2 つは AI 主導で連携します。/goal は持続的で検証可能な目標を設定し（プランモードに入り）、/loop <maxIterations> はその目標に向けて制限付きの自律イテレーションを実行します。完了は証拠に基づきます — アシスタントが自身の目標を完了と宣言することはできません。

/goal Build a Facebook campaign scraper and verify it works
/loop 5

受け入れ基準、検証方法、ループの上限、停止条件、各ステータスの意味については、専用ページ ゴールとループのコマンド を参照してください。

コマンドのソースと優先順位​

4 つのソースからのコマンドは 1 つのリストにマージされます。2 つのコマンドが同じ名前を持つ場合、次の優先順位によってどちらが実行されるかが決まります：

Built-in → Workspace → User → Plugin

  • **組み込み（Built-in）**コマンドは上書きできません。/clear、/help などは常に aiFetchly が定義した通りの意味を持ちます。
  • **ワークスペース（Workspace）コマンドは、同名のユーザー（User）コマンドをシャドウし、さらにユーザーコマンドはプラグイン（Plugin）**コマンドをシャドウします。
  • エイリアスも同様です。カスタムコマンドに clear というエイリアスを付けても、/clear は組み込みコマンドを実行します（組み込みの名前とエイリアスが常に優先されます）。

つまり、プラグインが outreach コマンドを定義していても、自分で outreach というカスタムコマンドを安全に作成できます — 自分のコマンドがプラグインより優先されます。ただし同名の組み込みコマンドがあれば、それがあなたより優先されます。

カスタムコマンドの作成​

カスタムコマンドは、小さな Markdown ファイルとして保存される再利用可能なプロンプトテンプレートです。よく送信するプロンプトに最適です。調査チェックリスト、固定のアウトリーチ構成、翻訳リクエスト、要約フォーマットなどに使えます。

配置できる場所は 2 つあります：

場所スコープ信頼
~/.aifetchly/commands/*.mdすべてのチャットで利用可能（あなたのグローバルコマンド）。自動的に信頼されます — あなたが作成したものだからです。
<workspace>/.aifetchly/commands/*.mdそのワークスペースがアクティブな場合にのみ利用可能。ワークスペースが信頼されている必要があります。

~ はあなたのホームディレクトリです（macOS/Linux では /home/you、Windows では %USERPROFILE%）。.aifetchly フォルダーは aiFetchly のグローバル設定ルートです。

ファイル形式​

各コマンドは 1 つの .md ファイルで、小さな frontmatter ヘッダーとプロンプト本体から構成されます：

---
name: outreach
description: Draft a cold outreach email for the given company.
type: prompt
argumentHint: <company website>
aliases:
  - reach
---
Research the company behind the following website, then write a concise,
friendly cold-outreach email proposing how aiFetchly could help them find
more leads. Keep it under 120 words.

$ARGUMENTS

Frontmatter のフィールド​

フィールド必須メモ
nameはい小文字、数字、-、_。先頭は文字でなければなりません。例: outreach。これが / の後に入力する名前になります。
descriptionはい最大 500 文字。サジェストのドロップダウンに表示されます。
typeはいカスタムプロンプトコマンドの場合は prompt でなければなりません。
argumentHintいいえ最大 100 文字。名前の横に表示されるヒント（例: <text>）。
aliasesいいえ最大 10 個の代替名。それぞれが name のルールに従います。YAML 文字列配列として記述します。

本体（2 つ目の --- 以降のすべて）がプロンプトテキストです。空であってはなりません。

正確なフィールド名を使用してください

frontmatter のパーサーは単純な key: value 行と文字列配列のみを理解します — セキュリティ上の理由から、意図的に完全な YAML パーサーにはなっていません。上記のフィールドのみを使用してください。ネストされたマップ、引用符で囲んだ複数行の値、未知のフィールドを追加して何か意味のある動作を期待しないでください。

$ARGUMENTS トークン​

コマンド名の後に入力した内容が、そのコマンドの引数になります。$ARGUMENTS トークンは、そのテキストがプロンプト内のどこに挿入されるかを制御します：

  • 本体に $ARGUMENTS が含まれる — すべての出現箇所が入力テキストに置換されます。
  • 本体に $ARGUMENTS はないが入力した場合 — 入力テキストは本体の末尾に追加され、黙って切り捨てられることはありません。
  • 何も入力しなかった場合 — 本体はそのまま使用されます。

/outreach acme.com の例：

Research the company behind the following website, then write ...
more leads. Keep it under 120 words.

acme.com

その他の例​

引数なしのコマンド（/review で呼び出す固定チェックリスト）：

---
name: review
description: Load my standard lead-review checklist into the chat.
type: prompt
---
Review the most recent lead in this conversation against my checklist:
1. Is the website a real business?
2. What product/service do they sell?
3. Who is the likely decision-maker?
4. What is a relevant hook for outreach?
Return the answers as a short table.

エイリアスを持つコマンド（/translate または /tr として呼び出し可能）：

---
name: translate
description: Translate the given text to English.
type: prompt
argumentHint: <text>
aliases:
  - tr
---
Translate the following text to English:

$ARGUMENTS

制限​

  • 各コマンドファイル: 最大 64 KB。
  • ソースごとに最大 200 コマンド。
  • description: 最大 500 文字。argumentHint: 最大 100 文字。aliases: 最大 10 個。

これらのルールに違反するファイルや、frontmatter が無効なファイルはスキップされ、/status で診断情報として表示されます。

ワークスペースコマンドと信頼​

ワークスペースの .aifetchly/commands/ フォルダーに配置されたコマンドは、リポジトリ経由でチームとコマンドを共有するための強力な手段です。これらはチェックアウトしたばかりのフォルダーに由来する可能性があるため、aiFetchly はデフォルトで信頼できないものとして扱います。

  • ワークスペースが設定を定義している場合、aiFetchly は Workspace AiFetchly config プロンプトを表示し、コマンドを有効化する前に内容を確認して信頼するよう求めます。
  • ワークスペースを信頼するまで、そのコマンドはドロップダウンから非表示になり、実行できません — "Command /name is disabled because workspace config is not trusted." と表示されます。
  • ワークスペースコマンドは属するワークスペースにスコープされます。ワークスペース A のコマンドが、ワークスペース B を使うチャットで利用できることはありません。

これがコマンドの出自に対する本当のセーフティゲットです — リポジトリ内の他のコードをレビューするのと同様に、ワークスペースを信頼する前に必ずその .aifetchly/ フォルダーを確認してください。

プラグインコマンド​

プラグインは、スキルや MCP サーバーと並んで独自のスラッシュコマンドをバンドルできます。プラグインをインストールすると、そのコマンドは自動的に Plugin バッジと plugin:<name> ソース ID とともに表示されます。プラグインのインストールと管理については Plugin Manager を、より広範なプラグイン所有の機能モデルについては AI Skills を参照してください。

ヒント​

推奨 ✅​

  • /help を使う — 現在のスコープで利用可能なコマンドを正確に確認できます。
  • 繰り返しのプロンプトはコマンド化する — 同じ指示を 3 回入力したなら、/command を作りましょう。
  • 短いエイリアスを付ける — 入力が素早く済みます（例: translate に対して tr）。
  • /status を実行する — 追加したばかりのカスタムコマンドが表示されない場合、診断カウントでファイルの読み込み失敗を確認できます。
  • ワークスペース設定は意識的に信頼する — 承認前にコマンドを読みましょう。

非推奨 ❌​

  • 組み込みの上書きを期待しない — /clear、/help などは常に優先されます。別の名前にしてください。
  • コマンドファイルにシークレットを書き込まない — ディスク上のプレーンな Markdown であり、リポジトリ経由で共有される可能性があります。
  • 読んでいないワークスペース設定を信頼しない — そのコマンドはプロンプトを実行し、ツールを呼び出す可能性があります。
  • Tab での自動補完を期待しない — ドロップダウンから選ぶには Enter を使います。

トラブルシューティング​

自作コマンドがドロップダウンに表示されない​

  • ファイルが ~/.aifetchly/commands/<name>.md（またはワークスペースの同等のパス）にあり、.md 拡張子で終わっていることを確認します。
  • name がルールに合致しているか確認します（小文字、先頭は文字、使用できるのは文字/数字/-/_ のみ）。
  • type: prompt が存在し、本体が空でないことを確認します。
  • /status を実行します — 診断カウントが 0 でなければ、ファイルのバリデーションに失敗しています。/reload-config で再スキャンを強制します。
  • 組み込みの優先順位を思い出してください。同名の組み込みコマンドやワークスペースコマンドが、あなたのコマンドをシャドウします。

"Unknown slash command: /name" と表示される​

そのコマンドは現在のスコープで利用できません。アクティブでない、または信頼されていないワークスペースのコマンドか、インストールされていないプラグインのコマンドの可能性があります。/help を実行すれば現在利用可能なすべてのコマンドが一覧表示されます。

"Command /name is disabled." と表示される​

そのコマンドは、まだ信頼していないワークスペースに由来しています。ワークスペースの信頼プロンプトを開き、設定を確認してから有効化してください。

コマンドを選択したのに実行されなかった​

それは仕様です。ドロップダウンからコマンドを選ぶと /name が入力ボックスに挿入され、リストが閉じます。引数を入力してから Enter を押すと実行されます。
