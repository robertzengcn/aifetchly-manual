ゴールとループのコマンド

/goal と /loop のスラッシュコマンドを使うと、AI Chat V2 アシスタントに永続的な目標を与え、1ターンごとにプロンプトを送る代わりに、その目標に向かって上限付き・検証可能なステップで作業を進めたり、固定間隔でプロンプトを再実行したりできます。

/goal は「完了」の意味を、明示的で検証可能な受け入れ基準とともに記録します。そして /loop には 2 つのモード があります。

  • ゴールループ — /loop 5 は、アクティブなゴールに向かって限られた回数の自律反復を実行し、新しい証拠を集め、ゴールを完了と判定する前に各基準を検証します。
  • スケジュール済みループ — /loop 5m check the deployment はプロンプトを固定間隔（5分ごと、2時間ごと…）で再実行し、時間とともに変化する作業を監視できるようにします。すべての実行と応答は同じ会話に残ります。
AI Chat V2 のみ

/goal と /loop は AI Chat V2 の入力欄で使える組み込みスラッシュコマンドです。AI が有効な aiFetchly の有効なサブスクリプションが必要で、AI Chat V2 既存の プランモード、ツール承認、ワークスペースの安全境界を再利用します。

/loop の 2 つのモード​

どのモードになるかは、/loop の後に何を入力したかで決まります。

モードコマンドできること必要条件
ゴールループ/loop <maxIterations>アクティブなゴールに向かって、その回数までの自律反復を実行する。/goal で設定済みのアクティブなゴール。
スケジュール済みループ/loop <duration> <prompt>プロンプトを固定間隔で、同じ会話内で再実行する。空でないプロンプト。
スケジュール済みループの制御/loop status・/loop pause・/loop resume・/loop stopアクティブな会話のスケジュール済みループを管理する。この会話にアクティブなスケジュール済みループがあること。

単なる整数（/loop 5）は常にゴールループを意味します。期間（/loop 5m …）は常にスケジュール済みループを意味します。2 つのモードが互いに干渉することはありません。

/goal — 永続的な目標を設定する​

構文​

/goal <objective>

例：

/goal Build a Facebook campaign scraper and verify it works

何が起こるか​

  1. その目標が現在の会話の アクティブなゴール になります。
  2. AI Chat が プランモード に入ります。目標が曖昧な場合、アシスタントは明確化の質問をします。
  3. アシスタントは 1 つ以上の 受け入れ基準 を含むプランを提案します。「完了」の意味を定義する具体的で検証可能な条件です。
  4. 通常のプランモードの承認フローで、プランを承認（または却下・変更要求）します。
  5. ゴールは 完了、ブロック、キャンセル されるまで、その会話でアクティブのままです。

/goal を再度実行すると、現在のアクティブなゴールが置き換えられます。

受け入れ基準と検証​

各受け入れ基準は自動的に検証されます — アシスタントが「完了」と言ったからといってゴールが完了することはありません。各基準には検証方法があります。

方法基準をどう確認するか
commandコマンドが成功で終了する。終了コードや出力パターンとの一致も任意で指定可能。
file期待されるファイルやプロジェクト状態が存在する（例：ファイルが存在する、変更された）。
manualループが一時停止し、あなたに確認を求める。
llm決定論的に確認できない基準について、独立した検証器が集めた証拠を評価する。

基準は 必須 または任意としてマークできます。ゴールが完了と判定されるのは、すべての必須基準 が新しい証拠でパスしたときだけです。

検証可能な目標を書く

/goal は「完了」をアプリが検証できるものにすると最も機能します。「スクレイパーを構築し、動作を検証する」のような目標 — 「テストコマンドが終了コード 0 で終了する」のような基準と組み合わせると — 「スクレイパーを良くする」のような主観的なものよりはるかに信頼できます。

ゴールループ — /loop <maxIterations>​

構文​

/loop <maxIterations>

<maxIterations> は 1 から 10 の整数です。明示的に指定してください — 省略したり範囲外の値を渡したりすると、/loop は有効なカウントを求めます。ゴールループはまた アクティブなゴールを必要とします。設定していない場合は、まず /goal を実行するよう促されます。

例：

/loop 5

各反復がすること​

各反復は同じ 観測 → 行動 → 検証 のサイクルを実行します。

現在の状態を観測
  → アシスタントが上限付きの次のアクションを1つ提案
  → 承認されたツールがそれを実行
  → システムが新しい証拠を収集
  → まず決定論的なチェックを実行
  → 残りの基準を独立した検証器が評価
  → ループが継続、完了、ブロック、または入力待ち

ループの実行中、進捗が会話に表示されます — 反復カウント、収集した証拠の要約、基準ごとの検証結果です。

ゴールループが止まるタイミング​

ゴールループは永遠に実行されることはありません。以下のいずれかが成立した時点で即座に停止します。

  • あなたが Stop を押す。
  • 最大反復回数に達した。
  • 実行あたりの時間制限に達した。
  • ゴールが 完了 した — すべての必須基準が新しい証拠でパスした。
  • ツールが承認を必要とする、またはプランモードが承認を必要とする。
  • アシスタントが質問する必要がある。
  • 同じ失敗が十分な回数繰り返され、ゴールが ブロック になった。
  • 検証器が blocked または needs_user_input を返した。
  • 回復不能なエラーが発生した。

完了がどう決まるか​

作業を行うアシスタントは、自分の宣言で自分のゴールを完了にすることはできません。完了には 新しく基準固有の証拠 が必要です — 例えば、最新のコード変更の 後で パスしたテストであり、以前の古い結果ではありません。

決定論的なチェック（コマンド、ファイル状態）が最初に実行されます。独立した LLM 検証器は決定論的に確認できない基準にのみ使われ、特定の証拠に紐付いた構造化された評定（satisfied、not_satisfied、blocked、needs_user_input）を返します — 自由文の「完了」は決してありません。

スケジュール済みループ — /loop <duration> <prompt>​

スケジュール済みループはプロンプトを固定間隔で再実行し、すべての実行とすべての応答を同じ会話に保ちます。ゴールを必要とせず、実行ごとに新しいチャットを作ることもありません。

/loop 5m check if the deployment finished and tell me what happened

時間とともに変化する作業 — デプロイ、インポート、キャンペーンの返信、スクレイピングジョブ、外部承認 — を手動で同じプロンプトを再送することなく監視するために使います。

スケジュール済みループを使うタイミング​

  • デプロイの監視 — /loop 5m check if deployment 218 finished and summarize the result
  • キャンペーンの監視 — /loop 1h --times 8 -- summarize new campaign replies and flag urgent leads
  • 長時間のインポート — /loop every 15m --for 3h -- check the contact import and report new failures

実行の合間に同じ会話でチャットを続けられます。次のスケジュール実行は、あなたの対話メッセージをコンテキストの一部として取り込みます。

構文​

短縮形 — 間隔の後にプロンプトを続ける：

/loop <duration> <prompt>
/loop 5m check if the deployment finished and tell me what happened
/loop 2h summarize any new campaign replies

正規形 — 明示的な上限指定用。プロンプトの前に -- セパレータを置く：

/loop every <duration> [--times <count>] [--for <duration>] -- <prompt>
/loop every 5m --times 12 -- check if the deployment finished
/loop every 1h --for 8h -- summarize new campaign replies
/loop every 30m --times 6 --for 3h -- check the import status

--times と --for の両方を指定した場合、先に到達した方の上限で停止します。正規形では -- セパレータが必須で、「times」や「for」という単語を含むプロンプト本文がオプションとして誤解されないようにします。

期間のルール​

間隔は 2 つの単位を使います。

  • m — 分
  • h — 時間

ルール：

  • 最小間隔：1m。最大間隔：24h。
  • 値は単位の前にスペースのない正の整数 — 5m、2h、30m。
  • 単位は大文字小文字を区別しません（5M と 5m は同じ）。
  • 小数、符号、科学表記、スペース、未知の単位は拒否されます。

拒否される例：

/loop 0m check deployment
/loop -5m check deployment
/loop 1.5h check deployment
/loop 5 minutes check deployment
/loop 5m
/loop 5d check deployment

デフォルトと最大の上限​

スケジュール済みループは 常に上限付きです — 実行回数と有効期間の両方で。

上限デフォルト最大
実行回数（--times）24100
有効期間（--for）24 時間7 日

短縮形 /loop 5m <prompt> は 最大24回・最大24時間 実行されます — どちらか先に来た方が適用されます。5分間隔では通常、実行回数が先にループを終わらせます。正規形の --times と --for を使えば、どちらかの上限を最大まで引き上げられます。

開始時に何が起こるか​

コマンドが受け入れられると、AI Chat V2 は見えるスラッシュコマンドと短い確認メッセージを同じ会話に追加します。例：

Scheduled every 5 minutes. Maximum 24 runs or 24 hours. Next run: 14:35.

最初の実行はループ開始から 1間隔後 に行われます — すぐには実行されません。確認メッセージが次回実行時刻を示すので、最初の確認がいつ行われるか正確に分かります。

スケジュール実行は1つの会話に留まる​

各実行は会話の通常の永続的なターンになります。

  1. スケジュールされたプロンプトが元の会話に追加される。
  2. AI がその会話の既存の履歴とコンテキストを受け取る。
  3. アシスタントの応答が 同じ 会話に追加される。
  4. その会話が開いている場合、更新され、応答がライブでストリーミングされる。
  5. 別の会話が開いている場合、aiFetchly は元の会話のプレビューと未読インジケータを更新し、現在の作業からあなたを遠ざけません。

スケジュールされたユーザーターンは小さな時計アイコンと実行ラベル（例：Scheduled — Run 2）で表示され、あなたが入力したメッセージと区別できます。

1つの会話、1つのタイムライン

すべての実行が1つのトランスクリプトを共有するため、後の実行は前の観測を基に積み上げられます。実行の合間にフォローアップの質問をすることもでき、次のスケジュール実行に取り込まれます。

ステータス、一時停止、再開、停止​

会話にアクティブなスケジュール済みループがある間、チャットヘッダーにループの状態とコンパクトな操作を備えた ステータスチップ が表示されます。

  • Pause — 新しい実行の開始を止める。履歴は保持される。
  • Resume — 次の実行時刻を計算して再開する。見逃した実行は再実行されない。
  • Stop loop — 以降の実行をすべて防ぐ。現在実行中の実行は完了まで許可される。
  • Stop current run — 現在実行中の実行だけを中断する。以降の実行はスケジュール通り続く。

同じ操作は、アクティブな会話に限定したコマンドとしても利用できます。

/loop status
/loop pause
/loop resume
/loop stop

これらはアクティブな会話のループにしか影響しません。別の会話のループを停止・変更することはできません。すべての制御操作は冪等です — 2回実行しても1回と同じ結果になります。

スケジュール済みループのライフサイクル​

スケジュール済みループは以下の状態を遷移します。

ステータス意味
active次の実行を待っている。
running実行が今まさに進行中。
paused一時停止中 — 再開するまで新しい実行は始まらない。
expired実行回数または有効期間の上限に達した。
failed繰り返しの実行失敗または回復不能なエラーでループが停止した。
stoppedあなたが停止した（または会話が削除された）。

再起動・スリープからの復旧​

スケジュール済みループは永続的なスケジューラに支えられているため、アプリの再起動やシステムのスリープに耐えます。

  • 実行を見逃していなければ、次回実行時刻は保持される。
  • アプリが閉じていたりスリープ中に実行を見逃した場合、最大1回のキャッチアップ実行 だけが行われる — 見逃した間隔ごとに1回のバーストは決してない。
  • オフライン中に有効期間が切れた場合、単に期限切れとマークされる。
  • 時刻、サマータイム、タイムゾーンの変更が重複実行を生むことはない。

データベースが信頼できる情報源です。更新通知を見逃しても、会話を開き直すだけで完全で正確な履歴が再読み込みされます。

上限と安全性​

上限値
間隔（/loop <duration>）1m – 24h
実行回数デフォルト24、最大100
有効期間デフォルト24h、最大7日
会話あたりのアクティブなスケジュール済みループ1つ
実行あたりの時間上限10分
ループが失敗するまでの連続失敗回数3

常に適用される安全性の保証：

  • スケジュール済みループは 常に上限付きです — 実行回数と有効期間で。永遠に実行されることはありません。
  • 常にキャンセル可能 です（Stop）。
  • 対話ターンが優先されます。 実行予定時にあなたが会話の途中なら、スケジュールされた実行は延期または統合されます — あなたのターンを中断することはありません。
  • 実行は 決して重複しません。実行が間隔より長くかかる場合、予定の実行は1つの保留中の実行に統合されます。
  • ツールポリシーはタスクスコープです。 スケジュール実行は無人なので、明示的に承認されたツールのみが利用可能で、影響の大きなツールはブロックされたままです。対話的な「Always Allow」の選択は、スケジュール済みループができることを 広げません。
  • AI の有効化 とワークスペース・ファイルの安全境界は引き続き適用されます。
  • ループはアシスタントの言葉（「done」「complete」）から完了を推論 しません。上限、失敗のしきい値、明示的な Stop、または会話が消えた場合にのみ停止します。
会話のクリア・削除はそのループを停止します

会話にアクティブなスケジュール済みループがある場合、履歴をクリアするとループも停止することの確認が求められ、会話を削除すると先にループを停止します。aiFetchly は削除された会話に対して無人のループを残したままにすることはなく、削除された会話を再作成することもありません。

ゴールとループのステータス​

ゴールは以下の状態を遷移します。

ステータス意味
draftゴールがプランモードで定義中。
active承認済みで、実行または継続を待っている。
running/loop が反復を実行中。
completeすべての必須基準が新しい証拠でパスした。
blocked繰り返しの失敗や未解決のブロッカー — あなたの注意が必要。
needs_user_inputループが質問や確認のために一時停止した。
failed回復不能なエラーが実行を終了させた。
cancelledあなたが停止した。

上限と安全性​

上限値
ゴールループの反復回数（/loop <N>）1–10（明示的に指定）
実行あたりの時間上限10分（デフォルト）
ブロック までの同一失敗回数3
会話あたりのアクティブなゴール1つ（新しいゴールを設定すると古いものが置き換わる）

常に適用される安全性の保証：

  • すべてのループは 常に上限付きです — 無限になることはありません。
  • 常にキャンセル可能 です（Stop を押す）。
  • AI の有効化、ツール承認モード、プランモード、ワークスペース・ファイルの安全境界は、ループ中も引き続き適用されます。
  • 破壊的なアクション、新しい依存関係、認証の変更、その他の影響の大きな副作用は、ループの途中であっても通常の承認境界を引き続き必要とします。
  • 検証器に示される証拠やログは、スコープ・サイズ上限付きで秘密がマスキングされ、信頼できないデータとして扱われます — 指示としては扱われません。

ヒント​

DO ✅​

  • ゴールループの前にゴールを設定する — /loop 5 は常にアクティブな /goal を必要とします。
  • 目標を検証可能にする — 主観的なものより、アプリが確認できる基準（コマンド、ファイル）を優先。
  • 小さなカウントでゴールループを始める（/loop 3）。もっと進める前に進捗を点検。
  • プランモードをオンのままにする — ファイルを変更する、アウトリーチを送る、多くのツール呼び出しを実行するゴールについて。
  • 監視にはスケジュール済みループを使う — 時間とともに変化するもの（デプロイ、インポート、キャンペーン）が適しています。
  • チャットアクセスを有効のままにする — スケジュール済みループは AI_DISABLED の失敗が繰り返されると一時停止します。

DON'T ❌​

  • 無制限の自律性を期待しない — ゴールループは常に1〜10の明示的なカウントを必要とし、スケジュール済みループは常に実行回数と有効期間の上限を持ちます。
  • 単なる「done」を信じない — ゴールの完了は証拠駆動です。必須基準がパスしていなければ、ゴールは完了していません。
  • アプリを閉じている間もスケジュール済みループが動くと期待しない — aiFetchly が開いている間だけ動き、再起動時に最大1回キャッチアップします。
  • 対話的な「Always Allow」がスケジュール実行に適用されると期待しない — スケジュールのツール権限はタスクスコープで、より厳格です。

トラブルシューティング​

症状おそらく原因対処
「Set a goal first with /goal」この会話にアクティブなゴールがない/goal <objective> を実行し、まずプランを承認する。
「Please provide an iteration count」数字なしで /loop を呼んだカウントを指定する（例：/loop 5）。
「Iteration count must be between 1 and 10」カウントが不在・ゼロ・10超1〜10の整数を使う。
「The interval must be between 1 minute and 24 hours」期間が1m未満、24h超、または不正5m や 2h のような整数の m/h 値を使う。
「A prompt is required for a scheduled loop」/loop 5m にプロンプト本文がない間隔の後、または正規形では -- セパレータの後にプロンプトを追加する。
「No active scheduled loop for this conversation」実行中のループがないのに /loop pause/resume/stopまず /loop <duration> <prompt> でループを開始する。
スケジュール済みループが早く止まった実行回数/有効期間の上限に達した、または3回連続失敗理由をステータスチップで確認。--times/--for で上限を上げるか、失敗に対処して新しいループを開始する。
ゴールが ブロック になった同じ失敗が（デフォルトで3回）繰り返された会話内の失敗理由を読み、根本原因に対処してから再び /loop するか、ゴールを調整する。
ゴールが needs_user_input のままループがあなたの回答や承認を待っている質問に答えるか、保留中のアクションを承認する。
スケジュール実行がちょうどの時刻に起こらなかったチャット中は実行が延期、長引くと統合、スリープ後は1回キャッチアップされる期待される挙動です。ステータスチップと次回実行時刻を確認。
