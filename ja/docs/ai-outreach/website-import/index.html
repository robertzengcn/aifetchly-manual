Webサイトをナレッジライブラリにインポート

Import Website 機能を使うと、公開されているWebページをURLから直接、検索可能なナレッジライブラリのドキュメントに変換できます。事前にページをファイルとして保存する必要はありません。aiFetchlyがページを取得してクリーンなMarkdownに変換し、アップロードしたファイルと同じRAGパイプラインでインデックスするため、インポートしたページはすぐにAI Email Writer、AI Chat、ナレッジライブラリの検索で利用できます。

サブスクリプションが必要

Webサイトのインポートはチャンク分割と埋め込み生成を実行するため、AIが有効なaiFetchlyサブスクリプションが必要です。AIが無効な場合、ページを取得する前にインポートがブロックされます。

2つのインポート方法​

Webページは2つの方法でインポートできます。どちらも同一のナレッジライブラリドキュメントを作成します。

方法場所適しているケース
Import Website ダイアログナレッジライブラリページ → Import Website ボタンすべてのオプションを使った制御された手動インポート
AI Chat ツールAI Chat でアシスタントに依頼会話形式での素早いインポート（「料金ページをインポートして」）

このページの以降では手動ダイアログを中心に説明します。AI Chatからの手順は、下の AI Chatからインポート を参照してください。

インポートモード​

ダイアログで3つのモードから1つを選択します。

モード入力使用する場面
Single pageURL1件（+任意のタイトル）特定の1ページが欲しい場合
URL list1行1URL、最大50件取得したいページがすでに分かっている場合
Site crawl開始URL1件 + ページ数/深さの上限同一生成元のリンクをたどってドキュメントサイトやFAQを取り込みたい場合
ページごとに1ドキュメント

インポートしたWebページは、Webサイトごとに1つの巨大なドキュメントではなく、それぞれ固有のナレッジライブラリドキュメントになります。これにより引用が正確になり、個々のページを削除・更新しやすく、重複検出も信頼できます。

Import Website ダイアログを使う​

手順 1: ダイアログを開く​

  1. 左のナビゲーションから Knowledge ページを開きます。
  2. ページヘッダーの Import Website をクリックします。

手順 2: インポートモードを選ぶ​

ダイアログ上部の Single page、URL list、Site crawl のいずれかを選択します。フォームは選んだモードに合わせて変化します。

手順 3: URLを入力する​

  • Single page と Site crawl — 1つの URL を入力します（クロールモードでは Start URL というラベルになります）。公開された http:// または https:// アドレス（例: https://example.com/pricing）を使用してください。
  • URL list — URLs ボックスに1行1URLで入力します（最大50件）。空行は無視されます。

手順 4: モード固有のオプションを設定する​

  • Single page — 任意で Title を設定し、ページ本来のタイトルを上書きできます。
  • URL list と Site crawl — Max pages（インポートするページ数）を設定します。
  • Site crawl — さらに Max depth（開始URLからたどるリンクのホップ数）を設定します。

手順 5: 共通メタデータを追加する（任意）​

フィールド説明
Tagsインポートするすべてのページに適用するカンマ区切りのタグ（例: pricing, product）。
Authorドキュメントに記録される作成者。既定は Website。
Descriptionドキュメントに保存する任意の説明。
Duplicate policySkip duplicates（既定）または Allow duplicates。重複の扱いを参照してください。

手順 6: インポートして確認する​

Import をクリックします。進行状況パネルに現在のページ、発見されたリンク数（クロールモード）、インポート数／スキップ数のライブカウントが表示されます。

インポートが完了すると、ダイアログに次の一覧が表示されます。

  • Imported — 各ページのタイトル、取得元URL、作成されたチャンク数。
  • Skipped — インポートされなかった各URLとその理由（重複、空のコンテンツ、取得失敗、ブロックされたURLなど）。
  • Discovered — クローラーが見つけた同一生成元リンクの数（クロールモード）。

Import another で新しいインポートを開始するか、Close でナレッジライブラリに戻ります。インポートしたページはアップロードしたファイルと同様にドキュメント一覧に表示され、すぐに検索できます。

上限​

上限値
URL list の最大URL数50
Max pages の範囲（URL list と Site crawl）1〜100（既定 20）
Max depth の範囲（Site crawl）0〜4（既定 2）
許可されるURLスキームhttp://、https:// のみ
クロールの範囲同一生成元のみ（クロスオリジンのクロール不可）

これらの上限は埋め込みコストを抑え、クロールを範囲内に保ちます。クローラーは控えめな既定値（低い並行度とリクエスト間の小さな待機）にも従います。

インポートしたコンテンツの保存方法​

各WebページはMarkdownに変換され、標準のRAGパイプラインで取り込まれます。

  1. 取得 — aiFetchlyのブラウザベースのスクレーパー（Webサイト分析と同じエンジン）でページを読み込みます。
  2. 抽出と変換 — ナビゲーション、スクリプト、スタイルなどの不要部分を削除し、本文をMarkdownに変換します。
  3. ステージング — Markdownをアプリ所有のドキュメントとして保存します。
  4. チャンク分割と埋め込み — アップロードしたファイルとまったく同じようにチャンク分割し埋め込みを生成します。
  5. インデックス — ページが検索可能になり、RAGコンテキストとして利用できます。

生成されるドキュメント名は {hostname}-{path}-{hash}.md のパターン（例: example.com-pricing-a1b2c3d4.md）に従い、取得元URLがドキュメントに記録されます。

抽出品質

aiFetchlyは最も可能性の高い本文領域（article、main、ドキュメント用コンテナ、最終的にbody）を選択します。品質はサイトにより異なり、読み取れるテキストが少ないページ（ログインページ、エラーページ、JavaScript中心のアプリ）は空としてスキップされることがあります。抽出品質は時間とともに改善されます。

重複の扱い​

既定では、ナレッジライブラリに既に存在するページはライブラリを清潔に保つために スキップ されます。

  • Skip duplicates（既定） — 重複ページはスキップされ、理由 duplicate 付きで Skipped に表示されます。単一ページのインポートで重複した場合は、重複エラーで失敗します。
  • Allow duplicates — コピーが既に存在していてもすべてのページをインポートします。意図的にページの2つ目のスナップショットが欲しい場合に使います。
ページの置き換え

自動的な「置き換え」モードはまだありません。ページを更新するには、古いドキュメントを削除してからURLを再度インポートしてください。

セキュリティと安全性​

Webサイトインポートは既定で安全になるよう設計されています。悪用やSSRF（Server-Side Request Forgery）を防ぐため、aiFetchlyは以下を拒否します。

  • http(s) 以外のURL（file://、mailto:、tel:、javascript:、data: を含む）。
  • localhost、ループバック、プライベート、リンクローカル、内部ネットワークのアドレス。
  • クラウドのメタデータエンドポイント（例: 169.254.169.254）。
  • 認証情報を含むURL。
  • 上記のいずれかに解決されるリダイレクトや発見されたリンク。

クロールは開始URLのオリジンから外れることはありません。インポートしたページのコンテンツは厳密に ナレッジ として扱われ、取得のためだけに保存され、指示として実行されることはありません。

プライベートサイトや認証サイトは不可

認証が必要なページ、ログイン壁の背後にあるページ、内部ネットワークのページはサポートされていません。公開ページのみインポートしてください。

AI Chatからインポート​

AI Chat のアシスタントにWebページのインポートを依頼することもできます。アシスタントは knowledge_library_import_website ツールを使用し、何かを取得する前に確認を求めます。

例:

https://example.com/pricing をナレッジライブラリにインポートして、pricing とタグ付けして。
https://example.com/docs のドキュメントページをナレッジライブラリにインポートして。
https://example.com/docs から最大25ページクロールして、Webサイトのドキュメントとしてインポートして。

アシスタントはモード、URL、上限、タグ、重複ポリシーを確認したうえで、インポート数とスキップ数を要約します。

トラブルシューティング​

症状考えられる原因対処
ページが読み込まれる前に 「Import failed」AI/サブスクリプションが無効サブスクリプションでAIを有効にして再試行してください。
ページが URL_BLOCKED で Skipped に表示URLがプライベート/localhost/非http(s)公開された http(s) URLを使用してください。
ページが EMPTY_CONTENT読み取れるテキストが少ない（ログイン/エラー、JSのみ）別のURLを試すか、ブラウザでページを確認してください。
ページが SCRAPE_FAILEDサイトがスクレーパーをブロックしたかタイムアウト後で再試行するか、ページ数を減らしてください。
ページが duplicateページが既にライブラリに存在Allow duplicates を使うか、先に古いドキュメントを削除してください。
クロールが期待より少ないページ数でインポートされたMax pages / Max depth に達した、または同一生成元リンクが少ない上限を上げるか、サイトが目的のページへリンクしているか確認してください。
インポートしたページがAIコンテンツに使われないRAGコンテキストが無効、またはコンテンツが無関係AI Chat / Email WriterでRAGコンテキストを有効にし、ドキュメント状態が Completed か確認してください。
