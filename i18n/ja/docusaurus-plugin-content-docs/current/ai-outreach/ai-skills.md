# AIスキル

AIスキルは、チャット中にAIが呼び出せるツールを追加するモジュラー式の拡張機能です。ウェブスクレイピング、自動化、ファイルアクセス、シェルコマンドなどの専門的な機能を提供します。スキルが有効化されていると、AIはリクエストに応答する際にそれを使用するかどうかを自律的に判断できます。

## スキルとは？

スキルは、以下の要素を持つパッケージ化されたツールです：

- 一意の**名前**と**バージョン**。
- **ソース**: **Built-in**（aiFetchlyに同梱）または **User Installed**（ユーザーがインポート、またはプラグインに同梱）。
- **権限カテゴリ** — スキルが宣言する権限から派生します（[権限カテゴリ](#権限カテゴリ)を参照）。
- **有効/無効**の状態。

## AIスキルへのアクセス

1. 左側のナビゲーションメニューで **System Setting** をクリックします。
2. **Manage Skills**（または **AI Skills**）をクリックします。

ページには、インストール済みのすべてのスキルがテーブル形式で一覧表示されます。

## スキルテーブル

| 列 | 説明 |
|--------|-------------|
| **Name** | スキルの識別子。スキルがプラグイン由来の場合、横に _"via plugin: \{name\}"_ チップが表示されます。 |
| **Source** | **Built-in** または **User Installed** のバッジ。 |
| **Category** | スキルの権限カテゴリ（`pure`、`network`、`filesystem`、`automation`、または `shell`）。 |
| **Version** | スキルのバージョン番号。 |
| **Status** | **Enabled** または **Disabled**。 |
| **Actions** | 有効/無効の切り替えトグルとアンインストールボタン — **ユーザーインストール済みスキルにのみ表示されます**。 |

:::note 組み込みスキルは常にオンです

組み込みスキルには、有効/無効の切り替えトグルもアンインストールボタンも **表示されません**。これらはこのページから無効化・削除できません。

:::

## スキルのインポート

スキルは `.zip` パッケージとしてインポートします。

1. **Import**（右上のアップロードアイコン）をクリックします。
2. スキルの `.zip` ファイルを選択します。
3. aiFetchlyがパッケージ（マニフェスト、権限、エントリファイル）を検証し、インストールを実行します。

:::tip インポートのヒント

- Importボタンでサポートされているのは `.zip` ファイルのみです。
- パッケージには有効な `manifest.json` が含まれている必要があります（[スキルパッケージの形式](#スキルパッケージの形式)を参照）。
- プラグインに同梱されたスキルはインポート不要です — プラグインのインストール時に自動的に表示されます。

:::

スキルは以下の経路で自動的に追加されることもあります：

- **プラグイン** — プラグインが1つ以上のスキルを同梱しています。それらはここに _"via plugin"_ チップとともに表示されます。**[Plugin Manager](./plugin-manager)** からインストール・削除を行います。
- **ローカルスキルフォルダ**（上級者向け） — `~/.aifetchly/skills/<name>/` に配置されたスキルは自動的に検出されます。

## 有効化・無効化・アンインストール

**ユーザーインストール済み**スキルに対して以下の操作が可能です：

- **有効化 / 無効化** — Actions列のチェック（有効）/ クロス（無効）のトグルを使用します。
- **アンインストール** — ゴミ箱アイコンをクリックし、確認します。アンインストールは元に戻せません。再びそのスキルを使用するには、`.zip` を再インポートしてください。

組み込みスキルにはActionsコントロールはありません — 常に有効な状態です。

## チャット内でのスキルの動作

スキルが有効化されると、AIは関連場面でそのスキルを呼び出すことを選択できます。ユーザーがスキルを名前で呼び出す必要はありません（ただし、「*このURLでウェブスクレイパーを使って*」のように明示的に指定することは可能です）。

### スキルカテゴリ

各スキルは **権限カテゴリ** に属し、AIがそのスキルを呼び出した際の承認方法が決まります。カテゴリは、スキルがマニフェストで最初に宣言した `permission` になり、何も宣言されていない場合は `pure` になります：

| カテゴリ | スキルができること |
|--------|----------------------|
| `pure` | 汎用ユーティリティ — テキスト処理、計算、フォーマット変換。特別なアクセス権は不要です。 |
| `network` | 外向きのネットワーク/HTTPアクセス（ページの取得、APIの呼び出し）。 |
| `filesystem` | ローカルファイルの読み書き。 |
| `automation` | ブラウザ自動化、スクレイピング、ソーシャル投稿、その他これらに類するスクリプト化された操作。 |
| `shell` | システムのシェルコマンドを実行。（組み込みの `shell_execute` のみ — インポート不可）。 |

カテゴリはテーブル上で生の小文字（例: `network`、`automation`）で表示されます。

### 承認プロンプト

AIがスキルを呼び出す際、aiFetchlyは実行前に承認を求める場合があります。プロンプトが表示されるかどうかは、スキルのカテゴリ **と** 現在のチャットのツール承認モードの両方によって決まります：

| カテゴリ | 承認の動作 |
|--------|-------------------|
| `pure` | 常に自動承認 — プロンプトは表示されません。 |
| `shell` | **コマンドごとに毎回プロンプトを表示します。** 自動承認されることはありません（後述）。 |
| `network` / `filesystem` / `automation` | デフォルトの _"ask for approval"_ モードではプロンプトが表示されます。_"approve for me"_ または _"full access"_ モードでは自動承認されます。 |

プロンプトが表示された場合、3つのアクションを持つ承認カードが表示されます：

- **Allow Once** — 今回の呼び出しのみ実行を許可します。
- **Always Allow** — この決定を記憶し、今後このスキルの呼び出しではプロンプトを表示しません。
- **Deny** — 今回の呼び出しをブロックします。

**shell** スキルの場合、カードのタイトルは **"Shell Command Execution"** となり、コマンドのプレビュー（コマンド、作業ディレクトリ、シェル、タイムアウト）が表示されます。また、3つ目のボタンは "Always Allow" ではなく **"Always Allow (This Session)"** と表示されます。

:::warning Shellの承認は実質的に1回限りです

`shell` スキルの場合、"Always Allow" は後続のコマンドには **適用されません**。各シェルコマンドは毎回再度プロンプトを表示します — シェルコマンドはマシン上で任意の操作を実行できるため、これは意図的な安全対策です。"Always Allow" を完全に永続的に記憶するのは、shell以外のカテゴリのみです。

:::

## スキルパッケージの形式

スキルの `.zip` には `manifest.json` が含まれている必要があります。最小限のマニフェストは以下のようになります：

```json
{
  "name": "my-custom-skill",
  "version": "1.0.0",
  "description": "What this skill does, shown to the AI.",
  "runtime": "javascript",
  "entry": "index.js",
  "parameters": {
    "type": "object",
    "properties": {
      "url": { "type": "string" }
    },
    "required": ["url"]
  },
  "permissions": ["network"]
}
```

### 必須のマニフェストフィールド

| フィールド | 説明 |
|-------|-------------|
| `name` | 一意のスキル識別子。 |
| `version` | バージョン文字列（例: `1.0.0`）。 |
| `description` | 短い説明 — AIはこれを読んでスキルを使用するタイミングを判断します。 |
| `runtime` | `javascript` または `python`。 |
| `entry` | パッケージ内のエントリファイル（例: `index.js` または `main.py`）。 |
| `parameters` | スキルの入力パラメータを記述するJSON Schemaオブジェクト。 |

### オプションのマニフェストフィールド

| フィールド | 説明 |
|-------|-------------|
| `permissions` | 権限文字列の配列。**有効な値は `network`、`filesystem`、`automation` のみです。** 最初のエントリがスキルのカテゴリを決定します（[スキルカテゴリ](#スキルカテゴリ)を参照）。不明な値はインポート時に拒否されます。 |

:::danger 権限は厳格に検証されます

受け付けられるのは `network`、`filesystem`、`automation` のみです。`web-search`、`data-access`、`shell` などの値は拒否され、スキルはインポートされません。独立した `category` フィールドは存在しません — カテゴリは最初の `permissions` エントリから派生します（指定がない場合は `pure`）。

:::

### パッケージング

1. パッケージのルートに有効な `manifest.json` を配置します。
2. `entry` が参照するランタイム/エントリファイルを追加します。
3. ラップフォルダではなく、**内容物**をzip化します。
4. ファイル名を `skill-name.zip` にします。

## トラブルシューティング

### インポートに失敗する

**考えられる原因:** 無効なzip、`manifest.json` の欠落や形式不正、無効な `permissions` 値、または必須フィールド（`runtime`、`entry`、`parameters`）の欠落。

**解決方法:**
1. zipの整合性を確認します。
2. `manifest.json` がすべての必須フィールドを有効な値で持っているか確認します。
3. `permissions` が `network`、`filesystem`、`automation` のみを使用していることを確認します。
4. `runtime` が `javascript` または `python` であり、`entry` が実在するファイルを指していることを確認します。

### スキルがチャットに表示されない

**考えられる原因:** スキルが無効、または（プラグインスキルの場合）そのプラグインが無効になっている。

**解決方法:**
1. テーブルでスキルのステータスを確認し、有効化します。
2. プラグインスキルの場合は **[Plugin Manager](./plugin-manager)** を確認します — 元のプラグインが有効になっている必要があります。

### AIが何度も承認を求めてくる

- **shell** スキルを使用しています。Shellの承認は設計上、1回限りです。
- その他のカテゴリでは、チャットのツール承認モードを _"approve for me"_ に切り替えることでプロンプトを減らせます（注意: これによりshell以外のスキルが自動承認されます）。

### 組み込みスキルに切り替えトグルがない

これは意図的な仕様です。組み込みスキルは常に有効であり、このページから無効化・アンインストールすることはできません。
