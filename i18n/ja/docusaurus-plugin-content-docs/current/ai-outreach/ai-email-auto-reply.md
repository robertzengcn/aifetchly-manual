# AIメール自動返信

AIメール自動返信は、アウトリーチのループを閉じます。aiFetchlyがメールボックスに接続して受信メッセージを取得し、AIで読み取り、[ナレッジライブラリ](./knowledge-library)に基づいた返信を下書きし、各返信を送信する前に承認できます。設定すると、aiFetchlyは厳格で安全性を優先した制限内で、ルールに一致するメッセージへの自動返信も行え、すべての判断は確認できる監査ログに記録されます。

## 仕組み

この機能は次のフローに従います：

```text
メールボックスを接続
  -> 受信メッセージを同期
  -> AIが各メッセージを読み取り、分類し、要約
  -> ナレッジライブラリに基づき、所有者の文体で返信を下書き
  -> 下書きを確認して承認（必須）
  -> 送信用メールボックスから返信を送信
  -> すべてがAI自動返信監査ログに記録される
```

送信は決して静かに行われません。下書き、承認、送信、スキップ、ブロック、失敗はすべて監査ログに記録され、AIが何を、なぜ行ったのかを常に確認できます。

:::info 各リリースの内容

最初のリリースは**支援型返信**です。AIが下書きを作成しますが、送信には常に明確な承認（またはAIチャットでの承認済み確認）が必要です。ルールに基づく**自動返信**（設定したルールに一致するメッセージへの自動送信）は後続の機能であり、有効にするまで無効のままです。

:::

## 前提条件

AIメール自動返信を使用する前に、以下を確認してください：

1. **アカウントでAIが有効になっている**こと。AIサービスの設定は[AIプロバイダー設定](../settings/ai-provider)を参照してください。
2. **送信（SMTP）が設定されたメールサービス**があること。返信は既存の送信メールサービスを通じて送信されます。
3. **（推奨） [ナレッジライブラリ](./knowledge-library)に**自社の製品、価格、プロセスに関するドキュメントがあること。AIは自社の資料を検索できる場合、事実に基づいたより良い返信を下書きできます。
4. 受信元メールボックスへの**IMAP（推奨）またはPOP3アクセス**。ほとんどのプロバイダーはIMAPをサポートしています。POP3を提供するプロバイダーもあります。

## メールボックスの接続

受信設定は、SMTP送信設定と同じ場所、メールサービスの設定にあります。

### ステップ1：メールサービスを開く

1. 左のナビゲーションで**Email Marketing**に移動します。
2. 送信に使用するメールサービス（または**Email Services**リスト）を開きます。
3. **Receive Settings**（受信設定）セクションを見つけます。

### ステップ2：受信設定を構成する

| 設定 | 説明 |
|---------|-------------|
| **受信プロトコル** | `IMAP`（推奨）または`POP3`。IMAPはフォルダーと既読/未読状態をサポートします。POP3はIMAPのないプロバイダー向けです。 |
| **IMAP/POP3ホスト** | 受信メールサーバーのアドレス（例：`imap.gmail.com`）。 |
| **IMAP/POP3ポート** | 受信サーバーのポート。プロバイダーがSSL/TLS用に公開しているポートを使用してください。 |
| **SSL/TLS** | 受信サーバーへの暗号化接続を有効にします。 |
| **受信ユーザー名** | 通常は完全なメールアドレスです。 |
| **受信パスワード** | メールボックスのパスワードまたはアプリパスワードです。安全に保存され、保存後に表示されることはありません。 |
| **監視するフォルダー** | デフォルトは`INBOX`です。 |
| **受信の有効化** | 同期準備ができたら受信をオンにします。 |

:::tip アプリパスワードを使用する

多くのプロバイダーは、IMAPに通常のログインパスワードではなく**アプリパスワード**を必要とします（例：Gmailのアプリ固有パスワード）。接続に失敗する場合は、プロバイダーのドキュメントを確認してください。

:::

### ステップ3：接続をテストする

受信を有効にする前に、**接続テスト**を使用してください。SMTP送信と受信は**別々に**テストされるため、送信の問題と受信の問題を切り分けられます。テストに失敗した場合は設定を修正して再テストしてください。

認証情報は保存後に表示されることはなく、設定ページもAIツールもパスワードを公開しません。

## 受信メッセージの同期

受信が有効になると、メッセージを取得します：

1. 受信が有効なメールサービスを開きます。
2. **Sync**（または**Fetch Unread**）をクリックします。
3. aiFetchlyがメールボックスに接続し、限定されたバッチの未読メッセージをダウンロードしてローカルに保存します。

受信設定で同期の動作も制御できます。たとえば**未読のみ**、**同期ごとの最大メッセージ数**、**同期のルックバック期間**、**処理後に既読にする**などです。

### メッセージリスト

同期されたメッセージは、次の情報を含むリストに表示されます：

- メールボックスアカウント / メールサービス
- 送信者
- 件名
- 受信時刻
- 既読/未読状態
- AI分類
- 返信ステータス
- 最終アクション

フィルターを使って重要なものに集中できます：**未読**、**返信が必要**、**下書き作成済み**、**送信済み**、**スキップ済み**、**ブロック済み**、**人間による確認**。

:::info デフォルトのプライバシー

メッセージ本文は表示前にサニタイズされます。リモート画像（トラッキングピクセル）はデフォルトで無効になり、HTMLはクリーンアップされ、スクリプトは実行されません。aiFetchlyはメッセージをローカルのマシンに保存します。

:::

## AI返信の下書き

受信メッセージを開くと、サニタイズされた本文、送信者と返信先アドレス、AI要約、推奨アクションを確認できます。

メッセージ詳細ビューには、**Generate draft**（下書きを作成）、**Regenerate draft**（下書きを再生成）、**Edit draft**（下書きを編集）、**Send reply**（返信を送信）、**Mark processed**（処理済みとしてマーク）、**Skip**（スキップ）があります。

### 下書きの作成

**Generate draft**をクリックします（またはAIチャットでAIに依頼します）。下書きの作成では：

1. メッセージの件名、本文、送信者、目標から検索クエリを構築します。
2. 関連する事実を[ナレッジライブラリ](./knowledge-library)で検索します（この下書きで無効にしない限り）。
3. それらの事実に基づき、**設定された所有者の文体で**返信を作成します。
4. 下書きを保存し、使用したソースを監査ログに記録します。

:::note ナレッジライブラリによる裏付け

AIはナレッジライブラリを使用して、正確でビジネス固有の事実に基づいて回答します。関連情報が見つからない場合、下書きは引き続き生成されますが、監査メタデータにはナレッジライブラリのサポート**なし**で作成されたことが明確にマークされます。この注記がメール本文に表示されることはありません。

:::

### 所有者の文体

返信はAIシステムではなく、実際のメールボックス所有者が書いたように見えるよう作成されます。メールサービスの**返信アイデンティティプロファイル**を構成します：

- 所有者の表示名
- 役割 / 会社の文脈
- 好みのトーン
- 署名
- 文体メモとよく使う表現
- 決して言わないこと
- 返信が自動化されていることを開示するかどうか（デフォルトはオフ）

開示を設定しない限り、AIは自身がAI、モデル、ボット、自動システムであることを言及しません。また、返信内で内部プロンプト、取得したドキュメント、信頼度スコアを明かすことはありません。

### 確認と編集

下書きは**送信前に必ず表示されます**。下書きを編集、再生成、またはトーンと目標を調整します。編集すると新しいリビジョンが作成され、以前に付与した承認は無効になるため、送信前に再度承認する必要があります。

## 返信の承認と送信

返信の送信には、最初のリリースでは**明確な承認が必要**です。静かな自動送信はありません。

1. 下書きビューで、宛先、送信元、件名、本文を確認します。
2. **Send**をクリックします（またはAIチャットで`send_email_reply`の確認を承認します）。
3. 返信は、構成済みの送信メールサービスを通じて、適切な返信ヘッダー（`In-Reply-To`、`References`）付きで送信され、会話が同じスレッドに維持されます。

送信後、メッセージと下書きは**Sent**（送信済み）になり、結果が監査ログに記録されます。

### 配信状態

| 状態 | 意味 |
|-------|-------------|
| **Sent**（送信済み） | プロバイダーが返信を受け入れました。 |
| **Send failed**（送信失敗） | プロバイダーが返信を拒否しました。エラーが記録され、送信済みとしてマークされることはありません。 |
| **Delivery unknown; verify mailbox**（配信不明。メールボックスを確認） | 送信後の結果が不明確です（例：タイムアウト）。返信は**自動的には再送されません**。メールボックスを確認し、手動で調整してください。 |

送信権限は、承認した下書きの正確なリビジョンに紐付いています。承認後の編集で無効になり、ブロック済みまたは失敗した下書きが送信されることはありません。

## AIチャットでAIメール自動返信を使用する

AIアシスタントは、組み込みツールのシーケンスとしてメールボックスを操作できます：

```text
list_email_inboxes        -> どのメールボックスがあるかを確認（秘密情報は公開しない）
fetch_unread_emails       -> 未読メッセージのバッチを取得
get_email_message         -> 1件のメッセージを詳しく読む
knowledge_library_search  -> ナレッジライブラリで関連する事実を検索
create_email_reply_draft  -> 返信を下書き（送信はしない）
send_email_reply          -> 送信。確認が必要
mark_email_processed      -> メッセージをスキップまたはブロックとしてマーク
```

チャットには各ステップが表示されます：メールボックスのメタデータを読む、メッセージ本文を読む、ナレッジライブラリを検索する、下書きを作成する、確認を待つ、送信する、またはセキュリティポリシーがブロックしたためメッセージをスキップする。

## AI自動返信監査ログ

**AI Auto Replies**（Email Marketing配下のAI自動返信）を開くと、AIが処理したすべてを確認できます：

- 受信メッセージの件名と送信者
- メールサービス / メールボックス
- AI分類
- **決定ステータス**と理由
- ナレッジライブラリの検索クエリとソース数
- 下書きプレビューと送信済み返信プレビュー
- 送信時刻 / 決定時刻
- 承認が必要だったかどうか
- 送信失敗時のエラーメッセージ

### 決定ステータス

| ステータス | 意味 |
|--------|-------------|
| `draft_created` | 下書きが生成されました。 |
| `approval_required` | 下書きが承認待ちです。 |
| `auto_sent` | メッセージがルールに一致し、自動返信されました。 |
| `blocked` | セキュリティポリシーが返信を止めました。 |
| `skipped` | メッセージが返信不要としてマークされました。 |
| `failed` | 下書きまたは送信が失敗しました。 |
| `needs_human_review` | AIが安全に判断できず、確認が必要とフラグを立てました。 |

ステータス、日付範囲、メールサービス、分類、送信者でフィルタリングするか、件名、送信者、決定理由で検索できます。詳細ビューには、元のメッセージ、生成および送信済みのプレビュー、使用した知識検索、決定理由、承認ステータスが表示されます。

## 自動返信ルール（自動化）

ルールに基づく自動返信はデフォルトで無効です。メールボックスで有効にすると、以下を構成します：

- 自動返信できる**許可された分類**（例：`interested`）
- 分類が満たす必要がある**信頼度しきい値**
- **ブロックされた送信者 / ドメインパターン**
- **1日の送信制限**と**スレッドごとの返信制限**
- **静かな時間帯**と、しきい値を下回る場合に承認が必要かどうか
- **自動化されたメッセージには自動返信しない**

自動送信は、すべての条件を満たした場合にのみ発生します。それ以外の場合、メッセージは下書きされ（または下書きとして作成され）、`blocked`、`skipped`、`needs_human_review`としてマークされます。こっそり送信されることはありません。

### ループ防止

セキュリティポリシーは、次のメッセージには自動返信しません：

- 自動化されている（`Auto-Submitted`が設定）、一括送信、またはメーリングリスト由来
- バウンスまたは配信失敗の通知
- `no-reply`、`noreply`、`do-not-reply`、`mailer-daemon`、`postmaster`から届いた
- aiFetchlyの自動返信をすでに受けたスレッドの繰り返し
- 設定されたクールダウン期間内の送信者から届いた

### クリーンなコンテンツのガードレール

AIが生成した返信には以下を決して含めません：

- 認証情報、トークン、内部ログ
- 未検証の価格、法的主張、約束
- AIが書いた、または取得ツールで組み立てられたという言及
- ナレッジライブラリのソース名、信頼度スコア、内部ラベル
- 添付ファイル（このリリースでは未対応）

返信は設定したアイデンティティプロファイルに応じて**「私」**や**「私たち」**で書かれ、返信に機密情報（返金、法的助言、アカウント詳細）が必要になる場合は人間による確認にエスカレーションされます。

## トラブルシューティング

### 接続テストが失敗する

1. ホストとポートがプロバイダーのIMAP/POP3ドキュメントと一致しているか確認します。
2. プロバイダーが必要とする場合は**SSL/TLSを有効**にしてみます。
3. プロバイダーが必要とする場合は**アプリパスワード**を使用します。
4. 送信と受信を別々にテストして問題を切り分けます。

### 同期後、メッセージが表示されない

1. メールボックスが**有効**で、正しいフォルダー（通常は`INBOX`）が監視されているか確認します。
2. 同期はデフォルトで**未読**メッセージの限定バッチを取得します。同期設定を確認してください。
3. 繰り返し同期しても保存済みメッセージが重複することはありません。プロバイダーのメッセージIDによる重複はその場で更新されます。

### 下書きが失敗する、またはAIが利用できない

1. アカウントで**AIが有効**で、AIプロバイダーが設定されていることを確認してください（[AIプロバイダー設定](../settings/ai-provider)）。
2. ナレッジライブラリに関連ドキュメントがない場合でも、下書きは警告付きで作成されます。
3. 生成を再試行できます。失敗した下書きはメッセージの状態を変更しません。

### 送信が「Delivery unknown」で停止している

返信が受信者に届いたかどうかは不明です。自動的に再送されることはありません。送信済みフォルダーを確認し、監査または送信試行の詳細ビューから手動で状態を調整してください。

## セキュリティとプライバシーに関する注意

- メールボックスのパスワードは保存時に暗号化され、保存後に表示されることも、AIツールに渡されることもありません。
- 受信メールは**信頼できない顧客コンテンツ**として扱われます。メール内の指示が、セキュリティポリシー、承認要件、送信ポリシーを上書きすることは決してありません。
- すべての読み取り、知識検索、下書き判断、承認、ブロック、スキップ、失敗、送信が監査ログに記録されます。
- メッセージ本文は表示前にサニタイズされ、監査レコードにはプレビューと理由のみが保存されます。完全な本文、認証情報、生のプロンプトは保存されません。

**ループを閉じる準備はできましたか？** メールボックスを接続し、受信を有効にし、未読メッセージを同期して、AIに最初の返信の下書きを任せましょう。すべての送信はあなたの管理下にあります。
