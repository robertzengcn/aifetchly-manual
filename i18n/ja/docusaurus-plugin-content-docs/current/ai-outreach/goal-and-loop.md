# ゴールとループのコマンド

**`/goal`** と **`/loop`** のスラッシュコマンドを使うと、AI Chat V2 アシスタントに持続的な目標を与え、ターンごとに指示を出す代わりに、制限付きで検証可能なステップでその目標に向かって作業を続けさせることができます。

`/goal` は「完了」の意味（明示的で検証可能な受け入れ基準を含む）を捉えます。そして `/loop` がその目標に向けて制限付きの自律イテレーションを実行し、新しい証拠を収集して各基準を検証した上でないと、目標を完了とは見なしません。

:::info AI Chat V2 のみ

`/goal` と `/loop` は **[AI Chat V2](./ai-chat-v2)** のコンポーザーで利用できる組み込みのスラッシュコマンドです。AI が有効な aiFetchly のアクティブなサブスクリプションが必要で、AI Chat V2 の既存の [プランモード](./ai-chat-v2)、ツール承認、ワークスペース安全性の各境界を再利用します。

:::

## 2 つのコマンドの関係

| コマンド | すること | 必要条件 |
|---|---|---|
| `/goal <objective>` | 会話のアクティブな目標を作成または置換し、プランモードに入ります。 | 空でない目標。 |
| `/loop <maxIterations>` | アクティブな目標に向けて、その回数までの自律イテレーションを実行します。 | `/goal` で既に設定されたアクティブな目標。 |

典型的な流れ:

```text
/goal Build a Facebook campaign scraper and verify it works
(プランモードで計画と受け入れ基準を承認する)
/loop 5
```

## `/goal` — 持続的な目標を設定する

### 構文

```text
/goal <objective>
```

例:

```text
/goal Build a Facebook campaign scraper and verify it works
```

### 何が起きるか

1. その目標が現在の会話の**アクティブな目標**になります。
2. AI Chat が**プランモード**に入ります。目標が曖昧な場合、アシスタントは明確化の質問をします。
3. アシスタントは 1 つ以上の**受け入れ基準**を含む計画を提案します — 「完了」の意味を定義する、具体的で検証可能な条件です。
4. 通常のプランモードの承認フローで計画を承認（または拒否・変更要求）します。
5. 目標は、**完了**・**ブロック**・**キャンセル**されるまで会話でアクティブなままです。

再度 `/goal` を実行すると、現在のアクティブな目標が置き換えられます。

### 受け入れ基準と検証

各受け入れ基準は自動的に検証されます — アシスタントが「できた」と言っただけでは目標は完了しません。各基準には検証方法があります:

| 方法 | 基準の検証方法 |
|---|---|
| **command** | コマンドが正常に終了し、任意で期待する終了コードや出力パターンに一致します。 |
| **file** | 期待するファイルやプロジェクト状態が存在します（例: ファイルが存在する・変更された）。 |
| **manual** | ループが一時停止し、確認を求めます。 |
| **llm** | 決定論的にチェックできない基準について、独立した検証器が収集した証拠を評価します。 |

基準は**必須**または任意に指定できます。目標が完了と見なされるのは、**すべての必須基準**が新しい証拠で合格した場合のみです。

:::tip 検証可能な目標を書く

`/goal` は「完了」をアプリが検証できるものとすると最も効果的です。「スクレーパーを構築し、動作を検証する」のような目標（「テストコマンドが終了コード 0 で終了する」といった基準付き）は、「良いスクレーパーにする」のような主観的なものよりはるかに信頼できます。

:::

## `/loop` — 制限付きイテレーションを実行する

### 構文

```text
/loop <maxIterations>
```

`<maxIterations>` は **1 から 10** の整数です。明示的に指定してください — 省略したり範囲外の値を渡したりすると、`/loop` は有効な回数を求めます。また `/loop` は**アクティブな目標を必要とします**。設定していない場合は、まず `/goal` を実行するよう促されます。

例:

```text
/loop 5
```

### 各イテレーションがすること

各イテレーションは同じ 観察 → 行動 → 検証 のサイクルを実行します:

```text
現在の状態を観察
  → アシスタントが制限付きの次のアクションを提案
  → 承認されたツールがそれを実行
  → システムが新しい証拠を収集
  → まず決定論的なチェックを実行
  → 独立した検証器が残りの基準を評価
  → ループは継続・完了・ブロック・または入力を要求
```

ループの実行中は進行状況が会話に表示されます — イテレーション数、収集された証拠の要約、基準ごとの検証結果です。

### ループが停止する条件

`/loop` は永遠に実行されることはありません。以下のいずれかが成立した時点で停止します:

- **Stop** を押した。
- 最大イテレーション数に達した。
- 実行あたりの時間制限に達した。
- 目標が**完了**した — すべての必須基準が新しい証拠で合格した。
- ツールが承認を必要とする、またはプランモードが承認を必要とする。
- アシスタントが質問する必要がある。
- 同じ失敗が十分な回数繰り返され、目標が**ブロック**になった。
- 検証器が `blocked` または `needs_user_input` を返した。
- 回復不能なエラーが発生した。

### 完了がどのように決まるか

作業を行うアシスタントは、自らの宣言で**自分の目標を完了にすることはできません**。完了には**新しく基準固有の証拠**が必要です — 例えば、最新のコード変更の*後*に合格したテストであり、その前の古い結果ではありません。

決定論的なチェック（コマンド、ファイル状態）が先に実行されます。独立した LLM 検証器は決定論的にチェックできない基準にのみ使われ、構造化された評定（`satisfied`、`not_satisfied`、`blocked`、`needs_user_input`）を返します — これらは特定の証拠に紐付き、自由文の「done」ではありません。

## ゴールとループのステータス

目標は以下の状態を遷移します:

| ステータス | 意味 |
|---|---|
| **draft** | 目標はプランモードで定義中です。 |
| **active** | 承認済みで、実行または継続を待機中です。 |
| **running** | `/loop` がイテレーションを実行中です。 |
| **complete** | すべての必須基準が新しい証拠で合格しました。 |
| **blocked** | 繰り返しの失敗や未解決のブロッカー — 注意が必要です。 |
| **needs_user_input** | ループが質問や確認のために一時停止しました。 |
| **failed** | 回復不能なエラーが実行を終了させました。 |
| **cancelled** | 停止しました。 |

## 上限と安全性

| 上限 | 値 |
|---|---|
| イテレーション数（`/loop`） | 1–10（明示的に指定） |
| 実行あたりの時間上限 | 10 分（既定値） |
| **ブロック**までの同一失敗回数 | 3 |
| 会話あたりのアクティブな目標 | 1 つ（新しい目標を設定すると古いものは置換されます） |

常に適用される安全性の保証:

- ループは常に**制限付き**です — 決して無限ではありません。
- 常に**キャンセル可能**です（Stop を押す）。
- AI の有効化、ツール承認モード、プランモード、ワークスペースやファイルの安全性の境界はすべて、ループ中も引き続き適用されます。
- 破壊的なアクション、新規依存、認証の変更、その他大きな影響のある副作用は、ループ中であっても通常の承認境界を引き続き必要とします。
- 検証器に示される証拠やログは、対象に絞り、サイズを制限し、シークレットをマスキングし、信頼できないデータとして扱います — 決して指示としては扱いません。

## ヒント

### ✅

- **ループの前に目標を設定する** — `/loop` には常にアクティブな `/goal` が必要です。
- **目標を検証可能にする** — 主観的なものより、アプリがチェックできる基準（コマンド、ファイル）を優先します。
- **小さな回数で始める**（`/loop 3`）— 多くをコミットする前に進行状況を確認します。
- **ファイルを変更する、アウトリーチを送る、多くのツール呼び出しを実行する目標ではプランモードをオンにしておく。**

### ❌

- **無制限の自律性を期待しない** — `/loop` には常に 1〜10 の明示的な回数が必要です。
- **「done」の一言を信用しない** — 完了は証拠に基づきます。必須基準が合格していなければ、目標は完了していません。

## トラブルシューティング

| 症状 | おそらく原因 | 対処 |
|---|---|---|
| *"Set a goal first with /goal"* | この会話にアクティブな目標がない | まず `/goal <objective>` を実行し、計画を承認してください。 |
| *"Please provide an iteration count"* | `/loop` が数値なしで呼ばれた | 回数を指定してください（例: `/loop 5`）。 |
| *"Iteration count must be between 1 and 10"* | 回数が欠落・ゼロ・10 を超えている | 1 から 10 の整数を使用してください。 |
| 目標が**ブロック**された | 同じ失敗が繰り返された（既定で 3 回） | 会話内の失敗理由を読み、根本原因に対処してから、再度 `/loop` を実行するか目標を調整してください。 |
| 目標が **needs_user_input** のまま | ループが回答や承認を待っている | 質問に答えるか、保留中のアクションを承認してください。 |
| ループが早く停止した | 承認・計画承認・質問が必要だった | 保留中の項目を承認し、続行するために再度 `/loop` を実行してください。 |
