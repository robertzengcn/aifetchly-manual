# ナレッジライブラリ

ナレッジライブラリは、aiFetchlyのインテリジェントなドキュメント管理システムです。ドキュメント（PDF、Wordファイル、HTMLなど）をアップロードしてナレッジベースを構築し、AIが生成するコンテンツを強化して、アウトリーチがコンテキストに沿った正確でパーソナライズされたものになります。

:::info サブスクリプションが必要です

ナレッジライブラリ（無料のローカル埋め込みモデルを含む）には、aiFetchlyのサブスクリプションが必要です。アカウントでAIが有効になっていない場合、ページには**サブスクリプションが必要**というプロンプトが表示されます。

:::

## RAGとは？

**RAG**（Retrieval-Augmented Generation）は以下の仕組みを持つ技術です：

1. **取り込み**：ドキュメントを読み込み、小さなチャンクに分割します
2. **ベクトル埋め込みの作成**：コンテンツの意味を理解するベクトル埋め込みを生成します
3. **関連情報の検索**：コンテンツ生成時に必要な情報を検索します
4. **AI応答の強化**：あなた固有のナレッジでAIの回答を強化します

:::info RAGが重要な理由

従来のAIシステムは一般的なコンテンツを生成します。RAGにより、aiFetchlyのAIはあなたのドキュメントを参照し、パーソナライズされた、コンテキストに基づいたメールやマーケティングコンテンツを作成します。

:::

## 対応ファイル形式

| 形式 | 拡張子 | 用途 |
|--------|------------|----------|
| **PDF** | `.pdf` | パンフレット、ホワイトペーパー、ドキュメント |
| **Microsoft Word** | `.doc`, `.docx` | 提案書、契約書、製品情報 |
| **テキスト** | `.txt` | シンプルなテキストファイル、メモ |
| **Markdown** | `.md` | 技術ドキュメント、READMEファイル |
| **HTML** | `.html`, `.htm` | Webコンテンツ、記事 |

## ドキュメントのアップロード

### ステップ1：ナレッジライブラリを開く

1. 左のナビゲーションメニューで**Knowledge**をクリックします
2. ナレッジライブラリのインターフェースが表示されます

### ステップ2：ドキュメントのアップロード

**方法1：ドラッグ＆ドロップ**

1. コンピューターからファイルをドラッグします
2. アップロードエリアにドロップします
3. ファイルが追加されていることを視覚的に確認できます

**方法2：ファイルブラウザ**

1. **Upload**ボタン（またはアップロードエリア）をクリックします
2. ファイルブラウザでファイルを探します
3. 1つまたは複数のドキュメントを選択します
4. **Open**をクリックしてアップロードします

### ステップ3：処理

アップロード後、ドキュメントは自動的に処理されます：

1. **保存**：ファイルがデータベースに保存されます
2. **チャンキング**：ドキュメントが小さなセグメントに分割されます
3. **埋め込み**：意味検索のためのベクトル埋め込みが作成されます
4. **ステータス更新**：処理ステータスが**待機中** → **処理中** → **完了**に変化します

:::tip 処理時間

処理時間はファイルサイズによって異なります：
- 小さいファイル（1MB未満）：10〜30秒
- 中程度のファイル（1〜5MB）：30〜60秒
- 大きいファイル（5〜10MB）：1〜3分

:::

## Webサイトからコンテンツをインポート

ファイルをアップロードするだけでなく、**公開WebページをURLから直接インポート**できます。aiFetchlyが各ページを取得してMarkdownに変換し、同じRAGパイプラインでインデックスするため、インポートしたページはすぐに検索できます。1ページ、URLのリスト、または同一生成元の範囲に限定したクロールから選べます。

完全なガイド、オプション、上限、セキュリティの詳細は [Webサイトをナレッジライブラリにインポート](./website-import) を参照してください。

## ドキュメントの管理

### ドキュメントリストビュー

ナレッジライブラリには、すべてのドキュメントが以下の情報とともに表示されます：

| 列 | 説明 |
|--------|-------------|
| **Name** | ドキュメントのファイル名 |
| **Title** | ドキュメントのタイトル（編集可能） |
| **Status** | 処理ステータス（待機中/処理中/完了/エラー） |
| **Type** | ファイルタイプ（PDF、DOCXなど） |
| **Size** | ファイルサイズ |
| **Upload Date** | ドキュメントのアップロード日時 |
| **Actions** | 表示、ダウンロード、削除、再埋め込み |

### ドキュメントの操作

| 操作 | 説明 |
|--------|-------------|
| **View** | ドキュメントを開いて内容を表示 |
| **Download** | 元のファイルをコンピューターにダウンロード |
| **Delete** | ドキュメントをナレッジベースから削除 |
| **Re-embed** | 新しい埋め込みモデルでドキュメントを再処理 |
| **View Logs** | 失敗したドキュメントのエラー詳細を確認 |

### 検索とフィルター

- **名前で検索**：ファイル名でドキュメントを絞り込みます
- **ステータスで絞り込み**：完了、処理中、失敗したドキュメントのみ表示
- **タイプで絞り込み**：特定のファイルタイプのみ表示

### 一括操作

- **複数選択**：ドキュメントの横にあるチェックボックスをオンにします
- **一括削除**：複数のドキュメントを一度に削除します
- **選択をクリア**：すべてのドキュメントの選択を解除します

## 処理ステータスについて

| ステータス | 色 | 意味 | 対応 |
|--------|-------|---------|--------|
| **待機中** | グレー | 処理待ち | 自動処理を待ちます |
| **処理中** | ブルー | 埋め込み処理中 | 完了を待ちます |
| **完了** | グリーン | AI生成に使用可能 | ドキュメントが有効です |
| **エラー** | レッド | 処理失敗 | ログを確認し、再埋め込みを試みます |

## ドキュメントの再埋め込み

埋め込みモデルを変更した場合や、ドキュメントを再処理する必要がある場合：

1. リストからドキュメントを見つけます
2. **Re-embed**ボタンをクリックします
3. ドキュメントのステータスが**処理中**に変わります
4. 現在のモデルで新しい埋め込みが作成されます
5. 完了するとステータスが**完了**に更新されます

**再埋め込みのユースケース：**
- 設定で埋め込みモデルを変更した場合
- 以前の埋め込みが部分的に失敗した場合
- 更新されたチャンキングパラメータを使用したい場合

モデルの選択や変更方法については、下記の[埋め込みモデルの設定](#埋め込みモデルの設定)を参照してください。

## 埋め込みモデルの設定

埋め込みは、テキストをAIが意味的に検索するためのベクトルに変換します。**設定**から、aiFetchlyが使用する埋め込みモデルを選択できます。

### 埋め込み設定を開く

1. **ナレッジライブラリ**を開きます。
2. ヘッダーの**設定**をクリックします。

ダイアログには、利用可能なすべてのモデルを表示する**埋め込みモデル**ドロップダウン、**現在のモデル**、**モデルを更新**ボタンが表示されます。

### ローカルモデルとリモートモデル

ドロップダウンには2種類のモデルが表示されます：

| 種類 | 例 | メモ |
|------|---------|-------|
| **ローカル（無料）** | `Xenova/all-MiniLM-L6-v2 (free)` | お使いのデバイス上で完全に実行されます（384次元）。無料、プライベート、キャッシュされればオフラインでも動作します。 |
| **リモート** | サーバー提供のモデル | aiFetchlyのAIサーバー上で生成されます。プランに応じて無料または有料です。 |

無料モデル（ローカル・リモート問わず）は、ドロップダウンに緑色の**無料**チップで表示されます。リモートモデルのリストを読み込めない場合でも、ローカルモデルは常にリスト表示され、必ず利用可能な選択肢が存在します。

:::tip ローカルモデル = プライベート + 無料

ローカルモデルは、Transformers.jsを介してお使いのCPU上で実行されます。選択されている場合、ドキュメントのテキストは**リモートの埋め込みエンドポイントに送信されることはありません**。埋め込みはお使いのマシン上で完全に生成されます。プライバシー、コストゼロ、オフライン利用にはこれを選択してください。

:::

:::note 初回利用時にモデルをダウンロードします

ローカルモデルを初めて使用するとき、aiFetchlyは（Hugging Faceから）モデルの重みファイルをダウンロードし、ディスクにキャッシュします。そのため、最初のインデックス作成は遅くなります。2回目以降はキャッシュされたモデルを再利用するため高速です。

:::

モデルを選択して**モデルを更新**をクリックします。新しいモデルは**今後の**インデックス作成と再埋め込みに適用されます。既存のドキュメントは、再埋め込みを行うまで、当初埋め込みに使用されたモデルが保持されます。

### インデックス作成中の自動フォールバック

リモートモデルを使用していて、再試行後も埋め込みが失敗した場合（ネットワークやサーバーのエラーなど）、aiFetchlyは自動的に以下を行います：

1. 埋め込み空間が混在しないよう、そのドキュメントの部分的なベクトルをすべて破棄します。
2. ドキュメント全体を**ローカルの無料モデル**で再埋め込みします。
3. ドキュメントにローカルモデルを記録します。

次のように表示されます：*「リモート埋め込みが失敗しました。AiFetchlyは代わりにローカルの無料埋め込みモデルを使用しました。」*

ローカルモデルも失敗した場合、ドキュメントは**エラー**としてマークされ、次のように表示されます：*「リモート再試行とローカルフォールバック後も埋め込み生成に失敗しました。詳細はドキュメントのエラーログを確認してください。」*

:::warning クオータエラーはフォールバックしません

リモートの失敗が課金やクオータ制限によるものの場合、aiFetchlyは**黙って**フォールバックしません。プランを補充できるよう、*「リモート埋め込みのクオータまたは課金制限に達しました」*と表示されます。続行するには、ローカルモデルに切り替える（またはクオータの問題を解決してから再埋め込みする）必要があります。

:::

### 混在モデルのライブラリの検索

一部のドキュメントがリモートモデルで、他がローカルモデルで埋め込みされている場合、各ドキュメントは埋め込み時に使用されたモデルで検索されます。2つの埋め込み空間は互換性がありません。検索中にリモートエンドポイントが利用できない場合、その検索ではリモートインデックスのドキュメントはスキップされ、ローカルインデックスのドキュメントのみが結果を返します。

## トラブルシューティング

### ドキュメントのステータスが「エラー」の場合

**考えられる原因：**
- ファイルが破損している
- サポートされていないファイル形式
- ファイルサイズが大きすぎる
- エンコーディングの問題

**解決策：**
1. **View Logs**で具体的なエラーを確認します
2. ドキュメントの**再埋め込み**を試みます
3. 元のファイルを**再アップロード**します
4. ファイルを別の形式に**変換**します（例：DOC → PDF）

### 処理が遅い場合

**考えられる原因：**
- ファイルサイズが大きい
- システム負荷が高い
- ネットワーク遅延（リモート埋め込みの場合）
- ローカル埋め込みモデルを初めて使用（モデルの重みファイルを一度ダウンロードします）

**解決策：**
1. 処理が完了するまで待ちます
2. 大きなドキュメントを小さなファイルに分割します
3. 他のアプリケーションを閉じてリソースを解放します
4. ローカルモデルに切り替えたばかりの場合、初回実行時にモデルがダウンロード・キャッシュされます。2回目以降は高速です

### ドキュメントがAIコンテンツに使用されない場合

**考えられる原因：**
- ドキュメントの処理が完了していない
- ドキュメントの内容がクエリに関連していない
- RAGコンテキストが有効になっていない

**解決策：**
1. ドキュメントのステータスが**完了**であることを確認します
2. AIチャット/メールライターでRAGコンテキストが有効になっていることを確認します
3. より具体的な内容で検索してみます
4. 関連する追加ドキュメントをアップロードします

## ベストプラクティス

### 1. ドキュメントの選択

**以下のようなドキュメントをアップロードしてください：**
- 製品やサービスの詳細な説明
- 価値提案の説明
- ケーススタディや成功事例
- 業界固有の専門用語を含むもの
- 競合優位性を示すもの

**避けるべきもの：**
- 一般的または古い情報
- 関連性のないコンテンツ
- 非常に大きなファイル（10MB超）
- フォーマットが不適切なドキュメント

### 2. ドキュメントの整理

**命名規則：**
- 説明的な名前を使用：`Product_Brochure_2024.pdf`
- バージョン番号を含める：`Pricing_Guide_v2.docx`
- 日付を追加：`Case_Study_January_2024.pdf`

**カテゴリ分け：**
- 関連するドキュメントをグループ化する
- 一貫した命名パターンを使用する
- タグでドキュメントを簡単にフィルタリングする

### 3. コンテンツの品質

**最良の結果を得るために：**
- 適切にフォーマットされたドキュメントを使用する
- 構造化された見出しを含める
- 具体的な詳細と例を提供する
- 情報を最新に保つ
- 専門的な言葉遣いを使用する

### 4. 定期的なメンテナンス

**ナレッジベースを健全に保つ：**
- **定期的に見直す**：古いドキュメントを削除する
- **コンテンツを更新**：情報が変更されたら再アップロードする
- **ステータスを監視**：失敗した埋め込みがないか確認する
- **サイズを最適化**：可能な場合は大きなドキュメントを分割する

## AI機能との連携

ナレッジライブラリは以下の機能と連携します：

### AIメールライター

AI生成メールを作成する際：

1. メールライターで**RAGコンテキストを有効**にします
2. AIがナレッジライブラリから関連情報を検索します
3. 取得したコンテンツを使用してメールをパーソナライズします
4. 正確でコンテキストに基づいた情報を含むメールが生成されます

**例：**
- 製品カタログのPDFをアップロードする
- AIが特定の製品を参照するメールを生成する
- 各メールが受信者に関連する製品に言及する

### AIマーケティングアシスタント

AIアシスタントとチャットする際：

1. **RAGコンテキストを切り替える**（📖アイコン）
2. あなたのビジネス、製品、サービスについて質問します
3. AIがナレッジライブラリから回答を検索します
4. 回答はあなたのドキュメントに基づいています

**質問例：**
- 「主な製品機能は何ですか？」
- 「競合と比較して価格はどうですか？」
- 「返金ポリシーはどうなっていますか？」
- 「製品Xのマーケティングメールを作成して」

## 技術的な詳細

### RAGの仕組み

1. **ドキュメントの取り込み**：
   - ファイルがアップロードされ、データベースに保存されます
   - メタデータ（名前、タイプ、サイズ、日付）が記録されます

2. **テキストプロファイルインサイト**：
   - さまざまなファイル形式からテキストが抽出されます
   - 可能な限りフォーマットが保持されます

3. **チャンキング**：
   - ドキュメントが小さなセグメント（チャンク）に分割されます
   - 一般的なチャンクサイズ：500〜1000文字
   - チャンク間の重複によりコンテキストが維持されます

4. **埋め込みの作成**：
   - 各チャンクがベクトル埋め込みに変換されます
   - 埋め込みは意味的な意味を捉えます
   - 高速な検索のためにベクトルデータベースに保存されます

5. **意味検索**：
   - コンテンツ生成時に、AIが関連するチャンクを検索します
   - 類似度マッチングで最も関連性の高いコンテンツを見つけます
   - 取得したチャンクがコンテキストとして含まれます

6. **コンテンツ生成**：
   - AIが取得したコンテキストとプロンプトを使用します
   - パーソナライズされた正確なコンテンツを生成します
   - あなた固有のナレッジを参照します

### ストレージとパフォーマンス

- **ストレージ**：ドキュメントはローカルのSQLiteデータベースに保存されます
- **ベクトルデータベース**：高速な類似度検索用に最適化されています
- **パフォーマンス**：関連コンテンツの検索はミリ秒単位で行われます
- **スケーラビリティ**：数千のドキュメントを効率的に処理します

## セキュリティとプライバシー

### データストレージ

- **ローカルストレージ**：すべてのドキュメントはお使いのコンピューターにローカル保存されます
- **クラウドアップロードなし**：元のファイルはお使いのコンピューターに残ります
- **暗号化**：追加のセキュリティのためデータベースを暗号化できます

### プライバシーに関する考慮事項

- **あなたのナレッジ**：あなたのドキュメントにアクセスできるのはあなただけです
- **AI処理**：ローカル埋め込みモデルを使用する場合、テキストはデバイスから離れません。リモートモデルの場合、埋め込みはaiFetchlyのサーバー上で生成されます
- **トレーニングデータとして不使用**：あなたのドキュメントは公開AIモデルのトレーニングに使用されません

:::tip 機密情報について

ナレッジライブラリは以下の用途に最適です：
- 社内製品ドキュメント
- 機密性の高い価格情報
- 独自のビジネスプロセス
- クライアント固有の情報
