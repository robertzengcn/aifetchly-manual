# サブエージェント

サブエージェントは、再利用できる専門 AI エージェント定義です。特定の役割、システムプロンプト、許可ツール、モデル設定、実行制限を記述し、aiFetchly が目的に応じた AI 作業に利用できます。

プラグインは AI Skills や MCP サーバーと一緒にサブエージェントをインストールできます。自分の繰り返しワークフロー向けに手動サブエージェントを作成することもできます。

## サブエージェントを開く

1. 左側ナビゲーションで **設定** をクリックします。
2. **システム設定** を開きます。
3. **サブエージェントを管理** をクリックします。

ページには、コンパクトな表、検索とフィルター、詳細ダイアログ、**サブエージェントを追加** アクションがあります。

## サブエージェントのソース

| ソース | 説明 |
|---|---|
| **組み込み** | aiFetchly に同梱されているエージェント。読み取り専用です。 |
| **プラグイン** | プラグインがインストールしたエージェント。サブエージェントページでは読み取り専用ですが、有効化または無効化できます。 |
| **ワークスペース** | ワークスペースファイルから読み込まれたエージェント。変更するにはワークスペースのエージェントファイルを編集します。 |
| **手動** | aiFetchly 内で作成したエージェント。編集、有効化、無効化、削除ができます。 |

ソースフィルターで、すべてのサブエージェントまたは特定のソースだけを表示できます。

## 検索とフィルター

表には次の列があります。

| 列 | 説明 |
|---|---|
| **Agent** | 表示名と実行 ID。 |
| **Description** | エージェントの役割の短い説明。 |
| **Source** | 組み込み、プラグイン、ワークスペース、手動。 |
| **Mode** | `specialist`、`verifier`、`coordinator`、`formatter` などの役割。 |
| **Tools** | エージェントが使用を許可されたツール数。 |
| **Status** | 有効または無効。問題があるエージェントには警告が表示されます。 |
| **Actions** | 利用可能な場合の有効化/無効化スイッチ。 |

エージェント ID、名前、説明、プラグイン名で検索できます。ステータスフィルターでは、すべて、有効、無効のエージェントを表示できます。

## 詳細を見る

行をクリックすると詳細パネルが開きます。パネルには次が表示されます。

- エージェント名と実行 ID
- ソースとプラグイン所有者
- ステータスとヘルス
- 説明
- ソースファイルまたはプラグインコンポーネントパス
- モードと既定モデル
- 最大ツール呼び出し数
- 最大実行時間
- 最大継続呼び出し数
- 許可ツール
- システムプロンプト

読み取り専用エージェントには、どこで編集すべきかを示す注記が表示されます。手動エージェントには **サブエージェントを編集** と **このサブエージェントを削除** が表示されます。

## 手動サブエージェントを作成する

1. **サブエージェントを追加** をクリックします。
2. **Name** を入力します。
3. 生成された **ID slug** を確認または編集します。
4. **Description** を追加します。
5. **Mode** を選択します。
6. **System prompt** を書きます。
7. カンマ区切りで **Allowed tools** を追加します。
8. 必要に応じて **Default model** を設定します。
9. 実行制限を設定します。
10. 必要に応じて **Output schema** の JSON オブジェクトを追加します。
11. サブエージェントを **Enabled** で開始するか選びます。
12. **Save** をクリックします。

ID slug は作成後にロックされるため、安定した識別子を選んでください。

## 手動サブエージェントの項目

| 項目 | 説明 |
|---|---|
| **Name** | 表と詳細パネルに表示される人間向けの名前。 |
| **ID slug** | 安定した実行識別子。初回保存前に名前から自動生成され、後から変更できません。 |
| **Description** | いつこのサブエージェントを使うかの短い説明。 |
| **Mode** | 機能上の役割: `coordinator`、`specialist`、`verifier`、`formatter`。 |
| **System prompt** | サブエージェントへの指示。自己完結し、具体的にしてください。 |
| **Allowed tools** | カンマ区切りのツール名。実行時ポリシーは引き続き適用されます。 |
| **Default model** | このサブエージェントの任意のモデル指定。 |
| **Max tool calls** | 1 回の実行で許可される最大ツール呼び出し数。 |
| **Max runtime (seconds)** | 1 回のサブエージェント実行の最大時間。 |
| **Max continue calls** | 最大継続ターン数。 |
| **Output schema** | 期待する構造化出力を表す任意の JSON オブジェクト。 |
| **Enabled** | このサブエージェントを runtime で利用可能にするかどうか。 |

## 手動サブエージェントの編集と削除

手動サブエージェントを開き、**サブエージェントを編集** をクリックすると、名前、説明、システムプロンプト、許可ツール、モデル、制限、出力スキーマ、有効状態を更新できます。

削除するには詳細パネルを開き、**このサブエージェントを削除** をクリックします。削除は元に戻せません。

## プラグイン提供サブエージェント

プラグインは `agents/` ディレクトリ内の Markdown ファイル、またはプラグイン manifest の宣言でサブエージェントを含めることができます。インストールされると、それらのファイルは aiFetchly 内のプラグイン所有サブエージェント定義になります。

プラグインサブエージェントには次を含められます。

- `name`
- `description`
- `tools`
- `model`
- `mode`
- 実行制限
- システムプロンプトになる Markdown 指示

プラグイン所有サブエージェントは、`lead-pack:researcher` のようにプラグイン名で名前空間化されます。ネストしたフォルダーでは `lead-pack:review:verifier` のような深い ID も作成できます。

## プラグインサブエージェントの管理

プラグインサブエージェントは次の 2 か所に表示されます。

- 完全なカタログとして **システム設定 → サブエージェント**。
- 1 つのプラグインが所有するエージェントとして **Plugin Manager → プラグイン詳細 → Subagents**。

プラグイン詳細の Subagents タブでは、名前、ID、モード、ツール数、ヘルス、有効状態を確認できます。1 つのプラグインサブエージェントを無効化しても、そのプラグインの他の skills、MCP サーバー、サブエージェントは無効化されません。

プラグイン全体が無効な場合、個別スイッチがオンでもそのサブエージェントは利用できません。プラグインを再度有効にすると、保存済みのコンポーネント単位設定が復元されます。

## ヘルスと警告

サブエージェントは `healthy`、`disabled`、`partial_load`、`invalid`、`missing_files` などのヘルス状態を報告できます。

警告は通常、aiFetchly が制限付きでエージェントを読み込んだか、元の定義に問題を見つけたことを意味します。原因を確認するには詳細パネルまたはプラグイン診断を開きます。

## 安全上の注意

- プラグインサブエージェントは定義であり、独立したプログラムではありません。
- permission mode、hooks、直接の MCP サーバー登録、特権実行設定など、プラグイン由来のセキュリティ上重要なフィールドは無視されるか警告されます。
- 許可ツールはサブエージェントの上限です。aiFetchly はそのリストを有効なツールと実行時ポリシーでさらに絞り込みます。
- 手動のシステムプロンプトは自己完結させてください。サブエージェントは親チャット履歴全体を見られる前提にすべきではありません。
