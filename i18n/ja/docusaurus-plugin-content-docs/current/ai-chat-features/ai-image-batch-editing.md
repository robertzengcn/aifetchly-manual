# Batch Image Editing

バッチ編集は**1 つの指示を多数の画像に適用**します。1 枚ずつ編集する代わりに、aiFetchly が画像ごとに分離された編集を行う制限付きバックグラウンドジョブを実行し、会話内には 1 枚の進行状況カードだけを表示します。典型的なジョブ:

- 「20 枚の商品写真すべてを白背景にして」
- 「この生成の画像をすべて明るくして」
- 「これらの画像それぞれにウォーターマークの文字を入れて」

## バッチ編集が使われるとき

次の 3 つのいずれかでバッチになります:

1. **3 枚を超える画像に同じ編集を依頼した場合。** チャットの直接リクエストは最大 3 枚のため、それより多いセットは自動的にバッチへ振り分けられます（aiFetchly が先に確認を求めます）。
2. **参照トレーで 4 枚以上を選択した場合。** aiFetchly が尋ねます: 「3枚を超える画像が選択されました。独立した編集のバッチとして処理しますか？」。確認してバッチを開始するか、却下して 3 枚ずつ編集します。
3. **番号付きの大きなセットを依頼した場合。**（例:「画像 4 から画像 12 まで編集して」）実行前に同じ確認が表示されます。

:::info コスト発生前に確認

バッチの確認ダイアログには開始前に正確な枚数が表示されます。確認するまで何も実行されず、AI 利用も請求されません。

:::

## バッチを実行する

1. **画像を生成または選択**します（[AI Image Generation & Editing](./ai-image-generation) を参照）。
2. **すべてに適用する 1 つの指示を送ります**。例:「これらすべての背景を白に置き換えて」。
3. 「バッチで処理しますか？」のダイアログが出たら**バッチを確認**します。何枚が編集されるかが表示されます。
4. 会話内の**進行状況カード**を確認します（詳細は下記）。各項目が確実に保存され次第、結果が表示されます。
5. **結果を処理**します: 完了した画像をダウンロード・確認し、失敗したものを再試行します。

## 進行状況カード

1 枚のカードがジョブ全体を追跡します。画像 1 枚ごとにメッセージを流すことはありません:

- **サマリー行**: `{completed} / {requested} 件完了 · 同時実行数 {concurrency}` とジョブのステータス（実行中、完了、部分的、失敗、キャンセル）。
- **バッチを停止**: いつでも停止できます。完了済みの画像は保存されたまま残り、開始していなかった項目はキャンセルとして記録されます。
- **展開できる失敗セクション**: 失敗した各項目をファイル名と短い理由付きで表示します。
- **失敗した項目を再試行（N）**: ジョブの終了後、失敗またはキャンセルされた項目だけを再実行します。成功した画像が再処理されることはありません。

### 部分的な成功でも安全

20 枚のうち 18 枚が成功したら、その 18 枚の結果は保持されます。1 枚の失敗が他の画像をキャンセルすることはありません。**失敗した項目を再試行**をクリックすれば、2 枚の失敗に再挑戦できます。

## バッチの仕組み

バッチ編集は会話を膨らませずにスケールするよう設計されています:

- **1 枚に 1 ジョブ。** 各画像は共有された指示を持つ独立した AI リクエストで編集されます。入力と出力の対応は維持され、結果は完了順ではなく選択順で報告されます。
- **制限付き同時実行。** 最大 **3 枚**を同時に処理します（コーディネーターにより 1〜3 で調整可能）。50 枚のジョブは 50 回の小さなリクエストであり、1 回の巨大なリクエストではありません。
- **親チャットは軽量。** メインの会話が受け取るのは進行状況・サマリー・完成画像だけです。画像データや項目ごとのトランスクリプトは分離されたワーカー内に留まるため、長いバッチの最中でも会話を続けられます。
- **永続的な出力。** 完成した各画像は進行状況カードが参照する前にローカルへ保存されるため、プロバイダー側の一時リンクが失効しても結果は失われません。

:::note 1 枚ごとに AI 利用コストがかかります

バッチの分離は会話のコンテキストを小さく保つもので、編集が無料になるわけではありません。各画像は画像モデルの 1 操作です。確認ダイアログが項目数を事前に示し、直接チャットと同じツール承認ルールが適用されます。

:::

## 制限

| 制限 | 値 |
|---|---|
| バッチジョブあたりの画像数 | 1〜50（重複は自動的に除去） |
| 同時に実行できる画像編集 | 1〜3（デフォルト 3） |
| 1 回の直接リクエストの画像入力 | 3 |
| 全項目に同じ指示 | はい、バッチごとに 1 つの共有指示 |
| 合成（複数画像を 1 枚へ） | バッチでは利用不可。3 枚までの直接パスを使用 |

## トラブルシューティング

**いくつかの項目が失敗しました。**
進行状況カードの失敗セクションを開いて理由を確認し、**失敗した項目を再試行（N）**をクリックします。失敗したものだけが再実行されます。

**「この画像はサイズの上限を超えています」**や**「対応していない画像タイプ」**
保存された元画像が大きすぎるか、エディターが読めない形式の可能性があります（PNG、JPEG、WebP に対応）。画像を再生成するか、ワークスペースに保存してリサイズ・変換し、ワークスペースファイルのバッチとして実行してください。

**「元の画像は利用できなくなりました」**
参照の背後にある保存ファイルが失われました。その画像を再生成し、新しいバッチを開始してください。

**「Image editing is unavailable: no edit-capable model is configured」**
ご利用の [AI プロバイダー](../settings/ai-provider)には画像編集モデルがありません。設定してから失敗項目を再試行してください。

**誤ってバッチを停止してしまいました。**
完了済みの結果はすでに保存されています。ジョブの終了後に**失敗した項目を再試行**をクリックしてください。キャンセルされた（未開始の）項目も取り込まれます。

**バッチが止まっているように見えます。**
同時実行は 3 編集までに制限されているため、大きなジョブには時間がかかります。サマリー行を確認してください。完了数が長時間増えない場合は**バッチを停止**し、残りの項目を再試行してください。
