# AI プロバイダー

**AI プロバイダー**ページでは、AI チャットがモデルを取得する場所を選択できます。2 つのオプションがあります。

- **ホステッド aiFetchly** — aiFetchly がモデルを実行します。これがデフォルトであり、aiFetchly AI サブスクリプションに含まれています。
- **カスタム / ローカルプロバイダー** — [Ollama](https://ollama.com) や LM Studio のようなローカルサーバー、OpenAI や OpenRouter のようなサードパーティ API など、任意の **OpenAI 互換**エンドポイントを aiFetchly に指定します。

:::info これが重要な理由

カスタムプロバイダーを使用すると、**aiFetchly AI サブスクリプションがなくても、独自のモデルで AI チャットを利用できます。** その他のホステッド aiFetchly AI 機能（キーワード生成、メールテンプレート生成、AI リカバリ、リランク、埋め込み）は引き続きサブスクリプションが必要です。チャット画面のみが独自のプロバイダーで実行できます。

:::

カスタムプロバイダーは、標準的な OpenAI のチャット補完契約（`/v1/chat/completions`、およびサポートされている場合は `/v1/models`）に従います。aiFetchly はプロバイダー固有の SDK をバンドルせず、アプリのバックエンドから直接エンドポイントと通信するため、API キーがお使いのマシンから外部に送信されることはありません。

## AI プロバイダーページを開く

1. 左側のナビゲーションメニューで **設定** をクリックします。
2. **AI プロバイダー**ページを開きます（システム設定の下）。

## プロバイダーモード

ページの上部で、ラジオグループからモードを選択します。

| モード | 使用するタイミング | 必要なもの |
|------|-------------|------------------|
| **ホステッド aiFetchly** | aiFetchly AI サブスクリプションを持ち、最もシンプルな方法を選びたい場合。 | 有効な aiFetchly AI サブスクリプション。 |
| **カスタム / ローカルプロバイダー** | 独自のモデルを実行する、より高い制御、プライバシー、低コストを求める、またはサブスクリプションを持っていない場合。 | 到達可能な OpenAI 互換エンドポイントと保存済みのプロバイダー構成。 |

**ホステッド**モードでは、ページにお使いのアカウントでホステッド AI が有効かどうか、またはサブスクリプションが必要かどうかが表示されます。

**カスタム / ローカルプロバイダー**モードでは、プロバイダー構成フィールドが（下記に）表示されます。このモードで保存すると AI チャットがお使いのプロバイダーに切り替わります。**ホステッド**モードで保存すると元に戻ります。

:::tip AI チャットのみがこの設定に従います

カスタムプロバイダーへの切り替えでロックが解除されるのは **AI チャット** のみです。ホステッド限定の AI 機能は、この設定に関係なく引き続きサブスクリプションが必要です。

:::

## プロバイダープリセット

入力の手間を省くために、**プロバイダープリセット**を選択します。選択すると推奨される名前とベース URL が自動入力されますが、その後もすべてのフィールドを編集できます。

| プリセット | デフォルトのベース URL | API キー |
|--------|------------------|---------|
| **Ollama** | `http://localhost:11434/v1` | 通常は不要 |
| **LM Studio** | `http://localhost:1234/v1` | 通常は不要 |
| **OpenAI** | `https://api.openai.com/v1` | 必須 |
| **OpenRouter** | `https://openrouter.ai/api/v1` | 必須 |
| **vLLM** | `http://localhost:8000/v1` | 通常は不要 |
| **LocalAI** | `http://localhost:8080/v1` | 通常は不要 |
| **Custom** | _（空）_ | 任意 |

その他の OpenAI 互換サーバー（企業ゲートウェイ、Groq 互換エンドポイント、別のローカル推論サーバーなど）には **Custom** を選択してください。

## 構成フィールド

**カスタム / ローカルプロバイダー**が選択されている場合、以下のフィールドが表示されます。

| フィールド | 説明 |
|-------|-------------|
| **プロバイダープリセット** | クイックスタートのテンプレート（上記参照）。デフォルト値を入力しますが、フィールドはロックされません。 |
| **プロバイダー名** | このプロバイダーのラベル。必須。 |
| **ベース URL** | プロバイダーの API ルート（例：`http://localhost:11434/v1`）。必須。[ベース URL の正規化](#ベース-url-の正規化)を参照してください。 |
| **API キー（オプション）** | `Bearer` トークンとして送信されます。マスク表示されます。必要としないローカルプロバイダーでは空欄のままにします。 |
| **デフォルトモデル** | AI チャットが使用するモデル。コンボボックス形式で、更新されたリストから選択するか、名前を手動で入力できます。必須。 |
| **コンテキストサイズ（オプション）** | モデルのコンテキストウィンドウをトークン単位で上書きします。 |
| **モデルを更新** | プロバイダーの `/models` エンドポイントからモデルリストを取得します。 |
| **接続テスト** | エンドポイントを検証し、機能を検出します。[接続テスト](#接続テスト)を参照してください。 |
| **保存** | 構成を永続化します。 |

### ベース URL の正規化

ベース URL は、`/v1` サフィックスの有無、末尾のスラッシュの有無にかかわらず入力できます。aiFetchly は保存時に `/v1` で終わり、末尾のスラッシュがない形に正規化します。

| 入力値 | 保存される値 |
|-----------|-----------|
| `http://localhost:11434` | `http://localhost:11434/v1` |
| `http://localhost:11434/` | `http://localhost:11434/v1` |
| `http://localhost:11434/v1/` | `http://localhost:11434/v1` |
| `https://api.openai.com/v1` | `https://api.openai.com/v1` |

### API キーの取り扱い

- **API キー**フィールドはマスク表示されます。目のアイコンをクリックすると、入力内容が表示されます。
- キーを一度保存すると、**プレーンテキストで再表示されることはありません**。フィールドには _"API key configured — leave blank to keep"_ と表示され、緑色の **API key configured** チップが表示されます。
- 既存のキーを保持するには、保存時にフィールドを空欄のままにします。
- 置き換えるには、新しいキーを入力して保存します。
- 削除するには、**Clear API key** をクリックします。

:::warning プレーン HTTP

`http://` は `localhost` およびローカルネットワークプロバイダーで許可されています。ローカル **でない** プレーン `http://` URL を使用すると、aiFetchly は接続が暗号化されていないことを警告します。リモートプロバイダーには `https://` を使用してください。

:::

## モデルを更新

**モデルを更新**をクリックすると、プロバイダーの `/models` エンドポイントにクエリを送信し、**デフォルトモデル**のドロップダウンに入力されます。これはオプションであり、代わりにモデル名を手動で入力することも常に可能です。

- `/models` が成功すると、返されたモデルが正規化されてドロップダウンに表示されます。
- `/models` が失敗した場合（一部のローカルサーバーは実装していません）、警告が表示されますが、**デフォルトモデル**が入力されていれば構成は有効です。aiFetchly は手動で入力されたモデルにフォールバックします。
- デフォルトモデルは存在するがリストを読み込めない場合でも、保存してチャットできます。

## 接続テスト

プロバイダーを本格的に利用する前に **接続テスト** をクリックします。テストは以下の順序で検証します。

1. ベース URL が有効な `http:` または `https:` URL であること。
2. プロバイダーに到達できること。
3. `/models` エンドポイントが機能する、**または** デフォルトモデルが手動で入力されていること。
4. ごく小さなプロンプトで非ストリーミングのチャット補完が成功すること。
5. ストリーミングチャット補完が成功すること（サポートされている場合）。
6. 可能な場合、ツール呼び出しのサポートが検出されること。

テストは最小限のプロンプトを送信します（例：モデルに `pong` と返答するよう依頼）。有効な補完はすべて成功とみなされます。ローカルモデルは多くの場合フォーマットを追加するため、aiFetchly は厳密なテキスト一致を要求しません。

結果はステータスメッセージと **機能バッジ**（下記）として表示されます。接続テストでお使いの API キーがログに記録されたり表示されたりすることはありません。

:::note サードパーティ API はトークンごとに課金する場合があります

OpenAI、OpenRouter、その他の有料エンドポイントはトークンごとに課金されるため、各接続テストでは非常に小さなリクエストのみを送信します。それでもテストは実際の API 呼び出しを行います。

:::

## 機能バッジ

接続テストの後、機能バッジはプロバイダーとモデルが何をできるかを示します。

| バッジ | 意味 |
|-------|---------|
| **Models** | `/models` エンドポイントが利用可能です。 |
| **Chat** | 非ストリーミングチャット補完が機能します。 |
| **Streaming** | ストリーミングチャット補完が機能します。 |
| **Tools** | モデルがツール呼び出しをサポートしています。 |
| **Vision** | モデルが画像入力を受け付けます。 |
| **Context** | 検出/上書きされたコンテキストサイズ（トークン単位）（利用可能な場合に表示）。 |

各バッジは以下のいずれかの状態になります。

| 状態 | 色 | 意味 |
|-------|-------|---------|
| **Supported** | 🟢 緑 | 動作が確認済みです。 |
| **Unsupported** / **Failed** | 🔴 赤 | 動作しないことが確認された、またはテストが失敗しました。 |
| **Unknown** | 🟡 黄 | 判定できません。注意して進めてください。 |

:::tip Tools が unsupported または unknown の場合

お使いのプロバイダーがツール呼び出しを（確実に）サポートしていない場合、AI チャットは自動的に控えめな承認モードを使用し、プレーンチャットではツール定義を送信しません。ツールに依存するツール必須およびプランモードのワークフローは、無効になるか警告が表示される場合があります。ツール/プランモードの完全なサポートには、ツール対応モデルまたはホステッド aiFetchly を使用してください。

:::

## AI チャットがプロバイダーを使用する仕組み

有効なカスタムプロバイダーが保存されると、以下のようになります。

- **AI チャットが利用可能になります** — aiFetchly AI サブスクリプションがなくても。
- AI チャットのモデルセレクターの近くに **プロバイダーインジケーター** が表示されます（例：`Local: Ollama`、`Local: LM Studio`、`Hosted`）。クリックするとこの設定ページが開きます。
- **モデルセレクター** には、プロバイダーのモデルが一覧表示されます（`/models` から、または `/models` が利用できない場合は構成済みのデフォルトモデルのみ）。
- チャットリクエストはアプリバックエンドから直接エンドポイントに送信され、ブラウザ/レンダラーから送信されることはありません。

プロバイダーに到達できない場合、AI チャットはサイレントに失敗するのではなく、明確なプロバイダーエラーを表示します。

:::info 関連：AI Chat V2

プロバイダーモードはチャット画面全体で共有されます。プランモードやコンテキスト使用量バッジなど、チャット体験自体については [AI Chat V2](../ai-outreach/ai-chat-v2) を参照してください。

:::

## セキュリティとプライバシー

- **API キーは保存時に暗号化され**、構成の他の部分とは別に保存されます。
- キーは保存後、**UI にプレーンテキストで返されることはありません**。ページには `apiKeyConfigured: true/false` のみが表示されます。
- **キーはログに記録されません。** デバッグログとリクエストログでは、`Authorization` ヘッダーやシークレットらしきものが編集されます。
- **リクエストはアプリバックエンドから行われ**、レンダラーからではないため、認証情報は Web コンテンツにさらされません。
- **ベース URL は** `http:` または `https:` のみとして検証されます。

## クイックスタート：Ollama

1. [Ollama をインストール](https://ollama.com)し、モデルをプルします（例：`ollama pull llama3.1`）。
2. **設定 → AI プロバイダー**を開きます。
3. **カスタム / ローカルプロバイダー**を選択します。
4. **プロバイダープリセット**を **Ollama** に設定します（`http://localhost:11434/v1` が入力されます）。
5. **モデルを更新**をクリックしてモデルを選択するか、手動で入力します（例：`llama3.1`）。
6. **接続テスト**をクリックして確認し、**保存**します。
7. AI チャットを開きます。インジケーターは `Local: Ollama` と表示され、サブスクリプションなしでチャットできます。

## クイックスタート：OpenAI / OpenRouter

1. **設定 → AI プロバイダー**を開きます。
2. **カスタム / ローカルプロバイダー**を選択します。
3. **プロバイダープリセット**を **OpenAI** または **OpenRouter** に設定します。
4. **API キー**を API キーフィールドに貼り付けます。
5. **デフォルトモデル**を入力します（例：`gpt-4o-mini`、または OpenRouter のモデル ID）。
6. **接続テスト**をクリックし、**保存**します。

## トラブルシューティング

### プロバイダーに接続できない

**考えられる原因：**
- ローカルサーバーが実行されていない（Ollama / LM Studio / vLLM のプロセスを確認）。
- ベース URL またはポートが間違っている。
- ファイアウォールが localhost/lan アクセスをブロックしている。

**解決策：**
1. プロバイダーを起動し、ブラウザで応答することを確認します（例：`http://localhost:11434/v1/models`）。
2. ベース URL を再確認し、**接続テスト**を実行します。
3. Docker や WSL のセットアップでは、aiFetchly のネットワークコンテキストからプロバイダーに到達できることを確認します。

### 認証失敗（401 / 403）

**考えられる原因：**
- API キーが欠落している、間違っている、または期限切れである。
- 選択したモデルへのアクセス権がキーにない。

**解決策：**
1. API キーを再入力して保存します。
2. OpenAI/OpenRouter の場合、キーが有効であり、モデルに対するクレジット/権限があることを確認します。

### 選択したモデルが利用できない

プロバイダーから "model not found" が返されました。**モデルを更新**リストから別のモデルを選択するか、プロバイダーが実際に提供している **デフォルトモデル** に更新してください。

### モデルリストを読み込めない

一部のローカルサーバーは `/models` を実装していません。これは想定内の動作です。**デフォルトモデル**にモデル名を手動で入力して保存してください。チャットは引き続き機能します。

### チャットは機能するが Tools / Streaming が unsupported と表示される

すべてのローカルモデルがツール呼び出しやストリーミングをサポートしているわけではありません。これらが必要な場合は、ツールまたはストリーム対応のモデルに切り替えるか、**ホステッド aiFetchly** を使用してください。[機能バッジ](#機能バッジ)を参照してください。

### ホステッド限定機能が引き続きサブスクリプションを求める

これは仕様です。カスタムプロバイダーでロックが解除されるのは AI チャットのみです。キーワード生成、メールテンプレート生成、AI リカバリ、リランク、埋め込みは、引き続き aiFetchly AI サブスクリプションが必要です。
