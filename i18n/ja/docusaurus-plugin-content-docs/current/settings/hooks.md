# フック

**フック**は、AI マーケティングアシスタントの操作の前後で独自のロジックを実行するライフサイクルトリガーです。明確に定義されたタイミングで発動します。最も重要なのは**ツールの実行前後**です。アクションを監視、ブロック、書き換え、注釈できます。フックを使うと、ポリシーを強制し（「この種類のコマンドは絶対に実行しない」）、AI が参照するコンテキストを追加し（「スクレイピング後にコンプライアンスを通知」）、すべてのフック決定の改ざん耐性のある監査ログを保持できます。

aiFetchly は、初期状態であなたを保護する**組み込みの安全フック**を同梱しており、さらに独自の**コマンドフック**を追加できます。コマンドフックは、イベントを JSON として受け取って次に何を行うかを決定する小さなスクリプトです。

:::info フックの位置づけ

フックは、AI とその AI が呼び出すツール（組み込みの [AI スキル](../ai-outreach/ai-skills)、[MCP ツール](../ai-outreach/mcp-tools)、およびレガシーツール）の間に位置します。フックは AI を**置き換えるものではなく**、AI が要求するツール呼び出しをゲートして形成します。呼び出しを*許可する*フックは通常の権限システムをバイパスしません。呼び出しを*ブロックする*フックは、実行される前に停止させます。

:::

## フックでできること

各フックはイベントの詳細を受け取り、決定を返すことができます。

- **ブロック** — アクションが発生する前に阻止します（例：危険なシェルコマンドを拒否）。
- **書き換え** — ツールが呼び出されようとしている入力を書き換えます（例：値をマスキング）。
- **コンテキストの追加** — ツール実行後に AI が読むコンテキストを追加します（例：コンプライアンスの通知）。
- **アクティビティの記録** — 後で監査ログで確認できるよう記録します。

## 主要な概念

### イベント

フックは1つの**イベント**にバインドされます。イベントとは、AI のライフサイクルの中でフックが発動するタイミングです。最も重要なイベントはツールライフサイクルのイベントです。

| イベント | 発動タイミング | ブロック可否 |
|---------|---------------|-------------|
| **PreToolUse** | ツールが実行される直前 | ✅ はい — ツールは実行されません |
| **PostToolUse** | ツールが正常に実行された後 | ❌ いいえ（ツールはすでに実行済み）ですが、コンテキストの追加や出力の書き換えは可能です |
| **PostToolUseFailure** | ツールが失敗した後 | ❌ いいえ（失敗を成功に切り替えることはできません）が、メッセージを追加することはできます |

フックモデルの追加イベント — **SessionStart**、**UserPromptSubmit**、**PermissionRequest**、**PermissionDenied**、および **Stop** — はイベントドロップダウンで選択可能で、セッション、プロンプト、権限、ターン終了のタイミングを表します。イベント名は（`PreToolUse` のような）コード識別子としてすべての言語で保持され、検索しやすく曖昧さのない状態に保たれます。

:::note ツールイベントがアクティブな強制ポイントです

現在完全に接続されている強制ポイントは、ツールライフサイクルイベント（**PreToolUse**、**PostToolUse**、**PostToolUseFailure**）です。ブロック、入力の書き換え、出力の書き換え、コンテキストの注入はここで効果を発揮します。セッション、プロンプト、権限、停止のイベントはフックモデルの一部であり UI で選択可能ですが、それぞれが発動するかどうかは、アプリケーション内のどこでその部分がトリガーされるかに依存します。

:::

### ソース

すべてのフックには**ソース**があり、これが所有者と操作可能な範囲を決定します。

| ソース | 内容 | デフォルトで表示 |
|--------|------|----------------|
| **builtin** | aiFetchly に同梱（安全性とコンプライアンス） | ✅ はい |
| **user** | このページであなたが作成 | ✅ はい |
| **session** | 現在のセッション用に一時的に登録 | **セッションホックを表示**がオンの場合のみ |

**ソース**フィルターを使って、リストをこれらのいずれかに絞り込めます。

### コマンドフック

UI から作成できる唯一の種類のフックは**コマンドフック**です。コマンドフックはローカルコマンド（スクリプトまたは実行可能ファイル）を実行し、JSON を介して aiFetchly と通信します。

1. aiFetchly はイベントの詳細を**標準入力の JSON オブジェクト**としてコマンドに送信します。
2. コマンドは処理を行い、**JSON の決定を標準出力**に書き出します。
3. aiFetchly はその決定を読み取って acted します（ブロック、入力の書き換え、コンテキストの追加など）。

組み込みフックはコード（コールバックフック）で記述されており、UI からは編集できません。オン/オフを切り替えることのみ可能です。

### マッチャー

フックの**マッチャー**は、それが*どのツール呼び出し*に適用されるかを絞り込みます。マッチャーは**ツール名**に対してテストされ、シンプルなワイルドカードパターンをサポートします。

| マッチャー | 一致対象 |
|----------|---------|
| `*` | すべてのツール |
| `shell_execute` | 名前が厳密に `shell_execute` のツールのみ |
| `scrape_*` | 名前が `scrape_` で始まるツール（例：`scrape_search`） |
| `*_search` | 名前が `_search` で終わるツール |
| `*scrape*` | 名前に `scrape` を含むツール |

マッチャーは最大 128 文字です。

### 「If」条件

オプションの **If 条件**は、ツールの名前だけでなく**引数の値**を照合することで、フックをさらに絞り込みます。ツールに渡される文字列引数に対してテストされる、同じワイルドカード構文を使用します。例：

- `PreToolUse` でマッチャー `shell_execute` の場合、If 条件 `git *` にすると、`git ` で始まるシェルコマンドに対してのみフックが発動します。
- If 条件 `rm -rf *` は、再帰的削除コマンドに対してのみ発動します。

ツール引数を持たないイベントでは If 条件は無視されます。最大 256 文字です。

### 失敗モード

フックは失敗する可能性があります。コマンドがクラッシュ、タイムアウト、無効な JSON を返す場合などです。**失敗モード**は、*フック自体*がエラーになった際にツール呼び出しをどうするかを決定します（これはフックが意図的に「ブロック」を返す場合とは別です）。

| 失敗モード | フックがエラーになった場合… |
|-----------|--------------------------|
| **warn** | エラーは監査ログに記録され、ツール呼び出しは**通常通り続行**されます。 |
| **block** | エラーはブロックとして扱われ、ツール呼び出しは**実行されません**。 |

重要でないフック（ロギング、助言的なコンテキスト）には **warn** を使います。フックのチェックを成功させずにツールを実行するくらいなら停止させたい場合にのみ **block** を使います。

:::tip ブロックと warn の違い（一文で）

フックが `{ continue: false }` を*返した*場合、失敗モードに関係なく常にツールをブロックします。失敗モードが意味を持つのは、フック**自体が壊れた場合**（タイムアウト、クラッシュ、不正な JSON）のみです。

:::

### グローバル有効化

ページ上部の**フックをグローバルに有効化**スイッチは、マスターキルスイッチです。オフの場合、**どこでもフックは発動しません**。組み込みもユーザー作成も同様です。ページの残りの部分はインタラクティブなままなので、システムが一時停止している間もフックを構成できます。この設定は再起動後も保持されます。

## フックページを開く

1. 左のナビゲーションメニューで **設定** をクリックします。
2. **フック**ページを開きます（スキルや MCP と並んでいます）。

## ページレイアウト

フックページには、上から下に並んだ4つの領域があります。

```
┌─ Hooks ──────────────────────────────────────────────┐
│ [✓] Enable hooks globally            [+ Add command]  │  header
│ Filter: Event[All▾] Source[All▾] [□ Show session]     │  list filters
│ ┌─────────────────────┬─────────────────────────┐    │
│ │ Hooks (N)           │ Edit panel              │    │  master–detail
│ │ ● block-shell   ✓   │ Hook ID / Event / …     │    │
│ │ ● compliance    ⏸   │ [Save] [Delete]         │    │
│ └─────────────────────┴─────────────────────────┘    │
│ ─ Recent audit ─────────────────────────────────────  │  audit panel
│ Time   Hook        Event       Status   Duration      │
└───────────────────────────────────────────────────────┘
```

- **ヘッダー** — グローバル有効化スイッチと **+ コマンドフックを追加** ボタン。フックがグローバルに無効な場合、黄色のバナーが表示されます。
- **リストフィルター** — イベントとソースでフックリストをフィルターし、オプションでセッションホックを表示します。
- **マスター/詳細** — 左側にフックリスト。フックをクリックすると右側で編集できます。
- **監査パネル** — 最近のフックアクティビティ。独自のフィルターとオプションの自動更新があります。

## 組み込みフック

aiFetchly には以下の組み込みフックが同梱されています。

| フック ID | イベント | マッチャー | デフォルト | 内容 |
|----------|---------|----------|-----------|------|
| `builtin-block-dangerous-shell-delete` | PreToolUse | `shell_execute` | **有効** | 危険な再帰削除パターンに一致するシェルコマンドをブロックします（例：`rm -rf /` や `rm -rf *`）。 |
| `builtin-scraping-compliance-context` | PostToolUse | `scrape_*` | 無効 | 任意のスクレイプツール呼び出しの後、AI のコンテキストに短いコンプライアンス通知を注入し、合法的で最小限のデータのアウトリーチを推奨するようにします。 |

:::warning スクレイピングコンプライアンスコンテキスト

`builtin-scraping-compliance-context` を有効にすると、**すべての**スクレイプツール呼び出しの後にコンプライアンスガイダンスが AI プロンプトに注入されます。これは意図的なものですが、AI のフォローアップ回答の表現に影響を与える可能性があることに注意してください。

:::

組み込みフックは**読み取り専用**です。フィールドは編集できず、削除もできません。オン/オフを切り替えることのみ可能で、そのオーバーライドは再起動後も保持されます。

## コマンドフックの作成

### ステップ 1：新しいフックを開始

**+ コマンドフックを追加** をクリックします。編集パネルが妥当なデフォルト値の空のフォームに切り替わります。

- **Event**：`PreToolUse`
- **Matcher**：`*`
- **Failure mode**：`warn`
- **Timeout**：`5000` ms
- **Enabled**：オフ（新しいフックは無効状態で開始）

### ステップ 2：フィールドに入力

| フィールド | 説明 |
|----------|------|
| **Hook ID** | フックの一意の名前（例：`block-home-delete`）。リストと監査ログで使用されます。 |
| **Event** | フックが発動するタイミング（[イベント](#イベント) を参照）。 |
| **Matcher** | フックが適用されるツール名。`*` はすべてを意味します（[マッチャー](#マッチャー) を参照）。 |
| **If condition** | オプション — ツールの引数値でさらに制限します（[「If」条件](#if条件) を参照）。 |
| **Command** | 実行するローカルコマンド。stdin でイベントを JSON として受け取り、stdout に JSON の決定を出力する必要があります（[コマンドフックの契約](#コマンドフックの契約) を参照）。 |
| **Timeout (ms)** | フックが強制終了されるまでの最大実行時間。デフォルト `5000`、上限 `60000`。 |
| **Failure mode** | フック自体がエラーになった場合の動作（[失敗モード](#失敗モード) を参照）。 |
| **Status message** | オプション — フック実行中に進行インジケーターとして表示される短いラベル。 |

### ステップ 3：保存して有効化

1. **保存** をクリックします。フックは **Enabled オフ** で保存されるため、まだ何も実行されません。
2. リストでフックを選択し、**Enabled** スイッチをオンにして有効化します。

:::tip フックは両方のスイッチが許可した場合のみ実行されます

コマンドフックは、**フックがグローバルに有効**であり、かつ**フック自体が有効**な場合にのみ発動します。新しいフックは意図的に無効状態で開始するため、実行前にコマンドを確認できます。

:::

## フックの編集、有効化、削除

- **有効化/無効化** — 任意のフックを選択し、**Enabled** スイッチを切り替えます。組み込みフックとユーザーフックの両方で機能します。変更は即座に反映され、保持されます。
- **フィールドの編集** — **user** フックのみ編集可能です。フックを選択してフィールドを変更し、**保存** をクリックします。組み込みフックとセッションフックはフィールドが読み取り専用で表示されます。
- **削除** — **user** フックのみ削除可能です。**削除** をクリックし、ダイアログでフック ID とコマンドプレビューを確認すると、フックは完全に削除されます。組み込みフックは削除できません（ボタンは非表示で、念のためバックエンドでも拒否されます）。

## コマンドフックの契約

コマンドフックが発動すると、aiFetchly は **Command** を `shell: false` で実行します。最初のトークンが実行可能ファイルで、残りのトークンがその引数です。イベントを **stdin** の JSON オブジェクトとして送信し、**stdout** から JSON の決定を読み取ります。

### 入力（stdin）

`PreToolUse` フックの場合、入力はおおよそ次のようになります。

```json
{
  "eventName": "PreToolUse",
  "hookRunId": "run-1a2b3c",
  "tool": { "id": "...", "name": "shell_execute", "source": "legacy-tool" },
  "input": { "command": "rm -rf /tmp/old" },
  "permissionState": { "allowed": true, "needsPrompt": false },
  "timestamp": "2026-07-10T09:42:00.000Z"
}
```

正確なフィールドはイベントに依存します（例：`PostToolUse` には `output` と `executionTimeMs` も含まれます）。スクリプトは防御的に読み取るべきです。オプショナルチェーンでフィールドにアクセスし、欠落キーを許容してください。

### 出力（stdout）

コマンドは決定を記述した JSON オブジェクトを出力します。すべてのフィールドはオプションです。

| フィールド | 効果 |
|----------|------|
| `continue` | `false` でツール呼び出しをブロックします（`reason` と併用）。省略または `true` で許可。 |
| `reason` | 監査ログと（ブロックの場合）AI に表示される人間が読める説明。最大 1000 文字。 |
| `additionalContext` | AI のコンテキストに追加されるテキスト（`PostToolUse` でよく使用）。最大 4000 文字。 |
| `systemMessage` | システムレベルのメッセージ。最大 2000 文字。 |
| `updatedInput` | ツールの入力を置き換えます（**PreToolUse のみ**）。最大 64 KB。 |
| `updatedToolOutput` | ツールの出力を書き換えます（**PostToolUse のみ**）。失敗を成功に切り替えることはできません。最大 128 KB。 |
| `suppressOutput` | 会話からツールの出力を非表示にします。 |
| `permissionDecision` | `allow`、`ask`、または `deny`。`allow` は助言的であり、権限システムを上書きすることはありません。 |

最小の「許可」レスポンスは空のオブジェクト `{}` です。有効な JSON でない出力はフックエラーとして扱われます（失敗モードの対象）。常に整形式の JSON を出力してください。

### 実行ルール

- **シェル機能は使用不可。** `shell: false` のため、パイプ（`|`）、リダイレクト（`>`）、チェーン（`&&`）、変数展開（`$VAR`）は**直接機能しません**。これらを使うには、明示的にシェルを起動してください（例：`sh -c "..."` や `bash -c "..."`）。
- **制限された環境。** コマンドはデフォルトで `PATH`、`HOME`、`USER`、`USERNAME`、`TEMP`、`TMP` のみの小さな許可リストの環境変数を受け取ります。aiFetchly は自身の認証情報やトークンをフックに渡すことはありません。
- **クォーティング。** コマンドパーサーはスペースを含む引数に対して単一引用符と二重引用符をサポートします（例：`-e "console.log(1)"`）。ただし、エスケープシーケンスや変数展開はサポートしません。
- **サイズ上限。** stdout は 256 KB、stderr は 64 KB が上限です。レスポンスは小さく保ってください。

## 例

### 例 1 — ホームディレクトリの削除をブロック

ホームフォルダ以下のファイルを削除するシェルコマンドを拒否する `PreToolUse` フックです。

**フック設定**

| フィールド | 値 |
|----------|-----|
| Event | `PreToolUse` |
| Matcher | `shell_execute` |
| Failure mode | `block` |
| Command | `node /home/me/hooks/block-home-delete.js` |

**`block-home-delete.js`**

```js
let raw = "";
process.stdin.on("data", (chunk) => (raw += chunk));
process.stdin.on("end", () => {
  let input = {};
  try { input = JSON.parse(raw); } catch { /* ignore malformed input */ }
  const command = String(input?.input?.command ?? "");
  if (/\brm\s+-rf\s+~(\/|$|\s)/.test(command)) {
    process.stdout.write(JSON.stringify({
      continue: false,
      reason: "Refusing to delete files inside the home directory.",
    }));
    return;
  }
  process.stdout.write(JSON.stringify({ continue: true }));
});
```

### 例 2 — スクレイピング後にコンプライアンス通知を追加

スクレイプツールが実行されるたびにガイダンスを注入する `PostToolUse` フックです。

**フック設定**

| フィールド | 値 |
|----------|-----|
| Event | `PostToolUse` |
| Matcher | `scrape_*` |
| Failure mode | `warn` |
| Command | `node /home/me/hooks/compliance-reminder.js` |

**`compliance-reminder.js`**

```js
let raw = "";
process.stdin.on("data", (chunk) => (raw += chunk));
process.stdin.on("end", () => {
  process.stdout.write(JSON.stringify({
    additionalContext:
      "Only keep contact data you have a lawful basis to process, and prefer minimal, opt-in outreach.",
  }));
});
```

### 例 3 — すべてのツール呼び出しをログファイルに追記

生のイベントをファイルに追記する `PostToolUse` フックです。リダイレクトを使用するため、明示的にシェルを起動します。

| フィールド | 値 |
|----------|-----|
| Event | `PostToolUse` |
| Matcher | `*` |
| Failure mode | `warn` |
| Command | `sh -c "cat >> /tmp/aifetchly-tool-audit.log"` |

:::tip 有効化前にテストする

まずターミナルからサンプル JSON をパイプでスクリプトに渡してテストします（`echo '{...}' | node my-hook.js`）。有効な JSON を出力し、すぐに終了することを確認してから、コマンドフックで指定してください。

:::

## 監査ログの確認

ページ下部の**最近の監査ログ**は、すべてのフック実行を記録します。各行には以下が表示されます。

| 列 | 意味 |
|----|------|
| **Time** | フックが実行された時刻。 |
| **Hook** | フック ID。 |
| **Event** | それをトリガーしたイベント。 |
| **Status** | `started`、`success`、`blocked`、`failed`、`timeout` のいずれか。 |
| **Duration** | フックにかかった時間（ミリ秒）。 |
| **Reason** | ブロックの理由、または失敗時のエラーメッセージ。 |

フィルターを使って**イベント**、**ステータス**、または**フック**で絞り込み、読み込む行数を選択できます（100 / 500 / 1000）。更新アイコンをクリックすると**自動更新**が開始されます（アクティブ中はアイコンが回転）。数秒ごとに再ポーリングするため、テスト中にフックアクティビティをライブで確認できます。

## セキュリティ

フックシステムは、問題のあるコマンドフックや悪意のあるコマンドフックがアプリケーションを侵害できないように設計されています。

- **デフォルトで無効。** 新しいコマンドフックは Enabled オフで保存されます。組み込みコマンドフックのみが有効状態で同梱され、そのうち有効なのは安全フック1つだけです。
- **制限された環境。** フックは環境変数の許可リストのみを受け取ります。aiFetchly の認証情報、API キー、セッショントークンは渡されません。
- **シェルインジェクションなし。** コマンドは `shell: false` と最小の argv パーサーで実行されるため、明示的にシェルを起動しない限りシェル演算子は解釈されません。
- **実行の制限。** すべてのフックにはタイムアウトがあります（デフォルト 5 秒、最大 60 秒）。超過すると強制終了され、`timeout` として記録されます。
- **出力の制限。** stdout と stderr には上限があり、超過した出力は切り詰められます。
- **監査での秘密情報のマスキング。** API キー、ベアラートークン、Cookie、`Authorization` ヘッダーのようなパターンは、監査ログに書き込まれる前にマスキングされます。
- **組み込みフックは改ざん不可。** UI から定義を編集・削除することはできず、切り替えのみ可能です。
- **フックは権限をバイパスしない。** `allow` を返すフックは助言的であり、標準の権限システムが引き続き適用されます。ツール呼び出しをショートサーキットするのは `block` を返すフックのみです。

:::warning 作成したコマンドフックはあなたの責任です

コマンドフックは、上記の環境であなたのマシン上のプログラムを実行します。信頼するスクリプトのみを、あなたが管理するディレクトリから指定し、有効化する前にコマンドを確認してください。

:::

## トラブルシューティング

### コマンドフックが発動しない

**考えられる原因：**
- フックがグローバルに無効（上部に黄色のバナー）。
- フック自体が無効（Enabled スイッチがオフ）。
- **マッチャー**がツール名に一致しない、または **If 条件**が引数値に一致しない。
- **Event** がアクティブなツールライフサイクルイベント（`PreToolUse` / `PostToolUse` / `PostToolUseFailure`）ではない。

**解決策：**
1. **フックをグローバルに有効化** をオンにします。
2. フックを選択して有効化します。
3. 一時的にマッチャーを `*` に設定し、If 条件をクリアしてフックが機能することを確認してから、再度絞り込みます。
4. 監査ログを確認します。ステータス `started` の行があればフックが選択されたことを意味します。行がなければ一致しませんでした。

### フックは実行されたがツールも実行された

**考えられる原因：**
- フックが `{ continue: true }`（または空のオブジェクト）を返し、呼び出しを許可した。
- フックが**エラー**になった（ステータス `failed` または `timeout`）うえ、失敗モードが **warn** のため、呼び出しが続行された。

**解決策：**
1. ブロックすべき場合、スクリプトが `{ continue: false, reason: "..." }` を出力するようにします。
2. フックがエラーになる場合、エラーでツールを停止させたいなら失敗モードを **block** に設定するか、スクリプトを修正してエラーが出ないようにします。

### フックのステータスが `failed` または `timeout` になる

**考えられる原因：**
- スクリプトがクラッシュした、または無効な（JSON でない）出力をした。
- スクリプトが構成されたタイムアウトより長くかかった。
- コマンドがシェルを起動せずにシェル機能（パイプ、リダイレクト）を使用した。

**解決策：**
1. ターミナルでスクリプトをテストします：`echo '{"eventName":"PreToolUse","input":{"command":"test"}}' | node my-hook.js`。有効な JSON を出力する必要があります。
2. タイムアウトを増やす（最大 60000 ms）、またはスクリプトを高速化します。
3. シェル機能を `sh -c "..."` や `bash -c "..."` でラップします。

### フック ID を変更できない

フック ID はフック作成後に固定されます（編集時はフィールドが無効化されます）。フックの名前を変更するには、希望する ID で新しく作成し、古いものを削除してください。

### 組み込みフックを編集・削除できない

これは意図的なものです。組み込みフックはコードが所有しており、オン/オフの切り替えのみ可能です。
