# AI 提供商

**AI 提供商**页面允许您选择 AI 聊天从何处获取模型。您有两个选项：

- **托管 aiFetchly** — 由 aiFetchly 为您运行模型。这是默认选项，包含在 aiFetchly AI 订阅中。
- **自定义/本地提供商** — 您可以将 aiFetchly 指向任何 **OpenAI 兼容**的端点，包括 [Ollama](https://ollama.com) 或 LM Studio 等本地服务器，或 OpenAI 和 OpenRouter 等第三方 API。

:::info 为什么这很重要

自定义提供商允许您**使用自己的模型进行 AI 聊天——即使没有 aiFetchly AI 订阅。** 其他托管的 aiFetchly AI 功能（关键词生成、邮件模板生成、AI 恢复、重排、嵌入）仍需要订阅；只有聊天界面可以通过您自己的提供商运行。

:::

自定义提供商遵循标准的 OpenAI 聊天补全协议（`/v1/chat/completions`，并在支持时使用 `/v1/models`）。aiFetchly 不打包特定于提供商的 SDK——它直接从应用程序的后端与您的端点通信，因此您的 API 密钥永远不会离开您的机器。

## 打开 AI 提供商页面

1. 点击左侧导航菜单中的 **设置**。
2. 打开 **AI 提供商**页面（位于系统设置下）。

## 提供商模式

在页面顶部，使用单选按钮组选择一种模式：

| 模式 | 适用场景 | 所需条件 |
|------|-------------|------------------|
| **托管 aiFetchly** | 您拥有 aiFetchly AI 订阅并希望走最简单的路径。 | 有效的 aiFetchly AI 订阅。 |
| **自定义/本地提供商** | 您运行自己的模型，希望获得更多控制权、隐私或更低成本，或者没有订阅。 | 可访问的 OpenAI 兼容端点和已保存的提供商配置。 |

在**托管**模式下，页面会显示您的账户是否已启用托管 AI，或者提示需要订阅。

在**自定义/本地提供商**模式下，会出现提供商配置字段（见下文）。在此模式下保存会将 AI 聊天切换到您的提供商；在**托管**模式下保存则会切换回来。

:::tip 仅 AI 聊天遵循此设置

切换到自定义提供商仅解锁**AI 聊天**。无论此设置如何，仅限托管的 AI 功能仍需要订阅。

:::

## 提供商预设

为节省输入，请选择一个**提供商预设**。选择预设会自动填写建议的名称和 Base URL——您之后仍可编辑每个字段。

| 预设 | 默认 Base URL | API 密钥 |
|--------|------------------|---------|
| **Ollama** | `http://localhost:11434/v1` | 通常不需要 |
| **LM Studio** | `http://localhost:1234/v1` | 通常不需要 |
| **OpenAI** | `https://api.openai.com/v1` | 必填 |
| **OpenRouter** | `https://openrouter.ai/api/v1` | 必填 |
| **vLLM** | `http://localhost:8000/v1` | 通常不需要 |
| **LocalAI** | `http://localhost:8080/v1` | 通常不需要 |
| **Custom** | _（空）_ | 您自行决定 |

对于任何其他 OpenAI 兼容服务器（例如公司网关、兼容 Groq 的端点或另一个本地推理服务器），请选择 **Custom**。

## 配置字段

当选择**自定义/本地提供商**时，会出现以下字段：

| 字段 | 描述 |
|-------|-------------|
| **提供商预设** | 快速启动模板（见上文）。会填写默认值，但不会锁定字段。 |
| **提供商名称** | 此提供商的标签。必填。 |
| **Base URL** | 提供商的 API 根地址，例如 `http://localhost:11434/v1`。必填。参见 [Base URL 规范化](#base-url-规范化)。 |
| **API 密钥（可选）** | 作为 `Bearer` 令牌发送。已掩码。对于不需要密钥的本地提供商，请留空。 |
| **默认模型** | AI 聊天使用的模型。这是一个组合框——从刷新后的列表中选择，或手动输入名称。必填。 |
| **上下文大小（可选）** | 覆盖模型的上下文窗口，单位为 token。 |
| **刷新模型** | 从提供商的 `/models` 端点拉取模型列表。 |
| **测试连接** | 验证端点并检测能力。参见 [测试连接](#测试连接)。 |
| **保存** | 持久化配置。 |

### Base URL 规范化

您可以输入带有或不带 `/v1` 后缀、带有或不带尾部斜杠的 Base URL——aiFetchly 会在保存时将其规范化，使其以 `/v1` 结尾且不带尾部斜杠。

| 您输入的内容 | 存储为 |
|-----------|-----------|
| `http://localhost:11434` | `http://localhost:11434/v1` |
| `http://localhost:11434/` | `http://localhost:11434/v1` |
| `http://localhost:11434/v1/` | `http://localhost:11434/v1` |
| `https://api.openai.com/v1` | `https://api.openai.com/v1` |

### API 密钥处理

- **API 密钥**字段已掩码。点击眼睛图标可显示您正在输入的内容。
- 密钥一旦保存，**就永远不会再以明文形式显示**。该字段会显示 _"API 密钥已配置——留空则保持不变"_，并出现一个绿色的 **API 密钥已配置** 标签。
- 要保留现有密钥，请在保存时将该字段留空。
- 要替换密钥，请输入新密钥并保存。
- 要删除密钥，请点击 **清除 API 密钥**。

:::warning 明文 HTTP

对于 `localhost` 和本地网络提供商，允许使用 `http://`。如果您使用 **非**本地的明文 `http://` URL，aiFetchly 会警告该连接未加密——对于任何远程提供商，请优先使用 `https://`。

:::

## 刷新模型

点击 **刷新模型** 以查询提供商的 `/models` 端点并填充**默认模型**下拉列表。此操作是可选的——您始终可以手动输入模型名称。

- 如果 `/models` 成功，返回的模型会被规范化并显示在下拉列表中。
- 如果 `/models` 失败（某些本地服务器未实现该端点），您会收到警告，但只要输入了**默认模型**，配置仍然有效。aiFetchly 会回退到手动输入的模型。
- 如果存在默认模型但无法加载列表，您仍然可以保存并聊天。

## 测试连接

在依赖某个提供商之前，请点击 **测试连接**。测试会按顺序验证以下内容：

1. Base URL 是有效的 `http:` 或 `https:` URL。
2. 提供商可访问。
3. `/models` 端点正常工作，**或者**已手动输入默认模型。
4. 使用一个极小的提示词成功完成非流式聊天补全。
5. 流式聊天补全成功（如果支持）。
6. 尽可能检测工具调用支持。

测试会发送一个最简提示词（例如要求模型回复 `pong`）。任何有效的补全都算作成功——aiFetchly 不要求精确的文本匹配，因为本地模型常常会附加格式。

结果显示为状态消息和**能力徽章**（见下文）。连接测试永远不会记录或显示您的 API 密钥。

:::note 第三方 API 可能按 token 计费

OpenAI、OpenRouter 和其他付费端点按 token 收费，因此每次测试连接只会发送一个非常小的请求。该测试仍会发起真实的 API 调用。

:::

## 能力徽章

连接测试完成后，能力徽章会描述您的提供商和模型能做什么：

| 徽章 | 含义 |
|-------|---------|
| **Models** | `/models` 端点可用。 |
| **Chat** | 非流式聊天补全正常工作。 |
| **Streaming** | 流式聊天补全正常工作。 |
| **Tools** | 模型支持工具调用。 |
| **Vision** | 模型接受图像输入。 |
| **Context** | 检测到/已覆盖的上下文大小（以 token 为单位，在可用时显示）。 |

每个徽章具有以下状态之一：

| 状态 | 颜色 | 含义 |
|-------|-------|---------|
| **支持** | 🟢 绿色 | 已验证可用。 |
| **不支持** / **失败** | 🔴 红色 | 已验证不可用，或测试失败。 |
| **未知** | 🟡 黄色 | 无法确定——请谨慎操作。 |

:::tip 当 Tools 不支持或未知时

如果您的提供商不（可靠地）支持工具调用，AI 聊天会自动使用保守的审批模式，并不会为普通聊天发送工具定义。依赖于工具的"需要工具"和"计划模式"工作流可能会被禁用或向您发出警告。要获得完整的工具/计划模式支持，请使用支持工具的模型或托管 aiFetchly。

:::

## AI 聊天如何使用您的提供商

一旦保存了有效的自定义提供商：

- **AI 聊天变为可用**——即使没有 aiFetchly AI 订阅。
- AI 聊天中的模型选择器旁边会出现一个**提供商指示器**（例如 `Local: Ollama`、`Local: LM Studio` 或 `Hosted`）。点击它会打开此设置页面。
- **模型选择器**会列出您提供商的模型（来自 `/models`，或者如果 `/models` 不可用，仅显示您配置的默认模型）。
- 聊天请求直接从应用后端发送到您的端点——从不从浏览器/渲染器发送。

如果提供商不可访问，AI 聊天会显示明确的提供商错误，而不是静默失败。

:::info 相关内容：AI Chat V2

提供商模式在各聊天界面之间共享。有关聊天体验本身，包括计划模式和上下文使用徽章，请参见 [AI Chat V2](../ai-outreach/ai-chat-v2)。

:::

## 安全与隐私

- **API 密钥在静态存储时加密**，并与配置的其余部分分开存储。
- 密钥保存后**永远不会以明文形式返回到 UI**——页面仅显示 `apiKeyConfigured: true/false`。
- **密钥永远不会被记录。** 调试和请求日志会脱敏处理 `Authorization` 头以及任何看起来像密钥的内容。
- **请求由应用后端发起**，而不是渲染器，因此凭据不会暴露给网页内容。
- **Base URL 仅被验证**为 `http:` 或 `https:`。

## 快速开始：Ollama

1. [安装 Ollama](https://ollama.com) 并拉取一个模型，例如 `ollama pull llama3.1`。
2. 打开 **设置 → AI 提供商**。
3. 选择 **自定义/本地提供商**。
4. 将**提供商预设**设置为 **Ollama**（会自动填写 `http://localhost:11434/v1`）。
5. 点击 **刷新模型** 并选择一个模型，或手动输入一个（例如 `llama3.1`）。
6. 点击 **测试连接** 进行确认，然后点击 **保存**。
7. 打开 AI 聊天——指示器显示为 `Local: Ollama`，您无需订阅即可聊天。

## 快速开始：OpenAI / OpenRouter

1. 打开 **设置 → AI 提供商**。
2. 选择 **自定义/本地提供商**。
3. 将**提供商预设**设置为 **OpenAI** 或 **OpenRouter**。
4. 将您的 **API 密钥** 粘贴到 API 密钥字段中。
5. 输入**默认模型**（例如 `gpt-4o-mini`，或一个 OpenRouter 模型 ID）。
6. 点击 **测试连接**，然后点击 **保存**。

## 故障排除

### 无法连接到提供商

**可能的原因：**
- 本地服务器未运行（检查 Ollama / LM Studio / vLLM 进程）。
- Base URL 或端口错误。
- 防火墙阻止了 localhost/局域网访问。

**解决方案：**
1. 启动提供商并确认它在浏览器中能响应（例如 `http://localhost:11434/v1/models`）。
2. 重新检查 Base URL 并运行 **测试连接**。
3. 对于 Docker 或 WSL 环境，请确保该提供商可从 aiFetchly 的网络环境中访问。

### 认证失败（401 / 403）

**可能的原因：**
- API 密钥缺失、错误或已过期。
- 该密钥无权访问所选模型。

**解决方案：**
1. 重新输入 API 密钥并保存。
2. 对于 OpenAI/OpenRouter，请确认密钥有效，并且对该模型有额度/权限。

### 所选模型不可用

提供商返回了"model not found"（未找到模型）。请从 **刷新模型** 列表中选择其他模型，或者将**默认模型**更新为该提供商实际提供的模型。

### 无法加载模型列表

某些本地服务器未实现 `/models`。这是预期情况——请在**默认模型**中手动输入模型名称并保存。聊天仍将正常工作。

### 聊天可用但工具/流式传输显示为不支持

并非所有本地模型都支持工具调用或流式传输。如果您需要这些功能，请切换到支持工具或流式的模型，或使用 **托管 aiFetchly**。参见 [能力徽章](#能力徽章)。

### 仅限托管的功能仍要求订阅

这是设计使然。自定义提供商仅解锁 AI 聊天——关键词生成、邮件模板生成、AI 恢复、重排和嵌入仍需要 aiFetchly AI 订阅。
