# AI Chat V2

AI Chat V2 是经过重新设计的 AI 助手。它保留了旧版 AI 营销助手所做的一切——知识库上下文、MCP 工具、AI Skills——并新增了更清爽的输入框、**计划模式**、**实时上下文用量徽章**、**内联计划批准**、**子智能体**以及**文件操作面板**。

V2 与旧版助手并行运行。如果 V2 的功能开关已开启，点击聊天图标（或按下 `Ctrl/Cmd + K`）会打开 V2。

## V2 的新功能

| 功能 | 作用 |
|---|---|
| **计划模式** | 让 AI 起草一份分步计划，并在任何工具运行之前先行批准。 |
| **上下文用量徽章** | 实时的 `CTX %` 指示器，让您了解距离模型的上下文上限还有多远。 |
| **内联计划批准** | 计划卡片在消息流中渲染，提供 批准 / 拒绝 / 请求修改 操作。 |
| **子智能体** | AI 可以派遣一名专家（例如 Lead Researcher），拥有独立的工具预算和输出架构。 |
| **文件操作面板** | 输入框上方的可折叠面板，列出 AI 刚刚读取或修改的每一个文件。 |
| **流式重连** | 如果数据流中断，V2 会自动重试并显示重连指示器，而不是悄无声息地卡住。 |
| **正在输入指示器** | 在 AI 思考或运行工具时可见。 |
| **停止按钮** | 取消正在进行的流式响应以及任何运行中的工具调用。 |
| **斜杠命令** | 在输入框中输入 `/` 即可执行操作（`/clear`、`/status`、`/plugin`），或展开您自己创建的可复用提示模板。参见 [斜杠命令](./slash-commands)。 |
| **语音** | 说出您的消息，并聆听 AI 的回复——设备端语音转文字与文字转语音。参见 [语音](#语音)。 |

## 打开 V2

1. 点击页眉中的**聊天图标**，或按下 `Ctrl + K`（Windows/Linux）/ `Cmd + K`（macOS）。
2. 如果已启用 V2，V2 面板会从右侧滑入。
3. 如需在本次会话中切回旧版助手，请在 `localStorage` 中关闭 V2 开关（`aifetchly:aiChatV2Enabled`）。

:::tip 调整面板大小

拖动面板的左边缘即可调整大小。面板会为本次会话记住其宽度。

:::

## 聊天模式与计划模式

使用输入框上方的**模式下拉菜单**在两种模式之间切换。

### 聊天模式（默认）

行为与旧版助手一致：您提问，AI 回答，工具按需运行。最适合问答、内容起草和快速查询。

### 计划模式

计划模式在 AI 执行任何破坏性或长时间运行的操作之前，增加一道批准关卡。

1. 将模式选择器切换到 **计划**。
2. 描述目标（例如"研究这 5 个潜在客户并为每个客户起草外联内容"）。
3. AI 起草一份计划——一份包含其打算执行步骤的 markdown 文档。
4. 计划以内联卡片形式呈现，附带状态、版本和目标。
5. 选择：
   - **批准** —— AI 立即开始执行该计划。
   - **拒绝** —— 附上理由发送；AI 会停下来并修订计划。
   - **请求修改** —— 要求修改但不当场拒绝。
6. 执行过程中，AI 会将进度和工具输出流式回传到对话中。

:::info 何时使用计划模式

当某个任务要运行大量工具调用、修改文件、发送外联内容或消耗较多点数时，请开启计划模式。如果只是"什么样的标题更好？"之类的问题，请保持在聊天模式即可。

:::

### 计划状态

| 状态 | 含义 |
|---|---|
| **Draft** | AI 仍在编写计划。 |
| **Awaiting Answer** | AI 在最终确定之前提出了一个澄清性问题。 |
| **Awaiting Approval** | 计划已就绪——等待您 批准 / 拒绝。 |
| **Approved** | 您已批准；执行进行中或已完成。 |
| **Rejected** | 您已带反馈拒绝。 |
| **Completed** | 计划已成功完成。 |
| **Cancelled** | 计划已被取消（由您或由错误触发）。 |

## 上下文用量徽章

在模式选择器旁边，一个小徽章会显示 **`CTX <percent>%`**。这是当前对话正在使用的模型上下文窗口的比例。

| 程度 | 区间 | 含义 |
|---|---|---|
| 低（灰色） | 0–49% | 空间充裕。 |
| 中（黄色） | 50–79% | 渐趋饱满。 |
| 高（橙色） | 80–94% | 建议尽快开启新对话。 |
| 严重（红色） | 95–100% | 接近上限——长消息可能被截断或自动压缩。 |

当徽章达到"严重"时，请开启新对话，或让 AI 压缩本次会话（见下文）。

## 子智能体

子智能体是主 AI 可以派遣的一种受限专家，用于处理边界明确的工作。每个子智能体都有：

- 一个针对其工作调优的**系统提示词**
- 一个**工具允许列表**（AI 可用工具的子集）
- 一个**输出架构**（子智能体必须返回与该架构匹配的 JSON）
- **预算**：最大工具调用次数、最长运行时间、最大延续轮数

### 内置：Lead Researcher

Lead Researcher 子智能体用于为某个潜在客户收集公开的商业背景。它被允许使用 `google_search`、`scrape_urls_from_search_engine` 和 `knowledge_library_search`。它返回一个结构化对象，包含：

- `businessSummary`
- `productsOrServices`
- `targetCustomerHints`
- `marketSignals`
- `sourceUrls`（每条陈述都必须有来源佐证）
- `confidence`（0–1）

您不会直接调用子智能体——由主 AI 决定何时派遣。要引导它，可以这样请求：*"使用 Lead Researcher 研究 acme.com 上的这个潜在客户。"*

:::tip 子智能体是受限的

子智能体只能使用其允许列表中的工具。它无法发送邮件、发布社交媒体内容，也无法修改记录。它的输出是给主 AI 据以行动的证据——而不是它自己执行的动作。

:::

## 文件操作面板

输入框上方的一个可折叠面板会显示 AI 在当前轮次中刚刚读取或写入的每一个文件。每个条目都是一个可点击的小块；点击可打开该文件（对于已编辑的文件则是 diff 视图）。

您可以用它来：

- 在信任结果之前，核对 AI 实际修改了什么。
- 直接跳转到 AI 提到的某个文件，无需费力查找。
- 对 AI 编辑了错误的文件翻个白眼。（确实会发生。）

## V2 中的 Skills、MCP 和知识库

V2 使用与旧版助手相同的 Skills、MCP 服务器和知识库：

- **[AI Skills](./ai-skills)** —— 从 Skills 页面或通过插件管理器安装；在 V2 中会自动作为工具出现。
- **[MCP 工具](./mcp-tools)** —— 点击 V2 页眉中的 **MCP 工具** 按钮来添加或管理外部 MCP 服务器。
- **[知识库](./knowledge-library)** —— 与旧版助手相同的方式切换 RAG 上下文。

## 权限与"始终允许"

当 AI 想要运行需要批准的工具时，V2 会显示一张内联批准卡片，提供两个选项：

- **允许一次** —— 仅本次运行。
- **始终允许** —— 记住此决定。

对于大多数 Skill 类别，**始终允许**会被永久记住。对于 **shell 执行**类别，出于安全考虑，**始终允许**仅对**当前会话**有效——下次重启应用时，AI 会再次询问。

:::warning shell 始终仅限会话范围

AI 只能在获得您明确批准的情况下运行 shell 命令。即使您对 shell 点击了"始终允许"，该权限也会在您关闭应用时失效。这是有意为之。

:::

## 流式、停止和重连

- **正在输入指示器**：AI 正在生成回复或运行工具时会出现一个小转圈。
- **停止按钮**：在流式响应期间取代发送按钮。点击它可取消响应以及任何进行中的工具调用。UI 会立即重置。
- **重连**：如果响应中途数据流中断，V2 会自动重试并显示重连指示器。如果重连失败，最后一条不完整的消息会保留显示，便于您决定是否重发。

## 压缩（自动摘要）较长的会话

当对话接近上下文上限时，V2 可以压缩会话：它将较早的轮次摘要为更短的形式，让对话能够在不丢失关键上下文的情况下继续进行。压缩会作为一项独立的后台任务运行；发生时您会看到一条提示。

## 斜杠命令

在输入框开头输入 `/` 即可打开斜杠命令菜单。`/clear`、`/help`、`/status`、`/plugin` 等内置命令会即时执行，您也可以将自己的可复用提示模板（例如 `/outreach <website>`）作为 Markdown 文件创建在 `~/.aifetchly/commands/` 中。完整的命令列表、自定义命令编写以及键盘快捷键，请参见专门的 **[斜杠命令](./slash-commands)** 页面。 对于有界的自主工作，可使用 **`/goal`** 设定一个可验证的目标，并用 **`/loop`** 朝该目标运行迭代；要监控随时间变化的事情，可用 **`/loop 5m <prompt>`** 在同一个聊天里按固定间隔重复运行某个提示词 —— 参见 [目标与循环命令](./goal-and-loop)。

## 语音

AI Chat V2 支持**语音输入**（语音转文字）和**语音回复**（文字转语音）。两者都通过 `sherpa-onnx` 语音引擎**在您的设备上**运行——您的麦克风音频在本地处理，不会发送到服务器。

语音默认关闭。请在 **[AI Provider → 语音设置](../settings/ai-provider#语音设置)** 中开启。

### 对 AI 说话（语音输入）

当启用语音输入后，输入框中会出现一个**麦克风按钮**：

1. 点击麦克风以**开始录音**（按键说话）。再次点击（或点击停止控件）即可停止。
2. 您说话时，输入框会显示录音状态。录音会在达到最大时长（默认 60 秒）时自动停止。
3. 您停止后，aiFetchly 会在本地将您的语音转录为文字，并将其作为可编辑文本插入到输入框中。
4. 检查或编辑转录文本，然后照常发送。

:::tip 自动发送

在语音设置中启用 **自动发送语音转录**，可在转录完成的瞬间立即发送转录内容，跳过检查环节。

:::

转录文本会成为一条普通的聊天消息——以文字形式存储和发送，与您手动键入的消息完全一致。

首次使用语音输入时，aiFetchly 会下载语音模型（一次性下载）。如果模型尚未安装，麦克风按钮会显示**缺失模型**状态，并提供安装操作。

### 聆听 AI 回复（语音回复）

聊天页眉中的**音量按钮**用于开启或关闭语音回复：

- **开启**（高亮）：AI 的文字回复会在流式生成时同步朗读。
- **关闭**：静音——回复仅以文字形式呈现。

aiFetchly 只朗读自然语言回复——不会朗读代码块、工具调用、表格或权限提示。

:::note 仅在语音输入后才朗读

在语音设置中，您可以将 AI 设置为**只朗读对您语音消息的回复**（实现免提的来回对话），而不是每条回复都朗读。

:::

在 AI 正在朗读时，**停止朗读**控件可让您中断播放。开始新的语音录音、切换对话，或点击聊天的**停止**按钮，也会中断朗读。

### 语音不会授予聊天权限

语音识别与合成在本地完成且免费，但要发送消息并获得回复，您仍然需要聊天权限——要么是 aiFetchly AI 订阅（托管版），要么是一个可用的[自定义/本地服务商](../settings/ai-provider)。如果没有可用的聊天模型，您的语音仍可在本地转录，但在聊天可用之前无法发送该消息。

## 充分利用 V2 的小贴士

### 建议 ✅

- 对多步或破坏性任务**使用计划模式**。
- **关注 CTX 徽章**——在它变红之前开启新对话。
- 对您信任的 Skill 使用"始终允许"来减少提示（shell 除外）。
- 在任何工具密集的轮次之后**检查文件操作面板**。
- 当您需要结构化的潜在客户数据时，**按名称引用 Lead Researcher**。

### 不建议 ❌

- **不要盲目批准 shell 执行**——先读一下命令。
- **不要让 200 轮的会话一直延续**——当 CTX 徽章攀升时请开启新对话。
- **不要指望子智能体去发送外联内容**——它们只负责收集并返回数据。
- **不要忽视计划卡片**——批准它意味着您错失了最后一次调整方向的机会。

## 故障排查

### 计划模式无法激活

- 确认模式下拉菜单已设置为 **计划**。
- 如果下拉菜单缺失，说明 V2 开关已关闭。请通过 `localStorage` 重新启用。

### AI 没有派遣 Lead Researcher

- AI 仅在判断为必要时才会派遣子智能体。请明确请求：*"对这项工作使用 Lead Researcher。"*
- 子智能体仅在其所需工具（Google 搜索、URL 抓取器、知识库）已启用时才会运行。

### 上下文徽章持续为红色

- 开启新对话，或让自动压缩运行。
- 如果是知识库注入的文本过多，请禁用 RAG 上下文。

### 工具审批在"始终允许"之后仍反复提示

- 您正在使用 **shell** 类 Skill。Shell 批准按设计仅对当前会话有效。
- 该 Skill 可能已被重新安装，这会重置其权限授予。
