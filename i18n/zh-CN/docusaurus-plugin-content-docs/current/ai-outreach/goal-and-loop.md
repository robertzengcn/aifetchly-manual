# 目标与循环命令

**`/goal`** 和 **`/loop`** 这两个斜杠命令让你为 AI Chat V2 助手设定一个持久目标，然后以有界、可验证的步骤朝该目标推进，或按固定间隔重复运行某个提示词 —— 而不是逐轮地手动提示它。

`/goal` 捕获“完成”的含义，包括明确、可检查的验收标准。随后 `/loop` 有 **两种模式**：

- **目标循环** —— `/loop 5` 朝活动目标运行有限次数的自主迭代，在目标可被标记为完成之前，收集最新证据并验证每一个标准。
- **计划循环** —— `/loop 5m check the deployment` 按固定间隔（每 5 分钟、每 2 小时……）重复运行一个提示词，让你能监控随时间变化的工作。每一次执行和每一条回复都留在同一个会话里。

:::info 仅在 AI Chat V2 中

`/goal` 和 `/loop` 是 **[AI Chat V2](./ai-chat-v2)** 输入框中可用的内置斜杠命令。它们需要开启了 AI 的有效 aiFetchly 订阅，并复用 AI Chat V2 既有的 [计划模式](./ai-chat-v2)、工具审批和工作区安全边界。

:::

## `/loop` 的两种模式

你得到哪种模式，取决于 `/loop` 后面输入的是什么：

| 模式 | 命令 | 作用 | 前提 |
|---|---|---|---|
| **目标循环** | `/loop <maxIterations>` | 朝活动目标运行至多该次数的自主迭代。 | 已用 `/goal` 设定的活动目标。 |
| **计划循环** | `/loop <duration> <prompt>` | 按固定间隔、在同一个会话中重复运行该提示词。 | 一个非空的提示词。 |
| **计划循环控制** | `/loop status`·`/loop pause`·`/loop resume`·`/loop stop` | 管理当前会话的计划循环。 | 当前会话存在活动的计划循环。 |

纯整数（`/loop 5`）始终表示目标循环。时长（`/loop 5m …`）始终表示计划循环。两种模式互不干扰。

## `/goal` —— 设定一个持久目标

### 语法

```text
/goal <objective>
```

示例：

```text
/goal Build a Facebook campaign scraper and verify it works
```

### 会发生什么

1. 该目标成为当前会话的 **活动目标**。
2. AI Chat 进入 **计划模式**。当目标含糊时，助手会提出澄清问题。
3. 助手提出一个计划，其中包含一个或多个 **验收标准** —— 定义“完成”含义的具体、可检查的条件。
4. 你通过常规的计划模式审批流程来批准（或拒绝或要求修改）该计划。
5. 该目标在会话中保持活动，直到被 **完成**、**阻塞** 或 **取消**。

再次运行 `/goal` 会替换当前的活动目标。

### 验收标准与验证

每个验收标准都会被自动验证 —— 目标不会仅仅因为助手说完成就算完成。每个标准都有一种验证方式：

| 方式 | 如何检查该标准 |
|---|---|
| **command** | 一条命令成功退出，可选择匹配预期的退出码或输出模式。 |
| **file** | 存在预期的文件或项目状态，例如某个文件已存在或已变更。 |
| **manual** | 循环暂停并请你确认。 |
| **llm** | 由一个独立的验证器评估所收集的证据，用于无法确定性检查的标准。 |

一个标准可标记为 **必需** 或可选。只有在 **每一个必需标准** 都凭新证据通过时，目标才能被标记为完成。

:::tip 写出可验证的目标

当“完成”是应用能够验证的事情时，`/goal` 效果最好。像“构建抓取器并验证它可用”这样的目标 —— 配上“测试命令以 0 退出”这样的标准 —— 远比“把抓取器做好”这类主观目标可靠。

:::

## 目标循环 —— `/loop <maxIterations>`

### 语法

```text
/loop <maxIterations>
```

`<maxIterations>` 是一个 **1 到 10** 的整数。请显式提供 —— 如果你省略它或传入超出该范围的值，`/loop` 会要求一个有效的次数。目标循环还 **要求存在活动目标**；如果尚未设定，它会提示你先运行 `/goal`。

示例：

```text
/loop 5
```

### 每次迭代做什么

每次迭代都运行相同的 观察 → 行动 → 验证 循环：

```text
观察当前状态
  → 助手提出一个有界的下一步动作
  → 已批准的工具执行它
  → 系统收集最新证据
  → 先运行确定性检查
  → 由独立验证器评估剩余标准
  → 循环继续、完成、阻塞或请求输入
```

循环运行时，进度会显示在会话中 —— 迭代次数、收集到的证据摘要，以及每个标准的验证结果。

### 目标循环何时停止

目标循环永远不会无限运行。只要满足以下任一条件，它就会立即停止：

- 你按下 **Stop**。
- 达到最大迭代次数。
- 达到单次运行的时长上限。
- 目标 **完成** —— 每个必需标准都凭新证据通过。
- 某个工具需要你的审批，或计划模式需要审批。
- 助手需要向你提问。
- 同一失败重复达到足够次数，目标因此变为 **阻塞**。
- 验证器返回 `blocked` 或 `needs_user_input`。
- 发生不可恢复的错误。

### 如何判定完成

执行工作的助手 **不能凭声明把自己的目标标记为完成**。完成需要 **新鲜的、针对具体标准的证据** —— 例如，在最近一次代码改动 *之后* 通过的测试，而不是之前的陈旧结果。

确定性检查（命令、文件状态）先运行。独立的 LLM 验证器只用于无法确定性检查的标准，并返回与具体证据绑定的结构化判定（`satisfied`、`not_satisfied`、`blocked`、`needs_user_input`） —— 绝不是一段自由文本的“完成”。

## 计划循环 —— `/loop <duration> <prompt>`

计划循环按固定间隔重复运行一个提示词，并把 **每一次执行和每一条回复都保留在同一个会话里**。它不需要目标，也绝不会为每次执行新建一个聊天。

```text
/loop 5m check if the deployment finished and tell me what happened
```

用它来监控随时间变化的工作 —— 部署、导入、营销活动的回复、抓取任务、外部审批 —— 而不必手动重复发送同一个提示词。

### 何时使用计划循环

- **部署监控** —— `/loop 5m check if deployment 218 finished and summarize the result`
- **营销活动监控** —— `/loop 1h --times 8 -- summarize new campaign replies and flag urgent leads`
- **长时间运行的导入** —— `/loop every 15m --for 3h -- check the contact import and report new failures`

你可以在两次执行之间继续在同一个会话里聊天。下一次计划执行会把你的交互消息作为上下文的一部分纳入。

### 语法

**简写形式** —— 时长后跟提示词：

```text
/loop <duration> <prompt>
```

```text
/loop 5m check if the deployment finished and tell me what happened
/loop 2h summarize any new campaign replies
```

**规范形式** —— 用于显式上限，在提示词前用 `--` 分隔符：

```text
/loop every <duration> [--times <count>] [--for <duration>] -- <prompt>
```

```text
/loop every 5m --times 12 -- check if the deployment finished
/loop every 1h --for 8h -- summarize new campaign replies
/loop every 30m --times 6 --for 3h -- check the import status
```

当同时给出 `--times` 和 `--for` 时，循环在先达到的上限处停止。规范形式要求 `--` 分隔符，这样包含“times”或“for”等词的提示词文本不会被误判为选项。

### 时长规则

间隔使用两个单位：

- `m` —— 分钟
- `h` —— 小时

规则：

- 最小间隔：**1m**。最大间隔：**24h**。
- 数值必须是单位前不带空格的正整数 —— `5m`、`2h`、`30m`。
- 单位不区分大小写（`5M` 与 `5m` 相同）。
- 小数、符号、科学计数法、空格和未知单位都会被拒绝。

被拒绝的示例：

```text
/loop 0m check deployment
/loop -5m check deployment
/loop 1.5h check deployment
/loop 5 minutes check deployment
/loop 5m
/loop 5d check deployment
```

### 默认与最大上限

计划循环 **始终是有界的** —— 受执行次数和有效期限制。

| 上限 | 默认 | 最大 |
|---|---|---|
| 执行次数（`--times`） | 24 | 100 |
| 有效期（`--for`） | 24 小时 | 7 天 |

简写形式 `/loop 5m <prompt>` **最多运行 24 次、最长 24 小时** —— 以先到者为准。按 5 分钟的间隔，通常是执行次数先结束循环。可在规范形式中用 `--times` 和 `--for` 把任一上限提高到最大值。

### 启动时会发生什么

命令被接受后，AI Chat V2 会在同一个会话中追加可见的斜杠命令和一条简短确认，例如：

```text
Scheduled every 5 minutes. Maximum 24 runs or 24 hours. Next run: 14:35.
```

第一次执行发生在你启动循环的 **一个间隔之后** —— 它不会立即运行。确认信息会告知下次运行时间，让你清楚第一次检查何时发生。

### 计划执行保留在同一个会话里

每一次执行都会成为会话中一个正常的、持久的回合：

1. 计划提示词被追加到原始会话。
2. AI 接收该会话已有的历史和上下文。
3. 助手的回复被追加到 **同一个** 会话。
4. 如果该会话处于打开状态，它会刷新并实时流入回复。
5. 如果打开的是另一个会话，aiFetchly 会更新原始会话的预览和未读指示，而不会把你从当前工作里带走。

计划的用户回合会带有一个小时钟图标和一个运行标签（例如 *Scheduled — Run 2*），以便与你手动输入的消息区分。

:::tip 一个会话，一条时间线

因为每次执行共享同一份记录，后续执行可以建立在之前的观察之上。你也可以在两次执行之间追问，下一次计划执行会把它纳入。

:::

### 状态、暂停、恢复与停止

当一个会话存在活动的计划循环时，聊天头部会显示一个 **状态标签**，展示循环状态并提供紧凑的控制：

- **Pause** —— 阻止新的执行启动。历史会被保留。
- **Resume** —— 计算下一次运行时间并继续。它不会重放错过的执行。
- **Stop loop** —— 阻止任何未来的执行。当前正在运行的执行会被允许完成。
- **Stop current run** —— 仅中止当前正在运行的那一次执行；后续执行按计划继续。

同样的操作也以命令形式提供，并仅作用于当前会话：

```text
/loop status
/loop pause
/loop resume
/loop stop
```

这些操作只影响当前会话的循环，不能停止或修改另一个会话里的循环。所有控制操作都是幂等的 —— 执行两次和执行一次效果相同。

### 计划循环的生命周期

计划循环会经历以下状态：

| 状态 | 含义 |
|---|---|
| **active** | 等待下一次执行。 |
| **running** | 某次执行正在进行。 |
| **paused** | 已暂停 —— 在你恢复之前不会启动新的执行。 |
| **expired** | 达到了执行次数或有效期上限。 |
| **failed** | 反复的执行失败或不可恢复的错误停止了循环。 |
| **stopped** | 你停止了它（或会话被删除）。 |

### 重启与休眠后的恢复

计划循环由持久化的调度器支撑，因此能挺过应用重启或系统休眠：

- 如果没有错过任何执行，则保留下次运行时间。
- 如果在应用关闭或休眠期间错过了执行，**最多补跑一次** —— 绝不会按每个错过的间隔来一次爆发式重放。
- 如果循环的有效期在离线期间已过期，则仅被标记为过期。
- 墙钟时间、夏令时和时区变化绝不会产生重复执行。

数据库是唯一事实来源。如果错过了一次刷新通知，重新打开会话即可重新加载完整且正确的历史。

### 上限与安全

| 上限 | 值 |
|---|---|
| 间隔（`/loop <duration>`） | 1m – 24h |
| 执行次数 | 默认 24，最大 100 |
| 有效期 | 默认 24h，最大 7 天 |
| 每个会话的活动计划循环 | 一个 |
| 单次运行时长上限 | 10 分钟 |
| 循环失败前的连续失败次数 | 3 |

始终适用的安全保证：

- 计划循环 **始终是有界的** —— 受次数和有效期约束。它永远不会无限运行。
- **始终可取消**（Stop）。
- **交互回合优先。** 当一次执行到期时你正在会话中，计划执行会被推迟或合并 —— 它绝不会打断你的回合。
- 执行 **绝不重叠**。如果一次执行比其间隔更长，到期的执行会被合并为一次待执行。
- **工具策略是任务级作用域的。** 计划执行是无人值守的，因此只有显式批准的工具可用，高影响工具保持阻止状态。你的交互式“Always Allow”选择 **不会** 扩大计划循环能做的事。
- **AI 启用**、工作区和文件安全边界继续适用。
- 循环 **不会** 从助手的措辞（“done”、“complete”）推断完成。它只在达到上限、失败阈值、显式 Stop 或会话已消失时停止。

:::warning 清空或删除会话会停止其循环

如果一个会话存在活动的计划循环，清空其历史时会要求你确认循环也将被停止，删除会话时会先停止循环。aiFetchly 绝不会让一个无人值守的循环针对已删除的会话继续运行，也绝不会重新创建已删除的会话。

:::

## 目标与循环的状态

一个目标会经历以下状态：

| 状态 | 含义 |
|---|---|
| **draft** | 目标正在计划模式中定义。 |
| **active** | 已批准，等待运行或继续。 |
| **running** | 一个 `/loop` 正在执行一次迭代。 |
| **complete** | 所有必需标准都凭新证据通过。 |
| **blocked** | 反复失败或未解决的阻塞 —— 需要你关注。 |
| **needs_user_input** | 循环暂停以向你提问或获取确认。 |
| **failed** | 不可恢复的错误结束了运行。 |
| **cancelled** | 你停止了它。 |

## 上限与安全

| 上限 | 值 |
|---|---|
| 目标循环迭代次数（`/loop <N>`） | 1–10（请显式提供） |
| 单次运行时长上限 | 10 分钟（默认） |
| 变为 **阻塞** 前的相同失败次数 | 3 |
| 每个会话的活动目标 | 一个（设定新目标会替换旧目标） |

始终适用的安全保证：

- 每个循环 **始终是有界的** —— 绝不无限。
- **始终可取消**（按下 Stop）。
- **AI 启用**、工具审批模式、计划模式以及工作区/文件安全边界在循环期间都继续适用。
- 破坏性动作、新增依赖、身份认证变更及其他高影响副作用，即使在循环中途也仍需通过常规审批边界。
- 展示给验证器的证据和日志是限定范围、限定大小、并脱敏过密钥的，且被当作不可信数据处理 —— 绝不当作指令。

## 小贴士

### 建议 ✅

- **目标循环前先设定目标** —— `/loop 5` 始终需要一个活动的 `/goal`。
- **让目标可验证** —— 优先选择应用可检查的标准（命令、文件），而非主观标准。
- **用较小的次数开始目标循环**（`/loop 3`），在投入更多前先检视进度。
- **保持计划模式开启** —— 用于会修改文件、发送外联或运行大量工具调用的目标。
- **用计划循环做监控** —— 任何随时间变化的东西（部署、导入、营销活动）都很合适。
- **保持聊天访问可用** —— 计划循环在反复出现 `AI_DISABLED` 失败后会暂停。

### 不建议 ❌

- **不要期望无界自主** —— 目标循环始终需要显式的 1–10 次数，计划循环始终有执行次数和有效期上限。
- **不要轻信一句“done”** —— 目标完成是证据驱动的；如果有必需标准未通过，目标就不算完成。
- **不要期望应用关闭时计划循环仍在运行** —— 它只在 aiFetchly 打开时运行，并在重启时最多补跑一次。
- **不要期望交互式“Always Allow”适用于计划执行** —— 计划的工具权限是任务级作用域且更严格。

## 故障排查

| 症状 | 可能原因 | 处理方法 |
|---|---|---|
| *“Set a goal first with /goal”* | 当前会话没有活动目标 | 先运行 `/goal <objective>` 并批准计划。 |
| *“Please provide an iteration count”* | 调用 `/loop` 时没有数字 | 提供一个次数，例如 `/loop 5`。 |
| *“Iteration count must be between 1 and 10”* | 次数缺失、为零或大于 10 | 使用 1 到 10 的整数。 |
| *“The interval must be between 1 minute and 24 hours”* | 时长小于 1m、大于 24h 或格式错误 | 使用整数的 `m` 或 `h` 值，如 `5m` 或 `2h`。 |
| *“A prompt is required for a scheduled loop”* | `/loop 5m` 没有提示词文本 | 在时长后、或在规范形式的 `--` 分隔符之后添加提示词。 |
| *“No active scheduled loop for this conversation”* | 没有运行中的循环却执行了 `/loop pause/resume/stop` | 先用 `/loop <duration> <prompt>` 启动一个循环。 |
| 计划循环提前停止 | 达到执行次数或有效期上限，或连续失败 3 次 | 在状态标签查看原因。用 `--times`/`--for` 提高上限，或解决失败后启动新循环。 |
| 目标 **阻塞** | 同一失败重复出现（默认 3 次） | 在会话中阅读失败原因，解决根本原因后再次 `/loop` 或调整目标。 |
| 目标停留在 **needs_user_input** | 循环在等待你的回答或审批 | 回应提问或批准待处理的动作。 |
| 一次计划执行没有在精确时刻发生 | 聊天期间执行被推迟、过长时被合并、或休眠后补跑一次 | 这是预期行为。查看状态标签和下次运行时间。 |
