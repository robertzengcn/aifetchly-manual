# 目标与循环命令

**`/goal`** 和 **`/loop`** 这两个斜杠命令让你为 AI Chat V2 助手设定一个持久目标，然后让它以有界、可验证的步骤持续朝该目标推进 —— 而不是逐轮地手动提示它。

`/goal` 捕获“完成”的含义，包括明确、可检查的验收标准。随后 `/loop` 朝该目标运行有限次数的自主迭代，在目标可被标记为完成之前，收集最新证据并验证每一个标准。

:::info 仅在 AI Chat V2 中

`/goal` 和 `/loop` 是 **[AI Chat V2](./ai-chat-v2)** 输入框中可用的内置斜杠命令。它们需要开启了 AI 的有效 aiFetchly 订阅，并复用 AI Chat V2 既有的 [计划模式](./ai-chat-v2)、工具审批和工作区安全边界。

:::

## 两个命令的关系

| 命令 | 作用 | 前提 |
|---|---|---|
| `/goal <objective>` | 创建或替换当前会话的活动目标并进入计划模式。 | 非空的目标。 |
| `/loop <maxIterations>` | 朝活动目标运行至多该次数的自主迭代。 | 已用 `/goal` 设定的活动目标。 |

一个典型流程：

```text
/goal Build a Facebook campaign scraper and verify it works
（在计划模式中批准该计划及其验收标准）
/loop 5
```

## `/goal` — 设定一个持久目标

### 语法

```text
/goal <objective>
```

示例：

```text
/goal Build a Facebook campaign scraper and verify it works
```

### 会发生什么

1. 该目标成为当前会话的**活动目标**。
2. AI Chat 进入**计划模式**。当目标含糊时，助手会提出澄清问题。
3. 助手提出一个包含一个或多个**验收标准**的计划 —— 即定义“完成”含义的、具体可检查的条件。
4. 你通过正常的计划模式审批流程来批准（或拒绝或要求修改）该计划。
5. 该目标会一直保持活动，直到被**完成**、**阻塞**或**取消**。

再次运行 `/goal` 会替换当前的活动目标。

### 验收标准与验证

每个验收标准都会被自动验证 —— 目标不会仅仅因为助手说完成就算完成。每个标准都有一个验证方式：

| 方式 | 如何检查该标准 |
|---|---|
| **command** | 某条命令成功退出，可选地匹配预期的退出码或输出模式。 |
| **file** | 存在预期的文件或项目状态，例如某文件存在或已更改。 |
| **manual** | 循环暂停并请求你确认。 |
| **llm** | 由一个独立的验证器针对无法确定性检查的标准评估所收集的证据。 |

标准可标记为**必需**或可选。只有当**每一个必需标准**都以最新证据通过时，目标才能被标记为完成。

:::tip 编写可验证的目标

当“完成”是应用能够验证的事情时，`/goal` 效果最好。像“构建抓取器并验证它可用”这样的目标（附带“测试命令以退出码 0 结束”这类标准），远比“把抓取器做好”这类主观目标可靠。

:::

## `/loop` — 运行有界迭代

### 语法

```text
/loop <maxIterations>
```

`<maxIterations>` 是一个 **1 到 10** 的整数。请显式提供 —— 如果你省略它或传入超出该范围的值，`/loop` 会要求一个有效的次数。`/loop` 还**要求存在活动目标**；如果你尚未设定，它会提示你先运行 `/goal`。

示例：

```text
/loop 5
```

### 每次迭代做什么

每次迭代都运行相同的 观察 → 行动 → 验证 循环：

```text
观察当前状态
  → 助手提出一个有界的下一步动作
  → 已批准的工具执行它
  → 系统收集最新证据
  → 先运行确定性检查
  → 独立验证器评估剩余标准
  → 循环继续、完成、阻塞或请求输入
```

循环运行时，进度会显示在会话中 —— 迭代次数、所收集证据的摘要，以及逐标准的验证结果。

### 循环何时停止

`/loop` 永远不会无限运行。只要以下任一条件成立，它就会停止：

- 你按了 **Stop**。
- 达到最大迭代次数。
- 达到单次运行的时间限制。
- 目标**完成** —— 每个必需标准都以最新证据通过。
- 某个工具需要你的批准，或计划模式需要批准。
- 助手需要向你提问。
- 同一失败重复达到足够次数，于是目标变为**阻塞**。
- 验证器返回 `blocked` 或 `needs_user_input`。
- 发生不可恢复的错误。

### 完成如何决定

执行工作的助手**不能仅凭声明把自己的目标标记为完成**。完成需要**针对每个标准的最新证据** —— 例如，一项在最近一次代码更改*之后*通过的测试，而不是之前陈旧的结果。

确定性检查（命令、文件状态）会先运行。独立的 LLM 验证器仅用于无法确定性检查的标准，并且它返回结构化的判定（`satisfied`、`not_satisfied`、`blocked`、`needs_user_input`），这些都绑定到具体证据 —— 绝不是一段自由文本的“done”。

## 目标与循环的状态

目标会经历以下状态：

| 状态 | 含义 |
|---|---|
| **draft** | 目标正在计划模式中定义。 |
| **active** | 已批准，等待运行或继续。 |
| **running** | 一个 `/loop` 正在执行一次迭代。 |
| **complete** | 所有必需标准都以最新证据通过。 |
| **blocked** | 反复失败或存在未解决的阻塞 —— 需要你关注。 |
| **needs_user_input** | 循环暂停以向你提问或获得确认。 |
| **failed** | 一个不可恢复的错误结束了本次运行。 |
| **cancelled** | 你停止了它。 |

## 限制与安全

| 限制 | 取值 |
|---|---|
| 迭代次数（`/loop`） | 1–10（请显式提供） |
| 单次运行时间上限 | 10 分钟（默认） |
| **阻塞**前的相同失败次数 | 3 |
| 每个会话的活动目标数 | 一个（设定新目标会替换旧目标） |

始终适用的安全保证：

- 循环始终是**有界的** —— 不会无限。
- 始终**可取消**（按 Stop）。
- AI 启用、工具审批模式、计划模式以及工作区/文件安全边界，在循环期间都继续生效。
- 破坏性操作、新增依赖、身份验证变更以及其他高影响副作用，即使是在循环中，仍需经过正常的审批边界。
- 展示给验证器的证据和日志都会被限定范围、限制大小、脱敏机密信息，并作为不可信数据对待 —— 绝不作为指令。

## 提示

### ✅

- **循环前先设定目标** —— `/loop` 始终需要一个活动的 `/goal`。
- **让目标可验证** —— 优先选择应用能检查的标准（命令、文件），而非主观标准。
- **从较小次数开始**（`/loop 3`），在投入更多之前先查看进展。
- **对于会修改文件、发送外联或运行大量工具调用的目标，保持计划模式开启。**

### ❌

- **不要期望无界自主** —— `/loop` 始终需要显式的 1–10 次数。
- **不要轻信一句“done”** —— 完成是基于证据的；如果某个必需标准未通过，目标就没有完成。

## 故障排查

| 症状 | 可能原因 | 处理方法 |
|---|---|---|
| *"Set a goal first with /goal"* | 当前会话没有活动目标 | 先运行 `/goal <objective>` 并批准计划。 |
| *"Please provide an iteration count"* | `/loop` 未带数字被调用 | 提供一个次数，例如 `/loop 5`。 |
| *"Iteration count must be between 1 and 10"* | 次数缺失、为零或大于 10 | 使用 1 到 10 的整数。 |
| 目标**阻塞** | 同一失败重复出现（默认 3 次） | 在会话中阅读失败原因，解决根因，然后再次运行 `/loop` 或调整目标。 |
| 目标停留在 **needs_user_input** | 循环在等待你的回答或批准 | 回应该提示或批准待处理操作。 |
| 循环提前停止 | 需要批准、计划批准或回答问题 | 批准待处理项并再次运行 `/loop` 以继续。 |
