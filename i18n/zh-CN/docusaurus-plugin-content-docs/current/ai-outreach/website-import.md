# 将网站导入知识库

**Import Website（导入网站）** 功能让你可以直接通过 URL 将公开网页转换为可搜索的知识库文档，无需先把网页手动保存为文件。aiFetchly 会抓取页面、将其转换为干净的 Markdown，并通过与上传文件相同的 RAG 流水线进行索引，因此导入的页面可立即供 [AI Email Writer](./ai-email-writer)、[AI Chat](./ai-chat-v2) 和[知识库搜索](./knowledge-library)使用。

:::info 需要订阅

网站导入会执行分块（chunking）和向量化（embedding），因此需要启用 AI 的有效 aiFetchly 订阅。如果未启用 AI，导入会在抓取任何页面之前被阻止。

:::

## 两种导入方式

你可以通过两种方式导入网页——两者都会生成完全相同的知识库文档：

| 方式 | 位置 | 适用场景 |
|------|------|----------|
| **Import Website 对话框** | 知识库页面 → **Import Website** 按钮 | 可控的手动导入，包含全部选项 |
| **AI Chat 工具** | 在 [AI Chat](./ai-chat-v2) 中让助手导入 | 快速、对话式导入（“导入我们的定价页”） |

本页其余部分聚焦于手动对话框。AI Chat 的方式见下文[从 AI Chat 导入](#从-ai-chat-导入)。

## 导入模式

在对话框中选择以下三种模式之一：

| 模式 | 输入 | 适用场景 |
|------|------|----------|
| **Single page（单页）** | 一个 URL（+可选标题） | 你只想要某个特定页面 |
| **URL list（URL 列表）** | 最多 50 个 URL，每行一个 | 你已经知道想要哪些确切页面 |
| **Site crawl（站点抓取）** | 一个起始 URL + 页面数/深度上限 | 你想通过抓取同源链接来拉取文档站、FAQ 或某个板块 |

:::tip 每页一个文档

每个导入的网页都会成为**独立的**知识库文档，而不是每个网站合并成一个巨大的文档。这样能让引用更精确、便于单独删除或更新页面，并提供可靠的去重检测。

:::

## 使用 Import Website 对话框

### 第 1 步：打开对话框

1. 从左侧导航打开 **Knowledge（知识）** 页面。
2. 点击页面顶部的 **Import Website** 按钮。

### 第 2 步：选择导入模式

在对话框顶部选择 **Single page**、**URL list** 或 **Site crawl**。表单会根据所选模式自动调整。

### 第 3 步：提供 URL

- **Single page** 和 **Site crawl** —— 输入单个 **URL**（在抓取模式下该字段名为 **Start URL**）。请使用公开的 `http://` 或 `https://` 地址，例如 `https://example.com/pricing`。
- **URL list** —— 在 **URLs** 框中每行输入一个 URL（最多 50 个）。空行会被忽略。

### 第 4 步：设置模式专属选项

- **Single page** —— 可选择设置 **Title（标题）** 来覆盖页面原有标题。
- **URL list** 和 **Site crawl** —— 设置 **Max pages（最大页数）**（要导入多少页）。
- **Site crawl** —— 额外设置 **Max depth（最大深度）**（从起始 URL 起跟随多少层链接）。

### 第 5 步：添加通用元数据（可选）

| 字段 | 说明 |
|------|------|
| **Tags（标签）** | 以逗号分隔的标签，会应用到每个导入的页面（例如 `pricing, product`）。 |
| **Author（作者）** | 记录在文档上的作者。默认为 `Website`。 |
| **Description（描述）** | 随文档一起保存的可选描述。 |
| **Duplicate policy（重复策略）** | `Skip duplicates`（默认）或 `Allow duplicates`。参见[重复处理](#重复处理)。 |

### 第 6 步：导入并查看

点击 **Import**。进度面板会显示当前页面、发现了多少链接（抓取模式），以及实时更新的已导入 / 已跳过计数。

导入完成后，对话框会列出：

- **Imported（已导入）** —— 每个页面及其标题、来源 URL 和创建的分块数量。
- **Skipped（已跳过）** —— 每个未导入的 URL 及其原因（重复、内容为空、抓取失败、被屏蔽的 URL 等）。
- **Discovered（已发现）** —— 抓取器找到的同源链接数量（抓取模式）。

使用 **Import another** 开始一次新的导入，或点击 **Close** 返回知识库。导入的页面会像上传的文件一样出现在文档列表中，并立即可被搜索。

## 上限

| 上限 | 取值 |
|------|------|
| **URL list** 的最大 URL 数 | 50 |
| **Max pages** 范围（URL list 与 Site crawl） | 1–100（默认 20） |
| **Max depth** 范围（Site crawl） | 0–4（默认 2） |
| 允许的 URL 协议 | 仅 `http://`、`https://` |
| 抓取范围 | 仅限同源（不支持跨源抓取） |

这些上限用于控制向量化成本并保持抓取在可控范围内。抓取器还遵循保守的默认设置：低并发，且每次请求之间有短暂延迟。

## 导入内容的存储方式

每个网页都会被转换为 Markdown，并通过标准 RAG 流水线摄入：

1. **抓取** —— 通过 aiFetchly 基于浏览器的抓取器加载页面（与网站分析使用的引擎相同）。
2. **提取与转换** —— 去除导航、脚本、样式等冗余内容，并将正文转换为 Markdown。
3. **暂存** —— 将 Markdown 保存为应用自有的文档。
4. **分块与向量化** —— 文档会像上传的文件一样被分块并生成向量。
5. **索引** —— 页面变为可搜索，并可作为 RAG 上下文使用。

生成的文档名遵循 `{hostname}-{path}-{hash}.md` 的格式（例如 `example.com-pricing-a1b2c3d4.md`），并且来源 URL 会随文档一起记录。

:::note 提取质量

aiFetchly 会选择最可能的正文区域（article、main、文档容器，最后回退到 body）。质量因站点而异，可读文本很少的页面（登录页、错误页、重度依赖 JavaScript 的应用）可能因内容为空而被跳过。提取质量会随时间不断改进。

:::

## 重复处理

默认情况下，aiFetchly 会**跳过**知识库中已存在的页面，以保持库的整洁。

- **Skip duplicates（跳过重复，默认）** —— 重复页面会被跳过，并以原因 `duplicate` 列在 **Skipped** 下。单页导入若为重复则会以重复错误失败。
- **Allow duplicates（允许重复）** —— 即使已存在副本，也会导入每个页面。当你有意要某个页面的第二份快照时使用。

:::info 替换页面

目前还没有自动的“替换”模式。要刷新某个页面，请删除旧文档后再次导入该 URL。

:::

## 安全与防护

网站导入在默认设计上就是安全的。为防止滥用和 SSRF（服务器端请求伪造），aiFetchly 会拒绝：

- 非 `http(s)` 的 URL，包括 `file://`、`mailto:`、`tel:`、`javascript:` 和 `data:`。
- `localhost`、环回地址，以及私有、链路本地和内部网络地址。
- 云元数据端点（例如 `169.254.169.254`）。
- 包含凭据的 URL。
- 解析到上述任意目标的重定向和发现的链接。

抓取绝不会离开起始 URL 的源。导入的页面内容被严格当作**知识**对待：仅用于检索而存储，绝不会作为指令执行。

:::warning 不支持私有或需要登录的站点

不支持需要认证、登录墙后或位于内部网络的页面。请仅导入公开页面。

:::

## 从 AI Chat 导入

你也可以在 [AI Chat](./ai-chat-v2) 中让助手导入网页。助手会使用 `knowledge_library_import_website` 工具，并在抓取任何内容之前请求确认。

示例：

```text
把 https://example.com/pricing 导入我的知识库，并打上 pricing 标签。
```

```text
把 https://example.com/docs 的文档页面导入知识库。
```

```text
从 https://example.com/docs 抓取最多 25 个页面，并作为网站文档导入。
```

助手会确认模式、URL、上限、标签和重复策略，然后总结导入了多少页、跳过了多少页。

## 故障排查

| 症状 | 可能原因 | 处理方法 |
|------|----------|----------|
| 在加载任何页面前出现 **“Import failed”** | 未启用 AI / 订阅 | 在订阅中启用 AI 后重试。 |
| 页面以 `URL_BLOCKED` 列在 **Skipped** 下 | URL 为私有 / localhost / 非 http(s) | 使用公开的 `http(s)` URL。 |
| 页面为 `EMPTY_CONTENT` | 页面可读文本太少（登录/错误页、仅 JS） | 换一个 URL，或在浏览器中检查该页面。 |
| 页面为 `SCRAPE_FAILED` | 站点屏蔽了抓取器或超时 | 稍后重试，或减少页面数量。 |
| 页面为 `duplicate` | 页面已存在于库中 | 使用 **Allow duplicates**，或先删除旧文档。 |
| 抓取导入的页面少于预期 | 达到 **Max pages** / **Max depth**，或同源链接很少 | 调高上限，或确认站点链接到了你想要的页面。 |
| 导入的页面未被用于 AI 内容 | 未启用 RAG 上下文，或内容不相关 | 在 AI Chat / Email Writer 中启用 RAG 上下文，并确认文档状态为 **Completed**。 |
